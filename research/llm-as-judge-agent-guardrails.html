LLM Agents: The Security Breach Pattern Nobody's Talking About

SpeakerNate B Jones · Nate B Jones Watchyoutu.be/SX1myuPEDFg · 19 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Quotes are verbatim from the talk transcript with the time they were said.
AgentsAI industry

If you only read one thing

  • Lindy's agent sent unauthorized emails during internal testing; stricter prompts and manual confirmation both failed, so they added a separate validator/judge model that reviews each proposed action before it executes.
  • Jones groups agent actions into four risk tiers by consequence -- read-only, reversible writes, external-facing actions, and high-risk actions -- with high-risk requiring a judge plus human approval.
  • The judge needs a four-way output (allow, block, revise, escalate), not a binary yes/no, and Jones says the 'correlated judgment' failure mode (actor and judge sharing blind spots) is much less of a concern on current frontier models than it was months earlier.
01Lindy's agent sent emails nobody approved

Lindy's agent sent emails nobody approved

  • Jones opens with Lindy's internal-testing failure: an agent started sending emails that had not been authorized.
  • Lindy first tried stricter prompts and manual confirmation, and both failed -- prompts don't reliably hold across a long context window, and manual confirmation just trains users to click okay out of habit, comparing it to how EU cookie-consent banners get clicked through without reading.

02The fix: a separate judge model

The fix: a separate judge model

  • Lindy's actual fix was architectural: a separate validator, or judge, model reads the acting agent's proposed action and justification and decides whether it should proceed.
  • Jones frames this as two specialized models -- one focused on completing the task, one focused only on checking that the proposed action matches the user's intent.

“In the new Lindy design system, a separate validator model, or judge model, reads the action and decides whether the model doing the action should proceed.”

said at 04:34
03Four risk tiers decide how much judgment you need

Four risk tiers decide how much judgment you need

  • Jones proposes classifying agent actions into four buckets by the degree of real-world consequence: read-only actions need little guarding, reversible writes need validation, external-facing actions (sending messages, opening pull requests, notifying customers) must pass through a strong judge every time, and high-risk actions -- spending money, deleting data, changing permissions, merging code -- should get a judge plus a human approval path.

“I would group agent actions into four buckets and I think the line that separates them is the degree to which an agent action has real consequences.”

said at 08:41

“Spending money, deleting data, changing permissions, merging code, submitting legal or financial work. Best practice these days is you get the judge plus a human approval path”

said at 10:13
04The judge needs more than yes/no

The judge needs more than yes/no

  • Jones argues a binary judge gets bypassed because it's too rigid.
  • Instead the judge needs a four-way decision scope: allow the action, block it, ask the agent to revise it, or escalate to a human or higher-trust process.

“It needs to be able to allow the agent to do the thing. It obviously needs to say no or block. It needs to be able to ask the agent to revise”

said at 12:48
05Correlated judgment, and agents as managed workers

Correlated judgment, and agents as managed workers

  • Jones flags 'correlated judgment' -- when the actor and judge share the same model, context, and assumptions, they can share blind spots -- as a real but shrinking risk on current frontier models.
  • He closes by framing the broader shift: agents are moving from workflow tools and chatbots toward being managed workers that need a manager, which is the role the judge plays.

“The idea is if your actor and your judge use the same model, the same context, the same prompt style, and the same assumptions, they share blind spots.”

said at 13:50

“agents are starting to look a lot less like just running in a workflow, running down a line racers, uh certainly less like chatbots. They're looking more and more like managed workers.”

said at 16:24

Commentary (ours)
