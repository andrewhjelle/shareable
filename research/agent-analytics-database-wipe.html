02Why chat logs and traces aren't enough

Why chat logs and traces aren't enough

  • The unit of product behavior is shifting from clicks and sessions to delegated work, which he says makes agent analytics 'the way we shape our work' rather than a debugging sidebar.
  • Chat logs capture what the user and agent said but not which tools were available, which calls failed, or where permissions blocked the work.
  • Engineering trace tools capture model calls, tool calls, and cost, but trace data isn't the same as product analytics: a trace can say a run cost 30 cents, but only product analytics can say whether that 30 cents was worth it.

04Completion is not acceptance

Completion is not acceptance

  • He proposes tracking completion rate (did the task reach a finish state) separately from acceptance rate (did the user trust the result).
  • High completion with low acceptance means the agent is finishing work users don't trust -- the exact blind spot that let a database-deleting run look like normal activity.

05What to instrument first

What to instrument first

  • His starting recommendation: ship three events -- when an agent run starts, when it completes, and when a user corrects or interrupts it mid-run -- all tied to a single agent run ID, so completion rate and correction rate can be computed per workflow.
  • He ties this back to the opening incident: the goal is catching defective workflows before an agent ever reaches a delete action.
