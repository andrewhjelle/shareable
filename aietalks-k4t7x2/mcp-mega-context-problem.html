MCP = Mega Context Problem

SpeakerMatt Carey · Cloudflare Watchyoutu.be/YBYUvGOuotE · 22 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Quotes are verbatim from the talk transcript with the time they were said.
patternMCP & protocolsContext engineeringSecurity

It explains one technique, code mode with sandboxed execution, in depth rather than Cloudflare full operating model end to end.

If you only read one thing

  • Cloudflare tried exposing its full API as MCP tools and blew the context window: the raw OpenAPI spec is 2.3 million tokens, about 1.1 million tokens as naive tool definitions, so it split into 16 product-based MCP servers that still had coverage gaps (e.g. 6 tools covering only 30 of a product's endpoints against ~2,600 total API endpoints).
  • Cloudflare's alternative, 'code mode,' lets the model write TypeScript against a generated typed SDK instead of loading tool definitions, but MCP clients didn't adopt it at first because running LLM-generated code without review felt too risky.
  • The fix is running that generated code in an isolated Workers sandbox with programmable guardrails (e.g. toggling internet access, blocking process.env), which Carey frames as a step toward 'one tool called code' replacing individual tool calls.

01Blowing the context window with a full API

Blowing the context window with a full API

  • About a year before the talk, Cloudflare tried giving agents naive tool access to its full API.
  • The OpenAPI spec alone is 2.3 million tokens, and converting it into tool definitions still comes to roughly 1.1 million tokens -- too large for even the biggest foundation models to use directly.

02Splitting into product MCP servers still has gaps

Splitting into product MCP servers still has gaps

  • Cloudflare's workaround was splitting its API into around 16 separate product-based MCP servers, each with far less context but incomplete coverage -- one product suite's server had six tools against roughly 30 total API endpoints, while Cloudflare's full API spans about 2,600 endpoints.

03Tool search as a partial fix

Tool search as a partial fix

  • One alternative to splitting servers is tool search, where an agent's query triggers keyword matching that loads roughly eight relevant tool definitions into context on demand, rather than loading everything up front.

“it would take the user the user question, it would do some sort of keyword matching, and then it would add K equals say eight tools to context”

04Code mode: let the model write code instead

Code mode: let the model write code instead

  • Cloudflare's own approach, published as a blog post, generates a typed SDK from the OpenAPI spec and lets the model write code against those types rather than calling discrete tools.
  • Despite this being available for months, MCP clients didn't implement it, largely because running LLM-generated code for users without review felt dangerous.

“how can we do something where we just let the agent write code? And we let the agent write code against our API”

said at 07:46

“it's a better way of interacting with uh with APIs. Just let the model write code against the API, but they didn't implement it. And why not?”

said at 09:51
05Sandboxing untrusted generated code

Sandboxing untrusted generated code

  • Cloudflare's answer to the risk is running generated code inside an isolated dynamic Worker with programmable guardrails -- for example, toggling whether the code can reach the internet, or blocking access to process.env and secrets.
  • Carey frames this as a preview of a broader shift where a single 'code' tool call, with far more degrees of freedom than an individual tool call, replaces enumerated tool calling as models get better at writing code.

“And this ran on the back end. It didn't run in my browser. It ran in a dynamic worker that's fully isolated”

said at 11:23

“it's like this worker is not permitted to access the internet via global functions. Or maybe we want it to access the internet. And now we can give it access”

said at 12:24

“Instead of doing tool calls, you can have one tool called code where the model generates the code of your choice and then you run it”
