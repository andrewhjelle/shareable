Why Eval++ Is the Next Great Compute Primitive

SpeakerSunil Pai & Matt Carey · Cloudflare Watchyoutu.be/SKDJo2CopRs · 24 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Slides below are frames from that recording, reproduced for reference and study; rights remain with the speaker and the conference. Quotes are verbatim from the talk transcript with the time they were said.
patternInfra & servingMCP & protocolsAgentic engineering

Explains the infrastructure bet Cloudflare is making for agent backends: durable objects for stateful, resumable compute, and 'dynamic workers' as a sandboxed code-execution primitive instead of JSON DSLs

If you only read one thing

  • Durable objects give Cloudflare an addressable, persistent, low-latency (~15ms in London) compute primitive that the team says turned out to be ideal for building AI agents.
  • Dynamic workers let a string of LLM- or user-generated code run instantly in a capability-locked, isolated sandbox with no default access to fetch or APIs, replacing JSON-DSL patterns like generative UI.
  • Code mode compresses Cloudflare's 2,600 API endpoints into about 1,000 tokens for an MCP server, and durable objects give resumable, multi-tab/multi-client streaming without extra database or sticky-session engineering.

This traces how the talk's two primitives, durable objects for state and dynamic workers for sandboxed code, plug into resumable streaming, code mode, and generative UI (ours). The infra-cost claim is drawn separately since the speakers didn't tie it directly to these mechanisms (ours).

01Durable objects as the base compute primitive
Slide at 02:50 · click any slide to enlarge · 1 more from this section below

Durable objects as the base compute primitive

  • The talk frames durable objects as 'stateful serverless': a class spins up once per ID and every future request or websocket connection lands in the same place, avoiding the need for an external database to hold state.
  • Cloudflare's network gives roughly 15ms latency in London, which the speakers say is fast enough for real-time collaborative tools like TLDraw and, they argue, makes durable objects the right unit for building AI agents that need to be addressable, long-running, and able to hibernate.

02Dynamic workers: a sandbox for LLM-generated code
Slide at 07:10 · click any slide to enlarge · 1 more from this section below

Dynamic workers: a sandbox for LLM-generated code

  • Dynamic workers let a worker take a string of code, generated by a user, customer, or LLM, and run it instantly in its own isolated worker rather than deploying it separately.
  • The sandbox model starts from zero access: the code can only run JavaScript, with no fetch, APIs, or environment variables unless explicitly granted, which the speakers contrast with sandboxes that start from a VM/container and add security around it.

“I have this string of code that a customer sent me or a user sent me or an LLM generated. And I'm going to run that piece of code in its own isolated worker.”

said at 07:09

“The only thing you can run is JavaScript in it, but it has no access to fetch, no APIs, nothing”

04Resumable streaming and multiplayer AI
Slide at 09:40 · click any slide to enlarge

Resumable streaming and multiplayer AI

  • Because durable objects maintain a persistent connection, a client can refresh mid-stream and just reconnect; the object continues emitting bytes from where the stream left off, giving automatic multi-tab and multi-browser sync without a database, replication, or sticky sessions.
  • One speaker frames this as evidence AI interfaces should be multiplayer, contrasting it with the inability to share a live ChatGPT conversation link.

“you just reconnect to it and if there's a stream going on, it just says well, here's the beginning of the stream and I'm just going to continue giving you bytes”

said at 13:55

“I'm a believer that AI should be a multiplayer game”

said at 13:55
05Rethinking generative UI, and why Cloudflare is cheap
Slide at 18:50 · click any slide to enlarge · 3 more from this section below

Rethinking generative UI, and why Cloudflare is cheap

  • The speakers argue that generating JSON payloads to render UI (comparing it to 'Jason Bender') is unnecessary when a sandbox can safely run generated HTML or React directly, as in Claude Artifacts, and that JSON-first patterns exist mainly because platforms lack a primitive for rendering untrusted code.
  • Separately, they attribute Cloudflare's low pricing to a decade-old infrastructure decision to install hardware near ISPs and buy bandwidth in bulk rather than build large data centers.

“Why are you generating JSON? Why don't you just generate HTML or even generate React and then just render that?”

said at 12:24

“We don't build massive data centers. Instead, we install hardware near ISPs. We buy bandwidth in bulk from uh level zero like top level ISPs”

said at 22:51

Commentary (ours)

The through-line across both dynamic workers and code mode is a bet that LLM-generated code, tightly sandboxed at the capability layer, is a cheaper and more general interface than structured JSON/DSL output -- worth watching whether other clouds converge on a similar capability-gated eval() primitive rather than each building bespoke tool schemas (ours).
