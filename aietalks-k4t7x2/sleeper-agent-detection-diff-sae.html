Your LLM Deception Monitor Is Broken. The Fix Is in the Training Data

patternSecurityPost-trainingEvals & benchmarks

Presents a peer-reviewed (IJCNN), open-source method for detecting sleeper-agent backdoors that behavioral evals and standard interpretability (cross-model/joint feature) approaches miss entirely

If you only read one thing

  • Behavioral monitors and evals miss sleeper-agent backdoors because the model is correct almost everywhere and only misbehaves on an untested trigger; standard cross-model (joint) interpretability features score near random (about 0.01) at catching it.
  • Training a sparse autoencoder on the difference between base and fine-tuned model activations (diffSAE, or delta A) instead of on concatenated joint activations gives a 40x stronger signal (0.4 vs ~0.01) with perfect precision and zero false positives in the SQL-injection backdoor experiment.
  • The method is cheap (one middle layer, one forward pass per checkpoint), layer- and fine-tuning-regime-independent, but a single feature only catches about 25% of triggers (recall), so ensembling multiple features is recommended, and it requires access to the base checkpoint to diff against.

This reads the diffSAE pipeline as subtract-then-decompose: the base/fine-tuned activation difference isolates the backdoor signal that joint/concatenated features drown out, though only one backdoor type on a 360M model has been tested (ours).

The threat: sleeper agents that pass every eval

  • A model can pass every eval and behavioral monitor yet still carry a backdoor that flips it to malicious behavior on an untested trigger, referencing the sleeper agents work from Hubinger et al. at Anthropic.
  • Four ways a backdoor can enter a shipped model are poisoned training/RLHF data, fine-tuning vendors returning unauditable weights, downloaded checkpoints of unknown provenance, and insiders with pipeline access.

“a model can pass every eval you have in every behavioral monitor you run, it still be carrying a backdoor that flips it into malicious on a trigger you never tested”

02Why current defenses miss it
Slide at 04:10 · click any slide to enlarge

Why current defenses miss it

  • Behavioral testing fails because you'd need to know the exact trigger in advance to catch it, and if you knew the trigger you wouldn't need the monitor.
  • Cross-model/joint interpretability features (concatenating base and fine-tuned activations and learning shared features) also fail because the backdoor signal has to compete with all of the model's ordinary semantics and gets drowned out.

“the backdoor has to compete with everything the model represents, all of its semantics, and it gets worried”

said at 03:41
03The fix: train a sparse autoencoder on the activation difference
Slide at 05:00 · click any slide to enlarge

The fix: train a sparse autoencoder on the activation difference

  • Instead of looking at joint/concatenated activations, the method runs each input through both the base and fine-tuned model, subtracts base activations from fine-tuned activations to get a delta, and trains a sparse autoencoder (diffSAE) on that difference so the backdoor emerges as a single feature that fires on the trigger.

“train the sparse autoencoder, a standard interpretability tool that breaks activations into sparse human-readable features. But, train it on the difference, so we call that a diff SAE”

said at 04:44
04Experimental setup and results
Slide at 05:50 · click any slide to enlarge · 8 more from this section below

Experimental setup and results

  • The team fine-tuned a 360-million-parameter SmolLM2 model with a controlled SQL-injection backdoor triggered by the year in context (2024 triggers vulnerable code, 2023 safe), using procedurally generated training data (about 1.6 billion possible combinations, over 95% unique) rather than handwritten examples.
  • Full-rank fine-tuning produced 100% vulnerable code on the trigger year and 0% on the benign year (a 100-point swing), while the diffSAE detector scored 0.4 versus about 0.01 for the joint-feature approach, a 40x gap with non-overlapping confidence intervals and perfect precision (zero false positives).

“That's about 1.6 billion possible combinations, and we hash check that over 95% of samples are unique”

said at 05:47

“full rank fine-tuning gives perfect separation, 100% vulnerable on the trigger year, and 0% on the benign year. A plus 100 point swing”

said at 06:50

“the cross coders are essentially at zero about 0.01, barely better than random. Now, the teal color bars here are delta, which is diffSEE at 0.4. That's a 40x gap”

said at 08:25
05Limitations and how to wire it in
Slide at 12:10 · click any slide to enlarge · 2 more from this section below

Limitations and how to wire it in

  • The method requires the base checkpoint to diff against, so it doesn't apply to an opaque downloaded model with no reference; a single feature catches only about 25% of triggers, so ensembling multiple features is needed for coverage; and it has only been tested on one backdoor type on a 360M-parameter model, with no adaptive-attacker testing yet.
  • Recommended pipeline integration: on a fixed probe set, compute the activation delta at one middle layer, run it through the diffSAE, and gate the build if the backdoor-shaped feature fires, since it's a single cheap forward pass per checkpoint.

“The single feature catches about 25% of triggers, so ensemble for coverage”

said at 12:31

Commentary (ours)

The demonstrated result is on a small (360M) model with one backdoor type and no adaptive attacker; the speaker is upfront about this, but the 40x gap should be read as proof-of-concept strength rather than a validated production number until it's replicated at larger scale (ours).
