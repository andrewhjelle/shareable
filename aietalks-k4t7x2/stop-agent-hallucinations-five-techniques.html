If you only read one thing

  • Filtering an agent's tool list to only the top few relevant tools (semantic tool selection) cut one 29-tool travel agent's per-call token cost from ~3,000 tokens to under 300.
  • For aggregation/count/multi-hop questions, GraphRAG (Cypher queries against a knowledge graph) returns a computed answer instead of the estimate a vector-search RAG model produces from a handful of retrieved chunks.
  • Rules written only in the system prompt are suggestions the model can ignore; enforcing them as code (Strands hooks that fire before a tool executes) makes them unskippable, and a runtime-steering layer lets soft rules redirect the agent instead of hard-blocking it.

This traces three of the talk's five techniques from problem to code fix to result: tool filtering and GraphRAG replace model guesses with computed lookups, and hooks make a stated rule unskippable (ours).

01Tool schemas quietly eat your context window
Slide at 05:50 · click any slide to enlarge · 8 more from this section below

Tool schemas quietly eat your context window

  • Every tool available to an agent has its full schema (name, description, typed parameters) sent to the model on every single call, whether or not the model uses it.
  • In the demo travel agent, 29 tools added roughly 3,000 tokens per call before any user message or response.
  • Building a small vector-searchable tool database and retrieving only the top few relevant tools per query dropped usage to under 300 tokens.

“adds up to somewhere around 3,000 tokens per call, just for the tool description”

“With this filter, the model sees only three most relevant tools. Tokens usage drops from thousands to fewer than 300.”

02GraphRAG turns guesses into computed answers
Slide at 18:00 · click any slide to enlarge · 8 more from this section below

GraphRAG turns guesses into computed answers

  • Standard vector-search RAG always returns something even when nothing in the retrieved chunks is truly relevant, and for aggregation-style questions (average rating across all hotels, count of hotels with pools) the model can only see a handful of chunks and has to estimate an answer from them, presenting the guess as fact.
  • GraphRAG instead has the model write a Cypher query against a knowledge graph built from the same documents, so the query runs across the full dataset and returns a computed, verifiable result.

“the graph run that query across all the data. And the model gets back a compute verified results, not a sample.”

03A second agent catches fabricated success
Slide at 35:10 · click any slide to enlarge · 1 more from this section below

A second agent catches fabricated success

  • A single agent that hits a tool error can rationalize it into a confident-sounding success response, and the user never sees the failure.
  • Splitting the work into an executor, validator, and critic agent (Strands' Swarm class handles the handoff) means the validator surfaces the tool error and the critic rejects the response instead of it reaching the user.

“the executor gets the error, the validator catches, the critic rejects this, and the user never see a fabricator response”

said at 34:43
04Rules belong in code, not prompts
Slide at 36:00 · click any slide to enlarge · 8 more from this section below

Rules belong in code, not prompts

  • A rule written in the system prompt or tool description is processed by the model as text it can choose to follow, not logic it must execute, so a stated limit like max 10 guests per booking can still be violated.
  • Strands hooks intercept a tool call before it executes so the rule check runs in Python and cannot be skipped.
  • Because hooks block unconditionally, a separate runtime-steering layer (Agent Control) is used for soft rules, letting the agent redirect and complete the task instead of stopping and making the user retry.

“prompts probably are suggestions, not constraints. The model process them as a text. Not as a logic it has to execute.”

said at 36:18

“you have a hook. You write the rule, check the parameters and if they fails you cancel the call”

said at 37:23

“Hooks blocks unconditionally. The agent is stop and the user has to retry.”

05Production path: AWS Bedrock AgentCore
Slide at 51:00 · click any slide to enlarge · 3 more from this section below

Production path: AWS Bedrock AgentCore

  • All five techniques were run locally in notebooks for the demo.
  • For production, AWS Bedrock AgentCore provides a runtime that can host any agent framework (not only Strands), a gateway that auto-builds the tool-selection index and routes tool calls to Lambda, and steering rules stored in DynamoDB that take effect on the next call without redeploying the agent.

“you inside the run time, you can put every framework that you want, not only run a strands”

said at 51:39

Commentary (ours)

The throughline across all five techniques is the same move: take something the model is currently trusted to compute or self-police (which tool to use, an aggregate number, its own correctness, a numeric limit) and replace it with a deterministic system that computes or enforces it instead. That's a reusable design lens beyond these five specific patterns (ours).
