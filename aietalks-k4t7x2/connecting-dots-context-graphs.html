Connecting the Dots with Context Graphs

SpeakerStephen Chin · Neo4j Watchyoutu.be/eW_vxrjvERk
MemoryContext engineering

01The pitch: context graphs as an emerging category

Chin frames the problem as enterprise knowledge being trapped in disconnected systems (Slack, CRMs, tickets), leaving agents unable to make well-grounded decisions. He positions context graphs as a way to connect data sources, decision traces, and reasoning tool calls into one consolidated view, and notes Foundation Capital wrote about the opportunity as a multi-trillion-dollar shift.

“all of our different enterprise data sources, previous decision traces, the reasoning tool calls of the tools to give us a more consolidated view of our enterprise stack”

“Foundation Capital actually started this thread with their $3 trillion startup opportunity post about how context graphs are going to move forward the industry”

02Healthcare demo: graph grounding beats a baseline LLM and plain RAG

Chin runs a live comparison on a care-plan question for a patient with emphysema. A baseline LLM gives generic medical advice, and a vector-database RAG system adds some patient context but still misses relevant history. Adding graph grounding pulls in the patient's smoking history and prior operation, producing specific recommendations like medication management and smoking-cessation counseling.

“What was the care plan associated with Andre Jenkins' emphysema? And when you ask the LLM, it has broad knowledge.”

▶ watch at 04:44

“You can see here that it it's specifically recommending medication management, smoking cessation counseling, pulmonary rehabilitation exercise.”

03Memory architecture and the open-source package

Chin describes three memory types needed for a complete agent history: short-term memory of the current pipeline, long-term memory organized by a domain model, and reasoning memory capturing why decisions were made. Neo4j has released an open-source agent memory package built on Neo4j that combines these three into a context graph structure.

“we need to now store the the memories, the short-term memory, the long-term memory, and the reasoning memory so that we have our complete history of what's happened that we can build on top of this”

▶ watch at 06:17

“we're building asset compliant um solutions with things like the Neo4j agent memory package. So this is an open source package which we built on top of Neo4j.”

04Financial services demo: explainable, auditable loan decisions

In a second demo, an application pulls from a support ticket system, a CRM, and an internal business system through 10 different MCP tools to populate a context graph. Asked whether a customer, Jessica Norris, should be approved for a loan, the system recommends against it and surfaces the specific risk factors and a previous rejection that informed the recommendation.

“it's pulling in from a variety of different data sources. So, we've hooked it up to a support ticket system, a CRM, and an internal business data system with 10 different MCP tools that it has access to.”

“unfortunately for Jessica, the the AI model recommends not giving her the loan, but it gives us the reasons, the risk factors, it gives us previous decisions which should influence this.”
