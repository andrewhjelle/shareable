A working-session walkthrough of a personal multi-agent development setup (Open Claw orchestrator plus tmux-managed Claude Code workers) built around keeping task-relevant context separate from implementation context, and using a separat...

If you only read one thing

  • Brief Slack-style messages work because the orchestrator (Open Claw) retains context and memory about ongoing tasks, so the user doesn't have to re-explain each time.
  • A separate manager-level agent evaluating a coding agent's own PR catches self-report bias: a worker agent tends to claim its own PR is ready to merge, while the manager agent (different context) can say another PR should supersede it instead.
  • Browser/visual testing reliability with coding agents has improved sharply over the past 6-12 months, reducing how much manual testing is still needed; cost is managed by switching from a primary model to a cheaper fallback (MiniMax) once token budget runs low.

This traces the speaker's loop from Open Claw dispatching tasks into worktrees and tmux workers through to a separately-contexted manager agent that catches self-report bias, with staging and a cheaper fallback model as the cost levers (ours).

03A manager agent counteracts the coding agent's self-report bias

A manager agent counteracts the coding agent's self-report bias

  • When a coding agent evaluates its own pull request directly, it tends to report the work as done and ready to merge.
  • Running a separate manager-level agent, which holds different context than the worker, produced a different verdict: recommending an existing PR be closed in favor of another that should supersede it.

“I feel like the work is not biased anymore. So, when I when I code with these directly, um I usually feel like there's a bias, where it wants to say things are really working or whatever, right?”

said at 10:01

Browser-testing reliability has improved sharply in the last year

Cost tradeoffs: staging doubles token usage, cheaper models as fallback

  • Running a second staging/sandbox instance and sending the same work to both roughly doubles token usage, traded off against added reliability from integration testing before merging to production.
  • The speaker's primary orchestrator model burns through budget quickly, so he switches to a less capable but cheaper model (MiniMax) once the primary's budget runs low, and reports tmux has meaningfully improved his own workflow efficiency.

“that could double your token usage if you send the same work to both of them. If you have two of them, right?”

Commentary (ours)

The self-report-bias fix (a separately-contexted manager agent judging a worker's own PR) is a cheap, generalizable pattern worth testing against any workflow where a coding agent both writes and grades its own output (ours).
