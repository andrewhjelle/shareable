Develop at Idea Velocity

SpeakerJeffrey Lee-Chan · Snapchat Watchyoutu.be/9arM9b7JgOo
Agentic engineeringCoding agentsContext engineering

If you only read one thing

  • Brief Slack-style messages work because the orchestrator (Open Claw) retains context and memory about ongoing tasks, so the user doesn't have to re-explain each time.
  • A separate manager-level agent evaluating a coding agent's own PR catches self-report bias: a worker agent tends to claim its own PR is ready to merge, while the manager agent (different context) can say another PR should supersede it instead.
  • Browser/visual testing reliability with coding agents has improved sharply over the past 6-12 months, reducing how much manual testing is still needed; cost is managed by switching from a primary model to a cheaper fallback (MiniMax) once token budget runs low.
01Brief messages work because Open Claw retains context

The speaker's setup lets him send short messages (e.g. 'fix the skeptic agent') because the orchestrator layer retains context and memory of prior tasks, avoiding re-explanation. He runs multiple agents using git worktrees, which he calls key for parallelization.

“when everything works, you know, maybe like 70% of the time, you describe your task. And then what's nice is open claw will have like context and memory about what you're talking about”

“I use multiple agents with work trees, that's very key for parallelization.”

02The goal: an agent autonomous enough to replace the operator

The speaker notes that his own responses to the agent are not especially specialized, which is part of why he's working toward making the system more autonomous, up to the point an agent could take over his role in the loop.

“I actually think an agent could replace me. So, that's kind of what I'm working on right now to like get things even more autonomous.”

▶ watch at 02:38
03A manager agent counteracts the coding agent's self-report bias

When a coding agent evaluates its own pull request directly, it tends to report the work as done and ready to merge. Running a separate manager-level agent, which holds different context than the worker, produced a different verdict: recommending an existing PR be closed in favor of another that should supersede it.

“I feel like the work is not biased anymore. So, when I when I code with these directly, um I usually feel like there's a bias, where it wants to say things are really working or whatever, right?”

▶ watch at 10:01
04Browser-testing reliability has improved sharply in the last year

The speaker describes previously having to manually test browser interactions extensively because agents struggled with things like finding pop-ups or entering passwords, but says that reliability has improved substantially over the past six months to a year, reducing manual testing load.

“before like I had to really manually test a lot because like you know, this worked fine, right? But these things didn't work that well with agents like last year but like a year ago even 6 months ago”

▶ watch at 06:48
05Cost tradeoffs: staging doubles token usage, cheaper models as fallback

Running a second staging/sandbox instance and sending the same work to both roughly doubles token usage, traded off against added reliability from integration testing before merging to production. The speaker's primary orchestrator model burns through budget quickly, so he switches to a less capable but cheaper model (MiniMax) once the primary's budget runs low, and reports tmux has meaningfully improved his own workflow efficiency.

“that could double your token usage if you send the same work to both of them. If you have two of them, right?”

▶ watch at 13:38

“then I just switch to MiniMax, which is not as good, but it kind of gets the job done”

▶ watch at 15:09

“I think my efficiency has improved a lot with tmux”

▶ watch at 10:34

Commentary (ours)

The self-report-bias fix (a separately-contexted manager agent judging a worker's own PR) is a cheap, generalizable pattern worth testing against any workflow where a coding agent both writes and grades its own output (ours).
