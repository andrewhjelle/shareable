Why understanding still matters when agents write the code

  • Litt opens with the observation that agents are landing PRs as large as 50,000 lines, making it hard for humans to keep up, and frames this as reviving an old debate about whether humans still need to understand code.
  • He distinguishes two reasons to understand: verifying correctness, a role he says is shrinking as agents get better at self-checking, versus understanding in order to participate -- because what you learn in one review loop is the foundation for having the next creative idea.
  • He ties the risk of skipping this to 'cognitive debt,' a term he attributes to scholar Margaret Stories and notes Simon Willison has also blogged about, describing how understanding degrades like technical debt if you don't stay in the loop.

02Explainer docs that end in a quiz you have to pass

Explainer docs that end in a quiz you have to pass

  • Litt describes a personal skill called 'explainedif' that generates a code-explainer document for each change: it starts with background on how the system works, not the diff itself, then gives intuition before details, then interactive figures, then a literate walkthrough of the code.
  • He builds these using HTML blocks in Notion pages, a feature he says Notion launched the morning of the talk, which lets agents embed interactive simulations directly in the doc.
  • At the bottom of every explainer is a five-question quiz, and his rule is that he won't send agent-written code to a teammate for review unless he can pass it himself.

03Microworlds: agent-built tools for building intuition, not shipping
Slide at 12:50 · click any slide to enlarge · 5 more from this section below

Microworlds: agent-built tools for building intuition, not shipping

  • Beyond documents, Litt describes having Claude build ephemeral debugging UIs -- 'microworlds' -- purpose-built to visualize what his own code is doing internally, such as a step-through debugger for a Prolog interpreter he was implementing.
  • The point of these tools isn't the software artifact itself but the intuitive feel for the system that building and using them gives the human, similar in spirit to Seymour Papert's vision of kids learning math by programming a turtle robot rather than by studying the robot.

“I had Claude make me a microworld. This is a debugger, ephemeral UI that was built specifically to visualize the internal implementation of my programming language.”

said at 12:56
04Shared understanding as a team primitive
Slide at 17:00 · click any slide to enlarge · 4 more from this section below

Shared understanding as a team primitive

  • Litt extends the argument from individual to team understanding, describing Notion's push toward shared spaces where humans and agents collaborate visibly rather than each person talking to their own agent in isolation.
  • He notes Notion has recently made it possible to bring coding agents like Claude and Cursor directly into Notion, and connects the broader theme back to Alan Kay's decades-old vision of computers as tools that level up human understanding rather than replace it.

“we just launched last week the ability to bring coding agents into Notion. So, Claude and Cursor can now live in Notion.”

Commentary (ours)

The quiz-gate is the most exportable idea here: it's a cheap, mechanical check on whether a human actually engaged with an agent's diff, rather than a values statement about wanting to 'stay in the loop.' Whether it scales past a single engineer's personal discipline to a team norm (enforced how, and by whom) is the open question the talk doesn't really answer (ours).
