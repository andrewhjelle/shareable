02Round 2 — after the 52-talk corpus pass (Aug 20)

  • Skills budget — longest skill description trimmed 471 → 163 chars; detail moved into the skill body.

03Round 3 — harness laws, then a skeptic (Aug 22)

Nine laws written — then audited against runs, not documents

Round 3 mined the 349-talk corpus through four lenses (harness, context, evals, attention), wrote nine standing harness laws into the pipeline doc, and applied them in code to the two script pipelines. Then a separate agent in a fresh context was told to refute it all. It did.

What round 3 wrote (laws) and where they now live

  • Session log per run · grader before ship · verifier ≠ author · done = receipt · halt file + write scope · one owner per synthesis · anomaly not haystack · staleness + model cooling-off · files are the store. Each cites the talk claims behind it (paperclip·c7/c8, harness-did·c2/c7, killed-pipeline·c3/c5, feature-flags·c8, continual·c6 …).
  • In code: the 6am Landscape script and the YouTube-digest script now write a JSONL session log, check a _HALT file before running, and log the artifact’s size + sha256 as the receipt. Verifier rules went into the weekly corpus skill.

The skeptic’s audit (fresh context, told to refute)

  • The one scheduled pipeline had produced nothing for 72 days. The Landscape script was saved as BOM-less UTF-8 with em-dashes; Windows PowerShell 5.1 reads it as cp1252, so it had failed to parse since Jun 12 — task result 1 every morning, no log, no artifact. Round 3’s patch added the log/halt/receipt code and eight more parse errors, and auto-sync pushed it four minutes later. Laws 1, 4 and 5 were “built” in a file PowerShell could not read.
  • Scorecard: of nine laws, zero were enforced on the pipelines Andrew actually reads; one (the grader) enforced for this talk corpus only; three paper-only; four contradicted by the running system.
  • The proposers were not verified: 10 of 28 round-3 proposals targeted machinery that does not exist here (context compaction, semantic search, a 4pm brief, handoff chains, knowledge-graph “nodes”); 8 of 12 adopt-now items were downgraded. Five claim ids in the laws were hand-abbreviated and did not resolve.
  • Three blind spots of the loop: it measures documents, not runs; nobody verifies the proposer; “built” does not survive a round — each round’s build list becomes the next round’s unexamined premise.

What changed the same night because of the audit

  • Encoding fixed (UTF-8 BOM): 15 parse errors → 0. A manual run produced the first receipts the pipeline has ever written (logs/landscape_2026-08-22.log, ResearchBot/runs/2026-08-22.jsonl) — and the receipt logged FAIL: no artifact, which is exactly what a receipt is for. A verbose re-run shows the headless agent executing the prompt (WebSearch calls in logs/debug_2026-08-22.jsonl); the invocation was hardened and the 06:00 scheduled run is the proof that counts.
  • The five non-resolving claim ids were corrected in the pipeline doc and the weekly skill.
  • Law 10 added to the lessons ledger: a harness edit to a script is not “built” until one manual run has produced a receipt. Rubric F1 (“current-state description must be verified against the repo”) now applies to miner output before ranking: a proposal that names a file or behavior that does not exist is discarded, not ranked.

04Avenues — further research or change

Where this goes next (ours)

  • Scale the corpus: run the full 3-month AI Engineer catalog through this pipeline; the claims graph only becomes decision-grade when convergences have n>2 behind them.
  • Claim clustering with an entailment gate: embedding similarity alone conflates “same claim” with “related topic”; add a bidirectional-entailment check so divergences are real contradictions (the GraphRAG/MultiClaimNet recipe).
  • Memory & continual-learning track next: the channel has a whole track on exactly the dreaming/memory questions this page ranks as experiments — brief those talks before building.
  • Open question the talks don’t answer: both assume the harness owner is a platform; neither addresses the solo-operator case where the human IS the observability layer. The watch-ranked items above are where that difference bites.
