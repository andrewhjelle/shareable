When All Context Matters: Extended Cache Augmented Generation

SpeakerLuis Romero-Sevilla · Orbis Watchyoutu.be/XovaGv4f39A
Context engineeringMemoryInfra & serving

If you only read one thing

  • GraphRAG works well when documents rarely change, but recomputing the knowledge graph on every data refresh is computationally expensive.
  • The proposed fix distributes documents in no particular order across parallel cache-augmented-generation (CAG) buckets, and a supervisor model interrogates buckets and asks follow-ups, which is faster than GraphRAG and more accurate than simple RAG.
  • Organizing buckets by domain doesn't work well because a supervisor tends to ignore domains that look irrelevant at first glance, given dense cross-document relationships.
01GraphRAG works, but recomputation is expensive when data changes fast

GraphRAG uses an LLM to read all documents and extract entities and relationships into a knowledge graph, then navigates that graph at query time to synthesize an answer across the whole collection. It's described as an excellent approach when the document collection doesn't change often, but recomputing the graph every time data is replaced is computationally expensive and slow.

02Distributing documents across parallel CAG buckets

The proposed approach loads documents into multiple cache-augmented-generation buckets in parallel rather than one large context or a recomputed graph, and uses a supervisor model to ask questions of the right bucket and follow up on interesting findings. Documents are distributed in no particular order rather than by domain, because a supervisor tends to ignore domains that look irrelevant at first glance given how densely interconnected the documents are.

“what if we use more CAGs in parallel and distribute the documents across different context buckets”

“the supervisor tends to ignore domains that at first glance seem irrelevant. For this reason, all documents are distributed in no particular order”

03Speed and accuracy tradeoff

Because all caches can be loaded in parallel, this bucketed CAG approach is described as significantly faster than GraphRAG's knowledge-graph build process while providing more accurate answers than simple vector-search RAG, though KV-cache cost remains a real expense to manage.

“the knowledge building process is significantly faster than graph rag while providing more accurate answers than a simple rag”
