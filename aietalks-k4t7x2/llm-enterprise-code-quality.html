  • 55% of developers now regularly use AI coding agents per the March 2026 Pragmatic Engineer Survey, but standard benchmarks like SWE-bench only measure functional correctness, not security or maintainability (c1).
  • Sonar's own benchmark on 4,444+ Java assignments found Claude Sonnet 4.6 produced the highest security-issue rate (300 per million lines) among tested models, and GPT-5.4/5.4 Pro High generated up to 1.2 million lines of code for the same assignment set (c4, c5).

Agentic coding adoption is real, but eval numbers miss what matters

  • The speaker cites the March 2026 Pragmatic Engineer Survey finding 55% of developers now regularly use AI coding agents, alongside a shift from IDEs (VS Code, JetBrains, Cursor) toward agentic platforms (Codex, Claude, Devin, Gemini CLI).
  • He argues that vendor-reported pass rates (80%+ on HumanEval, MBPP, SWE-bench) measure functional correctness on test cases but omit security, real-world reliability, architectural discipline, and tech debt.

04Why: mixed-quality training data and model non-determinism
Slide at 05:40 · click any slide to enlarge · 8 more from this section below

Why: mixed-quality training data and model non-determinism

  • The speaker attributes quality issues to mixed-quality open-source training data, built-in security flaws in that data, subtle hidden bugs slipping into training pools, and the LLMs' inherent probabilistic nature -- the same prompt to the same model produces different code from one day to the next, with limited context on a given company's codebase or architecture.

“the prompt that you are that giving to one model today, tomorrow when you give the same prompt to the same model, it is not going to generate the same code.”

said at 05:45
05ACDC: guide, verify, solve
Slide at 10:20 · click any slide to enlarge · 8 more from this section below

ACDC: guide, verify, solve

  • Sonar's response is a three-stage ACDC framework: guide (context augmentation into the LLM plus a private-beta data-cleanup product called Sonar Sweep), verify (SonarQube agentic analysis that runs in 1-5 seconds via MCP before a commit, versus a 1-5 minute CI run, feeding problems back to the agent to fix pre-commit), and solve (a remediation agent, in open beta, that fixes flagged PR issues or bulk tech-debt items and re-runs analysis and compilation on its own fix before proposing it, discarding fixes that introduce regressions).

“in the ACDC framework we have three stages. We have guide stage, we have verify stage and we have solve phase.”

said at 10:25

“the remediation agent is going to create the fix, run it through the analysis again, run it through the compilation part again and see whether that is creating any issues or not.”

said at 13:35

Commentary (ours)

The finding that Claude Sonnet 4.6 tops the tested models' security-issue rate while GPT-5.4 tops raw code volume suggests these are two independent failure modes (verbosity vs. insecure patterns) rather than one 'quality' axis -- worth checking whether Sonar's leaderboard breaks these out per-model over time rather than as a single snapshot (ours).
