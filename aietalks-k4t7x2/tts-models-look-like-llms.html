Why TTS Models Now Look Like LLMs

SpeakerSamuel Humeau · Mistral Watchyoutu.be/3jGAU2sbAyY
Voice & realtimeGenerative mediaOpen source

If you only read one thing

  • TTS's dominant use case has shifted from offline narration to interfacing with chat agents in real time, where most labs now use an autoregressive decoder backbone over audio-codec tokens, similar to how LLMs generate text.
  • Mistral's released open-source TTS model compresses audio to 500 tokens per second (12 frames/sec times 37 tokens per frame) through a 4-billion-parameter backbone, reaching 17ms latency between text input and first audio on a single GPU.
  • Voice cloning needs only a few seconds of reference audio, but Mistral did not open-source the voice-cloning encoder, so it remains a proprietary feature even though the base TTS weights are open.

02The common pattern: autoregressive decoder over codec tokens

Most labs have converged on treating audio generation like language modeling: an autoregressive decoder backbone generates audio codec tokens one piece at a time. Mistral's model cuts audio into 80-millisecond frames (12 per second), encodes each frame into 37 tokens for about 500 tokens per second total, and runs this through a 4-billion-parameter backbone -- though Mistral's release departs from the standard pattern by generating all 37 tokens per frame at once via a diffusion model rather than one token at a time.

03Latency and voice cloning limits

On a single GPU with the network removed, the model reaches 17 milliseconds between text input and the first playable audio. Voice cloning itself needs only a few seconds of reference audio, but Mistral withheld the voice-cloning encoder from the open-source release, serving it only as a proprietary feature for now.

04Streaming text-to-speech: still an open architecture question

For the next step -- real-time TTS that starts speaking as an LLM streams out text tokens rather than waiting for the full text -- the speaker describes two main patterns, interleaving audio and text tokens in a single layer versus a dual-stream architecture that blends separate audio and text streams, and says there isn't yet a clear winner between them.

“the two main ones are people who interleave audio and text, so as soon as there is a new text, they they put the text in the same uh layer.”

Commentary (ours)

The speaker's aside that voice cloning is being withheld specifically to avoid handing out easy impersonation, while framing vocal identity as the next brand-identity frontier after websites, suggests open-weight TTS releases may keep splitting base model (open) from cloning capability (gated) as a deliberate policy rather than a technical limitation (ours).
