03A taxonomy of six agent-specific flag types
Slide at 09:00 · click any slide to enlarge · 4 more from this section below

A taxonomy of six agent-specific flag types

  • The proposed taxonomy maps one flag type to each of six agent behavior surfaces: prompt variant, tool access, model routing, memory policy, autonomy level, and kill switch.
  • Autonomy level is presented as the single largest blast-radius dial, with three settings -- suggest (agent recommends, human acts), auto-approve (agent prepares, human confirms with one click), and autoexecute (agent acts alone) -- while a real kill switch is defined by three properties: it takes effect in seconds without a deployment, in-flight requests respect it at their next decision point, and its wiring exists from the design phase rather than as a 3 a.m. hot patch.

“Suggest where the agent recommend and a human acts. Auto approve where the agent prepares and a human one click confirms.”

said at 08:56

“It does not require any deployment, does not require any start, does not require any code changes.”

04Sub-agents can bypass the safety layer entirely
Slide at 13:20 · click any slide to enlarge

Sub-agents can bypass the safety layer entirely

  • The architecture places a middleware layer between the user and the agent loop that resolves flags, routes tools and models, applies autonomy, and honors the kill switch, sitting on top of an existing flag backend such as LaunchDarkly, Unleash, or a homegrown service.
  • The stated failure mode is a parent agent with flags properly applied spawning a child agent that calls the model and tools directly, bypassing the middleware so a flipped kill switch never reaches it.

“The biggest failure mode I see is a parent agent with flags properly applied that spawns a child agent.”

said at 13:07
05A five-step rollout playbook with numbers to track
Slide at 15:10 · click any slide to enlarge · 5 more from this section below

A five-step rollout playbook with numbers to track

  • The recommended rollout order is: wire the kill switch first, wrap every tool call to resolve a flag before execution, default autonomy to suggest and add auto-approve per surface as trust builds, move prompts into flag-resolved config, and track four numbers from day one -- kill-switch fires per week (target zero, investigate above two), rollback time to mitigation, canary error-rate delta, and flag audit-trail completeness.
  • The closing recommendation, repeated as the single most important takeaway, is to ship the kill switch first.

“First one, kill switch fires per week. The target is zero. If you have more than two a week, then investigate”

said at 14:08

“Ship the kill switch first. If you do nothing else, give your agent one agentwide kill switch and one per tool kill switch.”
