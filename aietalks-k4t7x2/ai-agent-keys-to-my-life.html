I Gave an AI Agent the Keys to My Life (Here's What Happened)

SpeakerRadek Sienkiewicz · @velvetshark-com Watchyoutu.be/sJ2jc7leKBk
MemoryAgentic engineeringContext engineering

If you only read one thing

  • Sienkiewicz incrementally gave a personal AI agent access to his email, notes, files, calendars, and OS-level automations, growing the setup one small step at a time rather than all at once.
  • The agent runs ambient maintenance overnight (indexing, backups) and does daytime attention filtering, e.g. catching a failed Netflix payment and getting it fixed within 5 minutes.
  • He warns that memory needs active upkeep -- rules still get missed even when written into agent.md/soul.md, and bad memory or brittle multi-step automations compound into real problems as the knowledge base grows.
01What the agent can access

Sienkiewicz describes giving the agent access to his emails, notes, files, calendars, tools, and operating system, built up gradually rather than granted all at once, starting from a single WhatsApp chat channel before he migrated to Telegram and then Discord.

“it can access my emails, it can access my notes, files, calendars, tools, my operating system.”

02How the setup grew: one step at a time

He describes a repeating pattern -- notice a need, solve it in the simplest way possible, then add more steps -- which he credits for avoiding the catastrophic breakage other users report. The knowledge base behind it is his Obsidian vault, built over years and now holding roughly 3,000 markdown notes covering work, personal life, tasks, projects, and research.

“I see the need. Uh I solve it in in a very simple way. Uh and and then I add more steps to it.”

“I have like about 3,000 pages or notes, markdown files in my Obsidian.”

03Overnight maintenance and daytime attention filtering

While he sleeps, the agent indexes and backs up his data so a worst case loses only a couple hours of work, and prepares a morning summary. During the day it filters for importance using context pulled from his notes; his example is a failed Netflix payment getting caught and resolved within 5 minutes.

“when I'm sleeping, again, my agent does everything so that it runs well. It indexes everything.”

▶ watch at 08:56

“Netflix payment failure for some reason didn't go through uh was fixed within 5 minutes when it happened”

▶ watch at 12:02
04Five categories of jobs organize the automations

He groups what the agent does into five areas of jobs, mapped to separate Discord channels (general, inbox, consulting, video research, briefing, and others), so different types of work stay separated rather than mixed into one conversation.

“so these are some like five areas or five types of jobs that my agent is doing.”

▶ watch at 10:30
05Failure modes: forgotten rules, memory bloat, brittle chains

He warns that even with rules written into agent.md or soul.md, the agent still sometimes forgets or skips them, which is why he added a separate critical-rules file. He also warns that memory quality compounds -- if it isn't set up correctly, growing to thousands of notes becomes a real problem -- and that multi-step automations are brittle and will eventually break. His recommendation is to start with one recurring pain point and grow trust incrementally by moving as much as possible into markdown files.

“even if I had something in agent MD uh or in soul MD, uh it it still managed to to forget something or not do something.”
