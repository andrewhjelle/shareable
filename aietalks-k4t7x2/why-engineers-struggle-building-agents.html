Why (Senior) Engineers Struggle to Build AI Agents

If you only read one thing

  • Agent-building replaces spec/code/test/deploy with an iterative instructions-run-observe-adjust loop, since the engineer no longer defines each execution step (c1, c2).
  • Long-running agents can't just restart on failure -- errors need to feed back as input -- and can't be graded with deterministic unit tests, which need to become evals measuring pass rate (c4, c5, c6).
  • APIs and tools need self-documenting, semantic interfaces because agents only see function schemas and docstrings, not years of institutional context a human engineer has (c7).

From writing code to writing instructions

  • Traditional software development follows spec, code, test, deploy; building agents instead means defining instructions, running the agent, observing what it does, and adjusting prompts or tools in a loop.
  • He compares the shift to going from traffic controller (control every road and light) to dispatcher (define the destination, not the exact route).

“We define instructions on what we want our agent to do. We run it, we observe what it does, we maybe adjust our prompts, maybe we adjust our tools”

02Text replaces data structures as the interface

Text replaces data structures as the interface

  • Where traditional systems mapped everything to booleans and flags, LLM-based agents can hold semantic meaning in plain text -- for example, a deep-research agent's plan can be approved while the user simultaneously injects new constraints in the same turn, instead of requiring a separate decline-and-resubmit step.

“I can approve the initial plan, but I can also on the same time provide additional information”

03Errors must feed back in, not trigger a restart
Slide at 05:00 · click any slide to enlarge · 1 more from this section below

Errors must feed back in, not trigger a restart

  • For a long-running agent (5-15 minutes of work), restarting from scratch after a failure wastes compute and loses accumulated context, so failures need to be treated like any other model input and fed back in rather than causing a full re-run.

“if you have like an agent which takes 5 minutes, 15 minutes and something in the flow breaks and you would start all all over, you would need to spend you need to spend a lot of compute again”

said at 05:14
04Unit tests give way to evals
Slide at 06:20 · click any slide to enlarge · 2 more from this section below

Unit tests give way to evals

  • Because agents are non-deterministic, the same input won't reliably produce the same output, so teams need to shift from unit tests asserting a fixed result to evals measuring how often something works, using an LLM-as-judge or human expert.
  • A customer agent that only succeeds one time in ten on the same prompt isn't production-ready.

“we cannot always guarantee that the same input will lead to the same steps and the same result. So we need to move from unit tests to eval”

said at 06:16

“If you have a customer agent and the same prompt only works one out of 10 times, it's nothing really you want to put in production”

said at 06:46
05APIs need to be rewritten for agents, and rebuilt often
Slide at 07:40 · click any slide to enlarge · 5 more from this section below

APIs need to be rewritten for agents, and rebuilt often

  • Agents only see function schemas, docstrings, and tool definitions -- not the years of background an engineer has with an existing API -- so tools need self-documenting, semantic interfaces.
  • He closes with recommendations to design for recovery rather than assuming reliability, and to expect to rebuild agent systems repeatedly as models improve, since the software itself is disposable.

“our agents only see like the function schemas and the doc strings and the tool definition”

said at 07:49

“We need to design for recovery. Models are not perfect. Agents are not perfect, especially if we have longer running agents”

said at 09:52

“software is disposable. We are going to rebuild many, many times the same things with better models, better agents”

said at 09:52
