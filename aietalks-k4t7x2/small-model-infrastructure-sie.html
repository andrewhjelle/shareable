The Small Model Infrastructure Nobody Built (So We Did)

SpeakerFilip Makraduli · Superlinked Watchyoutu.be/qdh_x-uRs9g
Infra & servingLocal modelsContext engineering

If you only read one thing

  • Small models (embedding, reranking, named-entity-recognition) can preprocess and filter data to fight context rot, where response quality degrades as context grows, before it reaches an agent.
  • Provisioning one GPU per small model wastes idle capacity; Sie hot-swaps models onto a single GPU with an LRU eviction policy to raise utilization.
  • No existing open-source project took users from model inference through production (routing, autoscaling, monitoring); Sie targets hundreds of open-source models and re-implements the forward pass per architecture (BERT, Qwen, ColBERT) since each handles attention, padding, and positional embeddings differently.
01Small models fight context rot

The speaker cites a Chroma research paper on context rot, where response quality degrades as context length increases. He argues that using small models to preprocess and filter data before it reaches an agent, or as tool-calling targets, is a way to manage this without giving up code/grep-based approaches.

“there is this effect of context rot. So, quality degrades as context increases.”

▶ watch at 04:37
02GPU utilization: hot-swapping beats one-model-per-GPU

Small models like the Stella embedding model or the GLiNER named-entity-recognition model each occupy only a few gigabytes, so dedicating a full GPU to each one leaves most of it idle. Sie's response is to hot-swap multiple models onto a single GPU using a least-recently-used eviction policy, raising per-GPU utilization and lowering cost.

“if you provision a GPU for each model, you're wasting a lot of, um, idle space.”

▶ watch at 07:17

“we've built the ability for you to swap all of these models in one GPU so that per GPU, you get much higher utilization.”

▶ watch at 07:48
03No open-source path from inference to production

The speaker states that, as of the talk, no open-source solution carried users all the way from model inference to production concerns like routing, autoscaling, and Prometheus/Grafana monitoring; teams had to write that layer themselves. Sie is positioned to fill that gap with built-in routing, autoscaling, and queuing.

“there is no open-source solution that leads you from creating the model inference to actually productionizing this at a scale, um, of this size”

▶ watch at 08:50
04Open source models are catching up, and there are millions of them

The speaker cites Hugging Face hosting millions of models as of a March count, with an estimate of close to 3 million more recently. He points to MTEB and other benchmarks showing open-source models beating managed services on narrow tasks, and cites Gemma's low-parameter models scoring higher ELO than much larger models.

“on hugging face currently, there are millions of models. This is from March. Now, there might be even more like close to 3 million models.”

▶ watch at 09:54

“if you look at MTEB or different benchmarks, you can see that for very narrow tasks, open source models are beating managed services”

▶ watch at 10:26
05Supporting many architectures means re-implementing the forward pass

Because BERT, Qwen, and ColBERT differ in attention implementation, positional embeddings, and query/key/value fusion, the speaker says there is no universal inference engine that handles them all, so Sie re-implements the forward pass per architecture (including variable-length flash attention to avoid padding waste). The team states a goal of supporting hundreds of models this way.

“there is no universal engine that can handle BERT, Qwen, and modern BERT as well because their architectures are different”

“we want to give you the whole end-to-end thing so that you can work with this models quickly”

“And we decided to do exactly this. Okay, let's do it. We'll build and support hundreds of models.”
