Anthropic Workshop: Build Agents That Run for Hours

SpeakerAsh Prabaker & Andrew Wilson · Anthropic Watchyoutu.be/mR-WAvEPRwE
Agentic engineeringCoding agentsContext engineering

If you only read one thing

  • A single agent judging its own output is unreliable (models are sycophantic about their own half-finished features), so the team splits work into a generator and a separately-tuned, harsh evaluator that actually drives the app with Playwright instead of just reading diffs.
  • The generator and evaluator negotiate a concrete test contract (27 criteria in one example) before building starts, and design quality is graded against a written four-part rubric -- design, originality, craft, functionality -- weighted toward design and originality.
  • On the same 'build a retro game maker' prompt, a single-agent solo loop shipped a game where the arrow and space keys did nothing, while the full generator-evaluator harness produced a working game for about $200 and 6 hours of runtime.
01Why agents struggle to run for hours

Beyond finite context windows, the speakers point to context rot (coherence degrading deeper into a session) and to models being bad judges of their own output: a model may look at a half-implemented feature and decide it looks done, or build a UI button with no working backend behind it.

“as you're working through a context window, there's this notion of context rot. So, uh, there's less coherence as you're you're getting deeper into that session”

“it might look at a feature and see that it's sort of half half-baked or a little bit implemented and say, Yeah, okay, uh, that looks done”

02Models have gotten much better at running long, unassisted

On the internal 'meter chart' that tracks how long an agent can run unsupervised while completing 50% of tasks with a minimal scaffold, Opus 4.6 jumped to roughly 12 hours, up from about 4 hours with the prior model generation using the same simple harness.

“this was a jump from about 4 hours up to 12 hours with sort of that very simple harness”

▶ watch at 14:34
03Replacing self-evaluation with an adversarial generator-evaluator loop

Modeled loosely on GANs, the team splits the builder and the checker into separate context windows and roles: the evaluator doesn't just read diffs, it opens the live app in Playwright, clicks around, and tries things before handing a critique back to the generator. The key justification is that tuning a standalone critic to be harsh is tractable, while tuning a builder to be self-critical about its own work is not.

“The evaluator here isn't just reading diffs, but it's actually using playwright, um, to open live pages, click around, try things out”

▶ watch at 18:42

“tuning a standalone critic, um, to be harsh is actually very tractable, but tuning a builder to be somewhat self-critical, um, is is not”

▶ watch at 19:45
04Grading subjective quality with an explicit rubric and contract

To grade fuzzy qualities like design taste, the team writes down a four-criteria rubric -- design, originality, craft, and functionality -- weighted toward design and originality, and calibrates it with reference-site examples. Before building starts, the generator and evaluator negotiate a concrete contract of testable assertions; for one app this reached 27 separate contract criteria, which the speakers say is the level of granularity needed to make evaluator findings actionable rather than vague.

“the way we do this at least is with kind of creating a rubric with four criteria, uh design, originality, craft, and functionality”

▶ watch at 21:18

“it was decided that there were 27 contract criteria. That's the level of granularity which we found, you know, that you really need to make findings kind of actionable”

▶ watch at 32:06
05Case study: retro game maker, solo loop vs. full harness

Run with the same prompt and model, a solo agent loop produced a game that looked finished but where pressing the arrow key or space key did nothing, because the agent had no way to test what playing the game actually meant. The full generator-evaluator harness, run for about $200 and 6 hours, produced a playable game with working controls, physics, and an in-app AI level-design assistant the planner invented from a vague spec line.

“Pressing the arrow key does nothing. Pressing a space key did nothing.”

▶ watch at 28:01

“this was about, yeah, 200 bucks, 6 hours”

Commentary (ours)

The $200/6-hour cost for one working app is a useful anchor for weighing this harness against simpler approaches, but it's a single example rather than a benchmark across task types -- the speakers themselves note the pattern is opinionated toward their stack (React/Postgres/Node) and would need re-tuning for a different one (ours).
