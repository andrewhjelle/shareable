If you only read one thing

  • Enterprise audit trails require a complete, replayable record of every agent action and data access — solved with an immutable, append-only event log rather than typical application logs (c1, c2)
  • PHI is kept in schema-driven object storage separate from the event log, accessed via bearer tokens at point of use — this also mitigates prompt-injection "lethal trifecta" risk (c4, c5)
  • These same primitives make evals a byproduct of the architecture: replay any point in time, compare human vs. agent performance on identical tasks, and run evals on production data without ever exposing PHI (c7)

The enterprise POC trap

  • A proof-of-concept that hits its accuracy targets tends to prompt a wave of production questions it wasn't built to answer: audit trails, data handling, escalation, integrations.
  • Lovejoy and Howard warn that bolting these requirements onto a point solution after the fact, rather than designing for them from the start, produces something brittle and hard to generalize across use cases.

Audit trail: an immutable event log

  • Security frameworks like SOC 2, HITRUST, and HIPAA require an audit trail that captures every action, every data access, and every authorization an agent used — well beyond a typical developer log.
  • Their answer is an append-only, immutable, unified transaction log (the event-sourcing pattern used in finance), which makes auditability trivial rather than a separate system, at the cost of making reads harder since reconstructing a view requires replaying the event history.

03Protected health data: object storage plus zero trust
Slide at 10:20 · click any slide to enlarge · 6 more from this section below

Protected health data: object storage plus zero trust

  • For PHI, they recommend schema-driven object storage kept separate from the event log, so events reference data blobs rather than containing PHI directly — letting developers debug and retrace agent steps without ever seeing the underlying health data.
  • Zero-trust, bearer-token access to that storage also closes off the prompt-injection "lethal trifecta" risk of an agent reaching data it shouldn't.

04Escalation and evals fall out of the same architecture
Slide at 13:40 · click any slide to enlarge · 6 more from this section below

Escalation and evals fall out of the same architecture

  • To handle unpredictable escalation needs, they define "agent" broadly enough that any action an LLM can take could also be taken by a human, so downstream steps don't need to know which one acted.
  • The same three primitives — immutable ledger, object storage, human-agent equivalency — then give privacy-preserving evals almost for free: replay any point in time, compare human versus agent performance on the same task, and run evals on production data, including inside a customer's own environment, without exposing PHI.

Commentary (ours)

Anterior sells agentic AI into health insurers, so these four primitives reflect what convinced their own compliance reviewers rather than a general-purpose framework. The specific standards named (SOC 2, HITRUST, HIPAA) mean the pattern generalizes most directly to other heavily regulated industries — finance, defense, government — rather than lighter-weight product contexts.
