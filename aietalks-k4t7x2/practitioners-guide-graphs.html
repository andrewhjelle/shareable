A Practitioner's Guide to Graphs

SpeakerTim Ainge · Good Collective Watchyoutu.be/3ySF0I5iE_0
Agentic engineeringContext engineering

If you only read one thing

  • Give an extraction agent a schema (not raw subject-predicate-object triples) plus explicit ontology instructions to get a meaningfully structured, queryable graph.
  • Embedding models solve entity resolution (matching 'garlic cloves' and 'minced garlic' to one node) more flexibly than naive retrospective matching, which requires knowing all variants in advance.
  • On a real .NET codebase, graph techniques for identifying relevant context produced a 40% reduction in tool calls for code search.
01Give the extractor a schema and an ontology, not raw triples

Ainge shows that extracting a graph from unstructured text using generic subject-predicate-object triples produces a graph with real problems. Giving the extraction agent a defined schema (e.g. a recipe with ingredients and quantities) via structured outputs produces a meaningfully more useful graph, and adding explicit ontology instructions (standardize ingredient names, standardize units to metric) further improves what gets extracted.

“if we give this to an agent with its structured outputs, what we get back is instantly way more meaningful than the graph we had before, and a lot tidier”

“These extra instructions are just as important to the title model as the schema is”

02Embeddings solve entity resolution better than naive matching

He describes the 'potato, potato problem' of duplicate nodes representing the same entity (garlic cloves vs. minced garlic vs. plain garlic). A naive retrospective matching approach can unify these but requires knowing all variants in advance; using an embedding model instead allows flexible matching, including on terms not known ahead of time.

“by using an embedding model here, we have not only more flexible matching, but we also have the ability to match on terms that we don't need to know in advance”

▶ watch at 06:17
03Personalized PageRank surfaces the most related nodes

Ainge explains personalized PageRank as a random walk from a starting node that teleports back to that node, so nodes visited more often have a stronger relationship to the start. He cites the Pinterest Pixie paper and HippoRAG as reference implementations, and gives a Supreme Court citation-graph example where the technique surfaces an authoritative case (Miranda v. Arizona) that isn't directly cited but is connected through the citation graph.

“Miranda v. Arizona is not cited in the Canvas v. Sheba case. It's purely through the relationships in the citation graph that we are able to find it”

▶ watch at 09:25
04Shortest path retrieves the context that explains a relationship

For a code-debugging example ('the checkout code broke after we changed the basket constructor'), traversing the shortest path between two known nodes in a code graph returns the intermediate symbols or summary as context, which he says would be slow to find via vector search or manual symbol lookups. Ainge reports that on a real .NET codebase, using techniques like this for code-search context produced a 40% reduction in tool calls.

“we wouldn't have found these intermediate nodes by doing vector search or even by doing individual symbol and reference lookups and the process of figuring that out for ourselves would have been slow”

▶ watch at 10:50

“we saw a 40% reduction in tool calls for code search where we used techniques like this to identify the context we needed to give the agent”

▶ watch at 10:59
05Subgraph matching finds structural patterns without known symbols

Rather than starting from a known node, subgraph matching queries entirely on relationship shape, for example searching for a decorator pattern (a class that wraps and implements the same interface as its target class) without knowing the specific class names in advance. Ainge frames this as an enabling capability rather than an optimization, useful for finding anti-patterns, security issues, or legal arguments by shape alone.

“we're searching for code in a certain shape, not knowing anything specific about the code we're looking for or any symbols up front”
