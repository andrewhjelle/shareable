Why this talk is a blueprint, not a take (ours)

Scope: Machinecraft's internal go-to-market agent system (Ira / Brain OS): ingestion of company documents into a graph-plus-vector memory, 36 named specialist agents, and a nightly consolidation cycle, built for a 100-person industrial machine maker.

An in-house agent system that reads a company's own historical documents into a vector store and relationship graph, runs 36 single-job agents (sales, pricing, fact-checking, corrections, and more) that draft outbound and inbound go-to-market work, and consolidates and prunes its own memory every night, with a hard rule that a human always sends the final output.

Prerequisites the talk implies:

  • A substantial private historical document archive (quotes, drawings, schedules, emails) to feed the system, since it is not trained on public data
  • A team willing to define narrow single-job agent roles instead of one general-purpose prompt
  • A vector database and a graph database run together (Qdrant and Neo4j in this case) plus access to multiple model providers
  • An explicit written set of guardrail principles (the 'soul file') specific to the organization, not a generic safety policy

What the talk does not say:

  • No engineering headcount or hours spent building the system are given, so the $30K in-house figure is not compared against internal labor cost the way the $230K agency quote presumably included
  • No detail on how the 213 tools were built or tested, or what fraction of go-to-market work is actually handled versus still done manually
  • No error rate or accuracy figures for agent drafts before human review
  • The talk's slide shows the agency quote as $320K where the speaker says $230K verbally; the spoken figure is used here, but the two sources disagree

If you were to replicate one thing first: Before building any agents, gather and chunk your own historical documents into a fact-extraction pipeline and store the results as both vectors and a relationship graph, since the memory layer is described as the actual differentiator, not the agents themselves.

Engineered memory layers, including a nightly dream cycle

  • Memory is built in explicit layers: working memory for recent context, pinned facts, whole conversations stored as episodes, and relationships that grow from stranger to trusted.
  • A 'salience gate' filters what's worth remembering at all, and each night a sleep cycle replays the day's activity, consolidates useful information, checks for contradictions, and discards stale data, producing a morning summary of what was learned.
