MCP UI: Extending the frontier

SpeakerLiad Yosef and Ido Salomon · MCP Apps Watchyoutu.be/o-zkvb0iFDQ
MCP & protocolsProduct & UXOpen source

If you only read one thing

  • MCP UI (now the MCP apps standard, co-adopted by Anthropic and OpenAI) lets servers return interactive HTML resources instead of text, because plain-text tool responses were a real blocker to companies sending their data to chat agents.
  • UI interactions don't talk to the app's backend directly; every click sends a message back through the host, keeping identity, branding, and context with the model.
  • The spec is adding reusable views (avoid re-rendering heavy apps) and a way for the model itself to click and fill forms inside an app's UI, closing the loop in the other direction.
01Why chat needed a UI layer

The speakers frame MCP apps as a response to a real adoption blocker: returning plain text from a tool call strips a company's data of identity and context, which made some companies reluctant to send data to ChatGPT at all.

“this was one of the main blockers of companies or tools not to send their data to ChatGPT because they didn't want to be reduced to like this thing, this wall of text where you don't have identity”

02From MCP UI to a joint Anthropic/OpenAI standard

MCP UI was released in May of the prior year as a general way to pass UI over MCP and handle UI-to-host communication. It was later brought into the MCP standard itself as MCP apps, the first official MCP extension, in partnership with Anthropic and OpenAI.

“So back in May last year I released MCPUI. The concept was pretty simple.”

▶ watch at 02:06

“And just a few months back MCPUI we partnered with Anthropic and OpenAI to really put this into the MCP standard as the first official extension called MCP apps.”

▶ watch at 02:37
03Two different spectrums: message control, and who generates the UI

Messages from a UI back to the host sit on a control spectrum: a notification cedes the least control (the UI just informs the host something happened), a tool call asks the host to run a tool, and a prompt hands full control to the host. Separately, UI generation itself sits on a spectrum from predefined UI (a company's own black-box component, described as good for 8% of cases) to declarative UI to fully generative UI produced by the model.

“this spectrum represents how much control the UI wants for itself and how much control it gives to the host”

▶ watch at 13:01

“That's predefined. That's a black box. That's good for 8% of the cases.”

▶ watch at 16:07
04What's next: reusable views and letting the model drive the UI

Today every render of an app creates a new instance, which is slow for heavy applications (cited example: Autodesk); the team is working on referencing the same view and pushing data into it instead. They are also working on the reverse interaction direction: exposing tools so the model itself can click buttons or fill forms inside an app's UI, not just receive events from user clicks.

“today, for simplicity, whenever you render an app, we actually render a new one”

▶ watch at 15:05

“But what if we want the model to be able to interact with the view? We want Claude to be able to click on buttons or to fill forms or do anything inside the UI.”

▶ watch at 15:37
05Scale claim and a prediction

The speakers cite a figure attributed to Sam Altman that ChatGPT had 800 million weekly users as of around October, describing it as about 10% of the world's population. They predict that within two years, browsers and websites as currently known may be replaced by a personal assistant that consumes small chunks of UI.

“Sam Altman said, I think it was October, that 800 million people are using ChatGPT on a weekly basis. That's 10% of the world's population.”

“Perhaps in 2 years, we won't have browsers as as we know them. We won't have websites as we know them.”
