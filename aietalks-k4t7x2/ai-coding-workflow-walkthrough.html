Useful for engineers designing a repeatable AI-coding workflow: whether to cap task size near a 'smart zone' instead of relying on a 1M-token context window, whether to replace default plan mode with a structured interview step before ge...

If you only read one thing

  • LLMs have a 'smart zone' that degrades around roughly 100K tokens regardless of the advertised context window size, because attention cost scales like adding teams to a football league -- quadratically (c1, c2).
  • A 'grill me' skill that interviews the human on every branch of a plan replaces default plan mode for reaching shared understanding before any code gets written (c4, c5).
  • Work should be split into vertical, traceable-bullet slices rather than horizontal phases, paired with TDD, so an AFK agent gets fast feedback while planning stays human-in-the-loop (c6, c7, c8, c10).

LLMs have a smart zone and a dumb zone

  • The talk frames every token added to context as adding a team to a football league: attention relationships scale quadratically, so quality degrades the longer a session runs.
  • Pocock places the practical 'dumb zone' marker at around 100K tokens regardless of whether the window is 1M or 200K, and recommends keeping the system prompt as small as possible since anything always-in-context (he cites people loading 250K tokens of it) pushes a session toward the dumb zone before work even starts.

02Grilling replaces plan mode for alignment

Grilling replaces plan mode for alignment

  • Instead of relying on default plan mode, which is described as eager to produce an asset before alignment is reached, a short 'grill me' skill instructs the agent to interview the user relentlessly until a shared understanding exists.
  • This is framed as a direct response to the 'specs to code' movement, which the speaker says he tried and found produces code he no longer understood, because it treats the code as disposable rather than as 'your battleground.'

“The LLM really has only a couple of things here. It just has the skill and it has the description of what I want to do”

said at 15:55

“you need to keep a handle on the code. You need to understand what's in it. You need to shape it because the code is your battleground”

03TDD and vertical slices keep agents from coding blind
Slide at 42:10 · click any slide to enlarge · 8 more from this section below

TDD and vertical slices keep agents from coding blind

  • TDD (red-green-refactor) is presented as essential to getting good output from agents.
  • Separately, work is split using the Pragmatic Programmer's 'traceable bullets' (vertical slices) rather than horizontal, layer-by-layer phases, because an AI left to code layer by layer (database, then API, then front end) gets no integrated feedback until the final phase.

“TDD I found is absolutely essential for getting the most out of agents”

said at 66:21

“which comes from the Pragmatic Programmer called traceable bullets or vertical slices. And traceable bullets really transformed the way I think about actually getting AI to pick its own tasks”

said at 41:55

“So, it loves to code layer by layer. So, in other words, in phase one, it will do all of the database stuff, all of the schema, all of the you know, all the stuff related to that unit”

04Deep modules make a code base testable
Slide at 76:50 · click any slide to enlarge

Deep modules make a code base testable

  • Drawing on John Ousterhout, the talk argues that a code base with deep modules (small interface, large hidden functionality) is easier to test than one with many shallow modules, and that better tests produce better feedback loops, which in turn produce better AI-generated code.

“if our code base is easy to test, then our code our feedback loops are going to be better, and the AI is going to do better work in our code base”

said at 76:43
05Split work into human-in-the-loop planning and AFK implementation
Slide at 26:00 · click any slide to enlarge · 8 more from this section below

Split work into human-in-the-loop planning and AFK implementation

  • The talk distinguishes two task types: human-in-the-loop tasks, where a person must be present (planning and alignment), and AFK tasks, where implementation can run unattended once the backlog and vertical slices are set up.
  • This split is presented as the basis for later parallelizing implementation across multiple agents.

“I think of there is being two types of tasks in the AI age. Where you have human in the loop tasks, where a human needs to sit there and do it”

said at 26:20
