uRun is selling real-time video generation as an inference-serving problem, not a model-quality problem: their pitch is a React component plus a Python runtime for wiring real-time models together, priced at roughly 1% of frontier batch-...

If you only read one thing

  • uRun's Helios (a distilled Wan 2.1 14B) generates video at about 1/100th the cost of frontier batch models, at comparable quality to last year's frontier. (c1, c2)
  • At current pricing, $10 buys about 3 hours of continuously generated video and $50 buys roughly a full day (15 hours). (c4)
  • At least 40 models with real-time or long-horizon generation capability shipped this year, which McCallum frames as reason to build serving infrastructure now. (c3)

Use cases beyond games: magic mirrors, accessibility, steerable content

  • McCallum lists a magic-mirror use case (transforming a live webcam feed into different outfits or settings), accessibility (visual, non-text interaction for people who think visually rather than in text), and content creation, where creators can steer generation live instead of the current slot-machine approach of prompting and spending roughly $10/minute hoping for the right shot.

“we've very much had a slot machine type approach where you're setting up a prompt and maybe some key”

“there's more opportunities to have companions or visual mediums that are going to allow more people to experience the things a lot of us have with coding models”

05Building this requires a serving layer, not just a model
Slide at 07:00 · click any slide to enlarge · 4 more from this section below

Building this requires a serving layer, not just a model

  • McCallum argues real-time applications need globally distributed GPUs, WebRTC/ICE/TURN setup, and multi-model streaming pipelines synchronized frame-by-frame with user controls. uRun's answer is a React component for the frontend and a programmable Python runtime behind it, plus a CLI/MCP server so agents can build these pipelines directly.
  • He frames 2026 as needing 'software factories,' not just platforms.

“what if there was just a React component that you could drop into your application”

said at 06:45

“in 2026, don't just need platforms, we need software factories and ways for agents interact with these”

said at 07:18

Commentary (ours)

The cost and hours-per-dollar figures are a useful anchor but are vendor-stated and not independently verified against a specific hardware/model config (ours) — worth re-checking against your own workload before using them to size a build-vs-buy decision.
