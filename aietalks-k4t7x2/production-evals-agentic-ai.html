Production Evals For Agentic AI Systems

SpeakerNishant Gupta · Meta Superintelligence Labs Watchyoutu.be/vljxQZfJ9wY
Evals & benchmarksAgentic engineeringInfra & serving

If you only read one thing

  • Benchmarks measure model capability while production measures system behavior, and the gap between them grows as agentic systems become more autonomous (c1, c2).
  • Reliability, not accuracy, should be the north-star metric; production telemetry, not benchmarks, is the highest-value evaluation signal (c4, c5).
  • Agentic systems drift continuously as models, prompts, tools, and user behavior change, so evaluation must run as a continuous, always-on loop rather than a pre-deployment testing phase (c7, c8).
01Benchmarks measure capability, production measures behavior

The speaker argues offline benchmarks keep improving while production reliability stays unpredictable, because benchmarks don't capture tool failure, API outages, context changes, user variability, or long-running workflows. He reframes the evaluation question from 'did the model produce the correct answer' to 'did the system behave correctly.'

“Offline benchmarks continue improving. Yet production reliability often remains unpredictable. Why is that? Because benchmarks measure model capability. Production measures system behavior”

▶ watch at 01:01

“But we should ask the question did the model produce the correct answer? Agentic systems force us to ask a different question. Did the system behave correctly?”

▶ watch at 01:32
02A failure-mode hierarchy beyond hallucination

He presents a layered hierarchy of agentic failure modes: memory, retrieval, and safety failures at the foundation; reasoning mistakes and poor planning in the middle; multi-agent coordination failures at the top. He argues evaluating only model output misses most of the production risk in this hierarchy.

“Agentic systems introduce an entire hierarchy of failure modes. At the very foundation, the memory failures, retrieval failures, safety failures”

▶ watch at 02:02
03Adopt an SRE mindset: reliability over accuracy

The speaker recommends evaluating agentic systems the way SREs evaluate services -- on reliability, availability, latency, cost, and recovery rather than accuracy -- with reliability as the north-star metric and accuracy as just one input.

“SREs don't measure success using accuracy. They measure reliability, availability, latency, cost, recovery. And agentic systems require the same approach”

▶ watch at 02:33
04An evaluation pyramid, with production telemetry at the top

He describes a three-tier evaluation pyramid: benchmarks at the bottom (scalable, repeatable, but operationally limited), scenario-based evaluations in the middle (simulate realistic workflows), and production telemetry at the top, which he identifies as the highest-value signal since every real user interaction becomes evaluation data.

“at the very top, you see production telemetry. This is where the highest value evaluation signals come from. The surprising insight is that the most evaluation data often comes from real users interacting with real systems”

▶ watch at 03:03
05Continuous evaluation as infrastructure

The speaker warns that agentic systems drift as models, prompts, tools, and user behavior change, with no single change looking catastrophic even as success rate, escalation, and tool failure slowly worsen. He argues evaluation should become part of the control plane -- continuously observing, collecting telemetry, running simulations, and coordinating human review -- rather than a pre-deployment testing phase, concluding that reliability ultimately matters more than raw model accuracy.

“The key takeaway, agent evaluation should be scenario driven, not prompt driven”

▶ watch at 03:34

“The challenge is that no longer single change appear catastrophic. Reliability slowly degrades. Success rate declines, escalation increases, tool failure rises”

▶ watch at 05:00

“reliability ultimately matters more than raw model accuracy. And finally, evaluation is becoming the infrastructure, not testing, not QA infrastructure”

▶ watch at 07:15

Commentary (ours)

The framing of evaluation as a control-plane function rather than a QA gate maps closely to how observability displaced pre-deployment testing in distributed systems; the open question is whether agent tracing tooling matures fast enough to make this practical outside large labs (ours).
