01Why model upgrades force rearchitecture, not just a swap

Bhatawdekar argues each recent model generation has been a step-function change rather than an incremental upgrade — better tool use, longer context, reliable code execution — that existing systems weren't built to exploit. Capturing the new capability means restructuring the application, which in turn means the evals have to be rebuilt to match the new architecture.

“it was not an incremental change to the previous state-of-the-art”

▶ watch at 02:35
02From single calls to ReAct loops to workflow graphs

AI systems evolved from a single prompt-and-response, to a fixed retrieval chain, to the ReAct pattern of models reasoning and acting in a loop. That loop was exciting but the models of 2023-24 weren't robust enough at tool calling and long-context reasoning, so teams baked orchestration and planning logic directly into workflow graphs or state machines to regain reliability — trading flexibility for predictability, until the graphs' own complexity created new failure surfaces.

03Back to loops, with new reliability metrics

As tool calling and planning got reliable again in mid-to-late 2025, teams moved back toward open agent loops. But run-to-run trajectory variance is now high, so evals shifted from single-answer scoring to distributional metrics: pass@k (did it succeed at least once across k runs, a capability measure) and pass^k (did it succeed every time across k runs, a reliability measure).

“pass at k and pass raise to k or pass wedge k”

▶ watch at 15:06
04Closing the loop: harvesting production failures

Bhatawdekar recommends treating evals as a flywheel — continually harvesting failures from production data to keep eval sets reflective of real-world use. Braintrust's "topics" feature runs cluster analysis on production data specifically to surface new failure categories teams hadn't anticipated and hadn't built guardrails or evals for.

Commentary (ours)

Braintrust is an eval and observability vendor, so recommending the production-harvesting flywheel and topics-style clustering is also a pitch for its own product category. The architecture history — single call to chain to ReAct to graph to loop — is a useful map for orienting an eval strategy regardless of which vendor's tooling is used.
