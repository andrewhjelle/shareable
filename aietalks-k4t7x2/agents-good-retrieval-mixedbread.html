How we taught agents to use good retrieval

SpeakerHanna Lichtenberg · Mixedbread AI Watchyoutu.be/1IdzkRVmWAA
Agentic engineeringEvals & benchmarks

If you only read one thing

  • Mixedbread found a large 'knowledge gap' between LLM reasoning and retrieval: giving a model default tools instead of the oracle-correct documents drops accuracy from 93% to 9% on BrowseComp Plus and from 64% to 8% on Office QA Pro.
  • A dedicated Mixedbread search tool using four bounded search rounds with parallel queries recovers nearly all of that gap on both benchmarks.
  • Their trained small search agent hit NDCG@10 of 0.4, versus 0.18 for the best published GPT multi-hop agent, and topped the Match QA leaderboard at 93.4% accuracy paired with Gemini 3.5 Flash.
01The oracle vs. default-tools gap

Mixedbread benchmarked models on BrowseComp Plus (complex queries over a 100,000-document corpus) and Office QA Pro (complex questions over a century of US Treasury documents). Oracle performance -- giving the model the correct documents directly -- reaches 93% on BrowseComp Plus and 64% on Office QA Pro, but a model like Codex using its default search tools drops to single digits on both.

“We see for Office for BrowseComp it's 93% and for Office QA Pro it's 64%.”

02A dedicated search tool nearly closes the gap

Swapping in Mixedbread's own search tool, using latent interaction retrieval, recovers most of the lost performance: the gap to oracle shrinks to about three points on BrowseComp Plus and is almost entirely closed on Office QA Pro, indicating the bottleneck is retrieval access, not model reasoning.

“the difference between the Oracle and the uh GPT-5 with Mixbread is just three point and for Office QA Pro we even almost completely closed the gap.”

▶ watch at 03:08
03Why agents write bad search queries

Left to their default tools, models produce keyword-stuffed, near-gibberish queries because they are mostly trained on coding tasks that use grep-style regular-expression search, plus human-oriented web search habits and benchmark biases toward entity-based, BM25-favoring queries.

“senator woman questions billionaires not a company then okay thank you staff will check hearing”

▶ watch at 03:39

“the models write these type of queries is they're mostly trained for coding task, like for coding agents, which are then optimized for code base exploration using tools like grep.”

▶ watch at 04:10
04A bounded, tool-diverse search harness

Mixedbread's agent harness offers four tools -- wide overview search, full-payload semantic search, metadata-facet filtering, and grep -- capped at four search rounds, with parallel searches allowed within each round. The harness also reframes query-writing as 'describe one concise sentence of what you want to find' instead of 'write a search query,' to steer the model away from keyword-stuffed BM25-style queries.

“it has a maximum four search rounds, but within each search round it can have parallel searches”

▶ watch at 06:48

“We kind of trick the um model into not thinking it has to write the typical BM25 base query by just instructing it to write one concise sentence describing what it wants to find”

▶ watch at 08:53
05Training and benchmark results

A small model trained via supervised fine-tuning plus on-policy reinforcement learning (with a retrieval reward and an LLM-judged trajectory reward) achieved an NDCG@10 of 0.4 on the BrowseComp benchmark, versus 0.18 for the best-performing published GPT multi-hop agent. Their production beta search agent topped the Match QA leaderboard with 93.4% accuracy when paired with Gemini 3.5 Flash.

“we achieved an NDCG of 10 at 10 of 0.4, which is a huge jump um towards the model that performed best on the paper of this benchmark, which is the GPT multi-hop agent, and which achieves 0. 18.”

“this agent is top one on the snowflakes match QA benchmark, achieving an accuracy of 93.4 when we give the Gemini 3.5 flash model our genetic search as search tool.”
