From Systems of Record to Systems of Context

Names a specific failure mode worth checking for in any assistant built on top of a data-rich platform: having access to all the data (boards, Slack, email) is not the same as understanding it, and an agent without a precomputed profile ...

If you only read one thing

  • The core diagnosis is that assistants have all the data but zero understanding, which is why asking 'what should I focus on' returns disconnected bullet lists rather than a real answer (c1, c2, c9).
  • monday.com's fix, the Monday world model, is built from a slow engine that learns a durable user profile over weeks and a fast engine that reads live signals, mirroring complementary learning systems in neuroscience and lambda architecture in data engineering (c3, c4, c5).
  • The architecture is resilient (isolated sources, graceful degradation) and compounds over time as more sources are added, though it acknowledges new users start with no reliable signal and existing signals carry bias (c6, c7, c8).

The problem: full data access, zero understanding

  • Bruchim opens with a concrete failure: asking an assistant like Claude 'what should I focus on right now' returned unrelated bullet points, in one case suggesting he go to the gym, despite the assistant having access to all his boards, tasks, emails, and Slack messages.
  • He frames the core problem as missing understanding, not missing data or retrieval, and gives a second example: an agent nails a drafted reply to a customer escalation (a task it's told to do) but has no way to know what to prioritize first because it doesn't understand who the user is.

The data model: structure, live signals, and a learned profile

  • monday.com's response, the Monday world model, constructs three things an agent can reason over from user activity: the structure of the user's work (entities and relationships, what depends on what), a current snapshot of live signals (what's overdue, who they're actively working with), and a durable profile of patterns and decisions learned over time.

“We collect thousands of data points on the user every item status change their activity log messages and meetings and construct three things the agent can resone over”

Two engines on different clocks: a slow profile builder and a fast signal reader

  • The system runs two engines on different time windows: a slow engine that mines weeks of activity into a durable profile of the user's role, routines, and collaborators, and a fast engine that recomputes live signals over a short recent window.
  • Ast draws the same split from neuroscience's complementary learning systems (hippocampus vs. neocortex) and from lambda architecture in data engineering (speed layer vs. batch layer), noting both fields independently landed on the same pattern.

“we use two engines running on different time windows and schedules. A slow engine that runs on a long time window and learns the user and their work”

said at 08:50

“In neuroscience, this split is referred to as complimentary learning systems. And in data processing architecture, it's referred to as a lambda architecture”

said at 09:56
04Resilience and compounding value
Slide at 10:00 · click any slide to enlarge

Resilience and compounding value

  • Because sources are isolated, a bad feed degrades gracefully rather than breaking the whole system, falling back to the last verified context.
  • The value compounds daily as more data accumulates and the profile sharpens, and adding a new data source is deliberately cheap, so the system's understanding only grows.

“The data model, it's resilient. Sources are isolated so a bad feed can't break the rest”

said at 11:30

“And the crucial part is that it compounds. Every day the data is captured, the layers fill in and the profile sharpens”

said at 12:02

Acknowledged limits

  • The team is explicit that the model always trails the live world: new users start with no reliable data to reason from, and the signals it does learn carry the system's own biases.

“the model itself is always trailing the actual live world. New users have no reliable data to reason from yet, and signals have our own biases built in”

said at 12:34

Commentary (ours)

The talk names the complementary learning systems / lambda architecture parallel as validation for the two-engine split, but doesn't share any measured accuracy or user-satisfaction numbers for the resulting 'Sidekick' assistant, so how much closer this actually gets to a correct prioritization answer versus the gym-suggestion baseline is asserted, not shown (ours).
