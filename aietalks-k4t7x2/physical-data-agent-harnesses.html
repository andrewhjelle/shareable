Frontier labs admit agents are bad at physical data

  • Petrov cites Anthropic and OpenAI results published this year showing agents perform poorly on data work without added scaffolding: Anthropic reported only 21% accuracy on data projects until specific data harnesses and context were added, and OpenAI needed six layers of context to make their data agent function.
  • He notes both examples were structured, warehouse-resident data, whereas his own work is on messy unstructured physical data, which he argues is a harder, distinct problem.

“Anthropic published that accuracy for data projects on their agents is only 21% until you add specific data harnesses to them and provide context.”

02Metadata explodes past what flat files or ad hoc databases can handle

Metadata explodes past what flat files or ad hoc databases can handle

  • A modest set of video files nests into clips, frames, and detected objects, producing an explosion in record count; his example of 90 analyzed dashcam videos already generated 100,000 records.
  • He warns the volume compounds further with scale, arguing storing this as scattered JSON files on S3 or duct-taping a second database creates latency, consistency, and two-stack maintenance problems, which is why DataChain instead uses Pydantic schemas as a shared language between data and code.

“if you analyze thousands of videos, right? It goes to like a million million scale and if you go to deeper to the objects, it can easily it can easily be multiplied by 10 20 even hundreds.”

03Execution needs incremental checkpoints, not full reruns
Slide at 18:20 · click any slide to enlarge · 3 more from this section below

Execution needs incremental checkpoints, not full reruns

  • Petrov argues unstructured data processing needs its own execution engine (unlike the SQL world, where the data warehouse plays that role), one that can parallelize across machines and, critically, recover from failure without recomputing everything.
  • He frames incremental updates and checkpoints as mandatory given how expensive and slow reprocessing hundreds of thousands of files can be, especially when LLM calls are involved.

“It's really sad when you process uh, hundreds of thousands of files and it fails in the middle because of bugs or API call issue and you want to execute everything from scratch, right?”

said at 18:18

“Incremental update and data checkpoints it's a must-have in this data world.”

04Data questions have one correct answer, unlike code
Slide at 19:50 · click any slide to enlarge · 8 more from this section below

Data questions have one correct answer, unlike code

  • He contrasts data projects with software projects: software has many valid ways to solve a problem, but a data question typically has only one correct answer, raising the bar on accuracy.
  • His recommendation is to stop running expensive ad hoc scripts against raw data for every question and instead build a reusable layer of pre-aggregated metadata/datasets that can answer a whole class of questions quickly.

“In data, there is usually only one way and only one current correct answer uh to solve the problem.”

said at 19:51

“instead, you need to organize layer of meta information over like data sets uh or tables around this uh raw data uh that could answer these questions very quickly.”

05Coding agents misfire on physical data without a harness
Slide at 26:20 · click any slide to enlarge · 1 more from this section below

Coding agents misfire on physical data without a harness

  • Petrov's closing claim is that general-purpose coding agents (Copilot, Codex, Claude Code) don't operate efficiently on physical data because their default assumptions don't hold in this domain, and that the fix is not a stronger frontier model but a purpose-built data harness that understands the different 'physics' of physical data.

“Their intuition pushes them in a wrong direction because laws of physics changes.”
