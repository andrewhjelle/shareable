01Clicking is solved; verifying the work is not

Clicking is solved; verifying the work is not

  • Barth opens by distinguishing between agents that can perform individual UI actions reliably and agents that can complete an end-to-end multi-app workflow, arguing the real work lives in the seams between applications where nothing today watches for success or failure.
  • She frames a rough 60-80% success rate as unacceptable for anything destructive, citing database deletion as the example that would make you stop trusting an agent.

“What we figured out, click clicking was actually the easy part. What we didn't solve is the actual work.”

said at 01:06

“if your agent one in four times deletes a database, you will never touch that agent again, right”

02Why coding got reliable first

Why coding got reliable first

  • She attributes coding's early jump to trustworthiness to the fact that code is verifiable: it can be run, tested, and checked with a pass/fail result, so reward signals from that verification could actually train reliability.
  • Most knowledge work, by contrast, has no equivalent 'unit test' and verification hits a wall exactly where most real work happens.

“It's because code is verifiable. You can run it, you can test it, you can check it and you can be for sure that it worked”

said at 05:50

“there is no unit test that can answer those questions. So verification really hits the wall right where most of our work lives”

said at 06:23
03Perception agents: closing the loop with shared context
Slide at 08:40 · click any slide to enlarge · 6 more from this section below

Perception agents: closing the loop with shared context

  • Barth's proposed fix is an agent that perceives the same rendered screen a human sees (not scraped code), so it needs less explanation and can confirm its own output rather than firing an action and hoping.
  • She defines this as completing the classic perceive-plan-act loop from robotics applied to screen-based work, and stresses it doesn't require an API or backend, since it works directly off rendered pixels and structure, which most everyday software doesn't expose via API anyway.

“You don't necessarily need a bigger brain. What you need is this shared context”

said at 08:27

“A perception agent can read the rendered screen so it can confirm its own output instead of just firing off those actions and then hoping”

said at 11:36

“it works off the rendered interface. It sees the same pixels and the structure you see. And most of today's software people use every day don't expose APIs at all”

said at 12:09
04Open-source release: annotation and verification
Slide at 13:10 · click any slide to enlarge · 8 more from this section below

Open-source release: annotation and verification

  • Amazon AGI Lab open-sourced the first two pieces of a perception-agent harness: an annotation tool (a Chrome extension for marking up UI elements to give the agent precise change instructions) and a verification tool that checks an agent's own output against a design-rules file, including both visual brand checks and automated user-flow walkthroughs.

“we just recently launched the first two pieces of our perception agent harness open source”
