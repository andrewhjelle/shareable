If you only read one thing

  • ACP standardizes agent-to-client (human-to-agent) interaction, distinct from MCP (tools-to-model) and A2A (agent-to-agent); the speaker chose ACP because Codex and Claude Code adapters existed for it first.
  • OpenClaw receives 60,000+ PRs total, 300-500 opened per day on average, from tens of thousands of stakeholders -- creating a triage problem acpx's workflow engine (find intent, judge implementation, check conflicts, run CI) is built to automate.
  • The speaker predicts enterprise agent usage will consume far more inference than personal/home usage, unlike prior PC-at-work-vs-home parity, driving disposable per-task agents running as full Kubernetes pods.

01ACP vs. MCP vs. A2A
Slide at 05:10 · click any slide to enlarge · 3 more from this section below

ACP vs. MCP vs. A2A

  • The speaker distinguishes three protocols: MCP gives tools to a model, ACP (Agent Client Protocol) standardizes agent-to-client interaction typically for a human talking to an agent (though an agent can also use it to talk to other agents), and A2A (agent-to-agent protocol) is for agents talking to each other directly.
  • He chose ACP because, at the time he needed it, only ACP had adapters built for both Codex and Claude Code.

“MCP for is for giving tools to the model. ACP's for uh like standardizing agent to client interaction”

“agent like agent to agent protocol, that's for agent talking to agent. ACP, agent client protocol, is for human talking to agent, but agent can use the human one to talk to other agents as well”

The scale of OpenClaw's PR triage problem

  • OpenClaw currently has over 60,000 total PRs with 300-500 opened per day on average, from what the speaker estimates are tens of thousands of stakeholders wanting to add features.

03Disposable, per-task agents on Kubernetes
Slide at 16:20 · click any slide to enlarge

Disposable, per-task agents on Kubernetes

  • The speaker's broader vision is one agent per task rather than one long-running personal agent, requiring Kubernetes, an agent harness (OpenClaw, Codex, or Claude Code), and state synchronization between agent instances.
  • His day-job project, an open-source orchestrator, gives each dispatched agent a full Kubernetes pod rather than a lighter sandbox, which he argues is the better abstraction despite being resource-wasteful, because giving an agent a full computer makes it more powerful.

“it's actually using like a full Kubernetes pod. Wasteful, but I think it's the better abstraction because open core showed the power, you know, when you give a full computer to an agent, it's a lot more powerful”

said at 16:37
04Enterprise vs. personal agent economics

Enterprise vs. personal agent economics

  • He predicts enterprise and personal computing will diverge for agents in a way they didn't for PCs, because enterprise agent usage will consume substantially more inference than home usage, meaning more money will be made on enterprise agent deployments -- part of his stated motivation for focusing on enterprise adoption of OpenClaw.

“you will be using consuming a lot more inference. And that means in enterprise there will be a lot more money to be made”

said at 13:01
05Current limitation: chat platforms lack multi-agent identity support
Slide at 13:40 · click any slide to enlarge · 8 more from this section below

Current limitation: chat platforms lack multi-agent identity support

  • He notes that chat platforms like Slack don't yet support provisioning multiple distinct agent identities (name, profile picture) from one integration without manually creating a separate app and manifest for each, which he says must be solved for the on-demand disposable-agent vision to work; in the meantime he demos the workaround via a separate web UI, used at his company for dispatching agents to debug production error reports.

“If you use open clone slack or teams or discord, this is one instance. You create an app.”

said at 13:31

“you can ask it to dispatch an agent to debug it, you know, you're like, "I'm uh, asking any new bugs after prod release."”

said at 16:06

Commentary (ours)

The 'full Kubernetes pod per disposable agent' choice is explicitly conceded as wasteful by the speaker -- it's a bet that agent capability from full-machine access outweighs the orchestration cost, which is a real tradeoff other teams building similar systems will hit (ours).
