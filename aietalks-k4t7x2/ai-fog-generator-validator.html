Nair argues, with data from Snyk's own customer base and red-team benchmarks, that letting the same model both generate code and validate its own security is unreliable, which directly informs whether a vertical-AI or agentic-coding depl...

If you only read one thing

  • Snyk's enterprise backlog data shows security debt growing 108% quarter over quarter despite widespread agentic coding adoption, and Five Eyes has warned AI will bypass cybersecurity systems within months (c2, c4).
  • In fresh Snyk red-team benchmarks, the newest models extracted PII 100% of the time under attack while an open model resisted decision-override attacks 0% of the time, and the same model asked to re-find a known vulnerability five times only succeeded half the time, scoring 40% F1 against a deterministic check (c5, c6, c7, c8).
  • A third or more of tested agent skills contain malware or exploitable vulnerabilities, underscoring why Nair says the generator and the validator of agentic output should not be the same system (c3).

Self-checking models don't reliably find their own bugs

  • In new Snyk benchmark research, asking a model to find the same known vulnerability five times succeeded only 50% of the time across those runs, and the latest models found only 75% of issues a deterministic check caught, scoring a 40% F1 against that check.
  • Nair uses this to argue for keeping generation and validation as separate systems rather than trusting a single model to grade its own output.

Remediation at scale is already happening
