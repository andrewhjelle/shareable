If you only read one thing

  • Microsoft frames agent knowledge as three categories -- intrinsic (model training/parametric memory), extrinsic (company grounding via Microsoft IQ: work IQ, fabric IQ, foundry IQ, web IQ), and learned (production traces fed back through an optimizer) (c1, c3)
  • Foundry's retrieval stack layers simple one-click ingestion on top of expert-level control over indexing and quantization, and its own evaluations show combined retrieval methods and agentic (reflective, multi-step) retrieval both outperform single-method, single-shot search on difficult cases (c4, c5, c6)
  • The Foundry Agent Optimizer automates a learning loop: it generates an evaluation from an agent's traces and instructions, then hill-climbs a candidate agent configuration against that evaluation before you apply the improved version (c7, c8, c9)

01Three kinds of knowledge, and the coding exponential
Slide at 01:10 · click any slide to enlarge

Three kinds of knowledge, and the coding exponential

  • Castro splits agent knowledge into intrinsic (what's baked into model training/parameters), extrinsic (company data an agent is grounded on), and learned (knowledge produced by observing and improving agents' own work over time).
  • He illustrates intrinsic knowledge's impact with a coding timeline running from Microsoft IntelliSense (1996) through machine-learning-ranked suggestions, GitHub Copilot, Cursor, and on to current-generation models, arguing this progression was powered largely by models' intrinsic knowledge and reasoning ability.
  • He also notes that Claude became generally available inside Microsoft Foundry the day before this talk.

02Grounding agents in company data
Slide at 07:50 · click any slide to enlarge

Grounding agents in company data

  • For extrinsic knowledge, Microsoft built Microsoft IQ as a single entry point into an organization's ambient data beyond whatever an individual agent is built with directly.
  • It splits into work IQ (SharePoint documents, email, calendar, chats, people connections), fabric IQ (data warehouses, data lakes, Power BI reports), foundry IQ (an agent's own pushed data), and web IQ (public web grounding).

“we built Microsoft IQ as a way to give you a single entry point into all these kind of ambient data that agents need to get the job done”

said at 05:42
03From vector search to agentic retrieval
Slide at 08:00 · click any slide to enlarge · 8 more from this section below

From vector search to agentic retrieval

  • Castro describes retrieval evolving from an early rush toward vector databases and cosine similarity toward more layered systems, citing internal evaluations showing combined retrieval methods consistently beat any single method, especially on real customer scenarios.
  • Foundry's Knowledge Base stack lets users start with simple ingestion (point at PDFs, let Foundry chunk and vectorize) or drop down to control indexing, quantization, and lexical retrieval directly, and every Knowledge Base is exposed as an MCP server.
  • On top of that, an agentic retrieval layer reflects on whether an information need has been satisfied before returning results, which internal evaluations show performs better than single-shot retrieval on difficult cases.

“what evaluations show over and over again is how, you know, if you combine methods, you just get better results”

04Learning loops: the Foundry Agent Optimizer
Slide at 13:00 · click any slide to enlarge · 6 more from this section below

Learning loops: the Foundry Agent Optimizer

  • For learned knowledge, Castro describes a Foundry component called the Agent Optimizer that evaluates a baseline agent, generates candidate configurations, and promotes ones that score better.
  • In a live demo he ran eval-generation from an agent's traces and instructions, then ran an optimize step that took roughly 45 minutes to hill-climb toward a better-scoring configuration, after which the improved instructions could be applied to replace the hand-written baseline.

“we built a component called the agent optimizer that effectively goes through this process and allows you to evaluate a baseline, generate candidates”

Commentary (ours)

Castro is presenting Microsoft's own product stack (Foundry, Microsoft IQ, Agent Optimizer) as the embodiment of a three-part knowledge taxonomy, so the framing and the retrieval/optimizer performance claims should be read as a vendor case for that stack rather than independently validated benchmarks; no comparison numbers or methodology for the cited evaluations are given in the talk.
