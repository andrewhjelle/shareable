Replacing 12K LoC with a 200 LoC Skill

If you only read one thing

  • Cursor deleted around 15,000 lines of code by replacing its Git-worktree and best-of-N (multi-model comparison) features with markdown skills built on two existing primitives, agent skills and sub agents; the best-of-N skill runs about 40 lines versus roughly 4,000 lines of code before.
  • The hardest part is keeping the agent from escaping its assigned worktree: the old code made this physically impossible, while the new skill relies on aggressive prompting alone, which the speaker calls 'vibes-based,' and evals show smaller models like Haiku deviate from the worktree more often than Composer or Grok.
  • The skill-based rewrite gained multi-repo worktree support the old feature never had but lost feature discoverability, and Cursor is now adding worktree-staying tasks to its Composer RL training pipeline since Composer 2 had none for this environment.
▣The system in one picture (ours, from the slides and the transcript)

The rewrite traded physically-enforced isolation for prompting plus evals, which is why Cursor is now backfilling worktree-staying tasks into RL training (ours).

03The hardest part: keeping the agent from escaping its worktree

The hardest part: keeping the agent from escaping its worktree

  • The speaker identifies instructing the model to stay on its assigned worktree as the hardest part of the rewrite, requiring what he calls aggressive prompting.
  • He contrasts this with the old code-based implementation, where it was physically impossible for the model to touch files outside its worktree; the new approach instead trusts the model, which he describes as a bit vibes-based.

04What the skill approach gained: multi-repo support

What the skill approach gained: multi-repo support

  • One concrete advantage of the new implementation is that it works across multi-repo setups (for example, separate front-end and back-end repos), something the old worktree feature did not support at all -- it was simply disabled in that case.

“Another big advantage is that the previous implementation did not work if you were working on multiple repos at the same time.”

05Fixing agent drift with evals and RL training data

Fixing agent drift with evals and RL training data

  • To address the agent drifting outside its worktree, Cursor is building evals (using Braintrust) that check whether a model worked inside its assigned worktree versus the primary checkout, and has already found that smaller models like Haiku deviate more often than Composer or Grok.
  • Separately, Cursor's own Composer model had no RL training tasks covering this kind of environment as of Composer 2, and the team is adding such tasks to the RL pipeline for future versions.
