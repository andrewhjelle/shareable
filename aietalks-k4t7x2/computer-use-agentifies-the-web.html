Computer-use models will agentify the web, not APIs

patternComputer useWeb automation

This is a direct argument against betting agent infrastructure on the web exposing APIs or MCP servers everywhere: most of the web (restaurant menus, school district procurement pages, small business sites) is scanned PDFs, JPEG gallerie...

If you only read one thing

  • The long tail of the web (the ~200 million active sites beyond the largest platforms) will not expose APIs; institutions change infrastructure slowly and much of it is scanned PDFs and image galleries with no extractable text (c2, c3).
  • Rendered information (prices, stock status, live scores) is often not present in the HTML at all — it's fetched asynchronously as JSON and rendered client-side, so scraping the HTML doesn't work either; the web was built for human eyes, so agents need vision (c4, c5).
  • Yutori's Navigator model hits 97% human-eval on a saturated Online Mind2Web benchmark and runs a 20-30 step task for about 80 cents versus a substantially higher cost for comparable frontier-model agents (c6, c7).

The API argument, and why it's wrong for the long tail

  • Batra frames a common argument: AI agents will drive web actions, the web will resist automated traffic, so it will expose APIs/MCP servers for agents to call.
  • He agrees with the first two steps but rejects the third specifically for the long tail of the web — the most popular sites may offer APIs, but the vast majority of sites will not.

“computer use agents and computer use models will identify the web not APIs and more specifically the long tail of the web”

What the real long tail looks like

  • He walks through concrete examples: a restaurant's gluten-free menu is often a JPEG gallery containing scanned PDF menu pages with no extractable text; a school district's RFP status may require filing a Freedom of Information Act request that gets manually scanned into a Google Drive.
  • There are roughly 200 million active websites, and the broader infrastructure they sit on changes very slowly, so coding-agent-generated API endpoints for these institutions are not coming soon.

03Even the HTML doesn't have the answer
Slide at 09:10 · click any slide to enlarge · 8 more from this section below

Even the HTML doesn't have the answer

  • Throwing a coding agent at the raw HTML doesn't solve it either.
  • On a modern site like nba.com, the score isn't in the initial HTML — an empty placeholder loads first, then the browser makes an asynchronous call and renders the JSON response.
  • Stock/sold-out status on product pages works the same way: the HTML doesn't say 'sold out,' a rendering script grays out the option based on a quantity variable fetched separately.
  • The web was built for human eyes; pixels, not markup, are the source of truth, so machines need vision to operate it.

“There's an empty placeholder initially and you wait a few hundred milliseconds to a few seconds depending on your network connection and your browser makes an asynchronous call later to fetch the information”

said at 09:23

“Fundamentally the web was built for human eyes. Pixels are the source of the truth because the consumers of the websites are humans. That is what it was built for”

04Where the numbers stand today
Slide at 15:30 · click any slide to enlarge · 1 more from this section below

Where the numbers stand today

  • Batra reports that Yutori's Navigator N1.5 model scores 97% human-eval on the Online Mind2Web benchmark (8 of 300 trajectories incorrect), which he says means the benchmark should be retired for something harder.
  • On latency and cost, a 20-30 step browser task runs about 80 cents versus roughly $2-30 for larger frontier-model-based agents, and he expects accuracy to keep rising while latency and cost keep falling.

Commentary (ours)

The wager here is specific: don't build product plumbing around an assumption of universal API/MCP coverage for third-party sites you don't control, especially small institutional ones. The counterargument not addressed in the talk is whether sites will actively adversarially block computer-use traffic once it's common at scale. (ours)
