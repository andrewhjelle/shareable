From 46% to 90%: Fine-Tuning Tiny LLMs for On-Device Agents

SpeakerCormac Brick · Google Watchyoutu.be/-TiET_K-E_g
Local modelsPost-trainingAgentic engineering

If you only read one thing

  • Fine-tuning Function Gemma (270M params) on a synthetic data set raised app-intent function-calling success from 46% to over 90% for 8 of 10 functions.
  • On-device skills are loaded on demand via a load-skill tool call rather than stuffed into the prompt up front; an 8-skill model chains skills across a conversation reasonably well but calling multiple skills within one answer is still unreliable.
  • Google's on-device runtime (formerly TensorFlow Lite) already ships inside Android OS and supports over 2.7 billion devices.
01System-level vs. app-level on-device AI

The speaker frames on-device AI as a choice between system gen AI (Gemini Nano via AI Core, pre-installed and free of app size cost) and app gen AI (a model bundled into the app itself via the LiteRT-LM runtime for more customization). The underlying runtime already runs inside Android OS at large scale.

“it does uh, support over 2.7 billion devices, like lots and lots of daily invocations, and lots and lots of Android apps uh, leverage this”

▶ watch at 02:05
02How skills load on device

Skill descriptions are put into the system prompt so the model knows what skills exist, but the model doesn't see a skill's full function details until it calls a load-skill tool for that skill on demand. With the current 4B-parameter model and about eight enabled skills, chaining skills across turns in a conversation (skill, skill, skill) works robustly, but getting the model to call multiple skills within a single answer is still being worked on and only works sometimes.

“the model is aware of the types of skills it can use, but it doesn't have to see all of the functions and details of the skill”

03What tiny models can do today

Apple's FastVLM, a 500-million-parameter visual language model, runs accelerated on a Qualcomm NPU through the same stack. Function Gemma, a 270-million-parameter model published with DeepMind based on Gemma 3, is small enough to hit almost 2,000 tokens/second prefill and 140 decode even on a legacy Pixel 7.

“this is a visual language model that's only 500 million parameters and this is optimized and running on like a um this is running on the Qualcomm NPU”

▶ watch at 12:23

“if you go all the way back to a Pixel 7, they still can process almost 2,000 tokens per second prefill and 140 decode”

▶ watch at 13:25
04Fine-tuning turns a weak baseline into a robust one

Out of the box, Function Gemma's success rate on the team's app-intent functions (like add calendar or add email) was about 46%. After generating a synthetic training data set (using Flash) and fine-tuning on it instead of relying on a system prompt, success rose to over 90% for 8 of the 10 target functions, with the remaining two lower.

“when we took function Gemma out of the box, our success rate in that was I think 40 6% or something like that”

▶ watch at 14:27

“that then got that 46% um to over like it was over 90% for eight of the 10 functions we were trying and two of the functions were a bit lower in their kind of ACs”

Commentary (ours)

The 46%-to-90% jump is specific to this team's narrow app-intent function set, not a general claim about tiny-model reliability -- worth checking whether similar synthetic-data fine-tuning gains hold for tool-calling tasks with more than 10 functions or more ambiguous intents (ours).
