How Lovable self-improves every hour

Describes two concrete mechanisms Lovable uses to make its coding agent learn from production failures without retraining: a clustered knowledge base ('Stack Overflow for Lovable') that gets injected into context and A/B-tested for usefu...

If you only read one thing

  • Lovable clusters 'stuck' sessions (repeated asks, complaints, abandoned sessions) into a knowledge base, then A/B-tests whether injecting that context actually improves outcomes before rolling it out (c2, c3, c4).
  • A 'vent tool' lets the agent send Slack messages about tooling/doc/platform friction only when it's genuinely frustrated, which keeps signal-to-noise far better than an external reviewer scoring every turn (c6, c7, c8).
  • The vent tool has surfaced real bugs (a file-copy failure caused by non-breaking spaces) and even served as an incident detector when spikes in complaints coincided with outages (c9, c10).

01The problem: users shouldn't have to explain the same thing twice

The problem: users shouldn't have to explain the same thing twice

  • Verbeek frames the talk around continuous learning at scale: agents should learn from a mistake once and never repeat it.
  • He distinguishes technical users, who can push through friction points and manual fixes, from non-technical users, who tend to walk away the first time they hit a technical block.
  • Lovable's goal for the past year has been eliminating those give-up points so non-technical users never get stuck.

“We want to have a mistake happen once and then never again.”

said at 01:02

“one clear signal of someone being stuck is that they ask for the same thing more than once”

02Building a Stack Overflow for Lovable
Slide at 06:50 · click any slide to enlarge · 3 more from this section below

Building a Stack Overflow for Lovable

  • Lovable detects stuck sessions via signals like repeated requests, explicit complaints, or abandoned sessions, flagged by an LLM judge.
  • When a session moves from 'stuck' to resolved, the team asks what should have been injected at the start of the query to avoid the friction, clusters similar issues to avoid overfitting to one exact prompt, and has an agent (occasionally a human) validate the fix before it enters a growing knowledge bank.

“we basically learn from uh whenever someone is stuck and has an issue, we try to figure out the solution and give that to the agent”

said at 06:43
03Testing injected context with a blind holdout
Slide at 09:10 · click any slide to enlarge · 3 more from this section below

Testing injected context with a blind holdout

  • A lightweight model decides when to inject a knowledge-base entry into the main agent's context, but for a small sample of eligible cases it deliberately injects nothing, creating a control group.
  • Comparing outcomes between the injected and blank groups lets Lovable measure whether an entry actually helps and rebalance or discard entries that go stale as models and features change.

“we inject a blank. So, we don't actually send anything for a small sample of use cases.”

said at 09:52

“the number of messages with fixing tent or people being stuck is dropping significantly”

said at 10:53
04Giving the agent a 'vent' tool instead of scoring every turn
Slide at 12:20 · click any slide to enlarge · 2 more from this section below

Giving the agent a 'vent' tool instead of scoring every turn

  • Rather than using an external reviewer to critique every conversation turn -- which produces low signal-to-noise since most turns are fine -- Lovable gave its agent a tool to send feedback to Slack only when it judges tooling, docs, or platform behavior to be genuinely degrading its work.
  • The agent has more context on the actual cause of a failure than the user does, since it has been directly working the problem, sometimes across several turns.

“we thought, why not do exactly that, but for the agent?”

said at 12:25

“One problem with that is that you get a pretty low signal-to-noise ratio.”

said at 12:56

“In this case, it's prompted to only send feedback if it is really frustrated.”

said at 13:27
05The vent tool caught real bugs and outages
Slide at 15:10 · click any slide to enlarge · 8 more from this section below

The vent tool caught real bugs and outages

  • One vent report revealed that the copy tool failed on file names containing a regular space, and after that fix, complaints continued because screenshots from WhatsApp or Mac inserted a non-breaking space the regex didn't catch.
  • Separately, spikes in the volume of vent messages over time lined up with server outages and broken sandboxes, making the vent stream a usable incident-detection signal.

“It turns out that there was an error where it could not copy files with a space in their name.”

said at 15:33

“it turned out that this was actually a prime place to notice when our product was having an incident”

said at 17:37

Commentary (ours)

The blind-injection holdout is the part worth stealing regardless of domain: most 'agent learns from feedback' systems skip the control group and just assume the injected context helped, which is how knowledge bases quietly rot into context bloat (ours).
