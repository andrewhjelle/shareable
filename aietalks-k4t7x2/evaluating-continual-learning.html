If you only read one thing

  • Standard LLM evals reset the model's memory between every task instance, which structurally can't measure learning; the author defines continual learning as sample-efficient online learning that is stable over long horizons (c1, c2).
  • Continual Learning Bench 1.0 requires three properties per task -- headroom, shared structure, and a learning mechanism -- and separates gain (stateful minus stateless reward) from raw reward so base-model strength doesn't get confused with learning ability (c4, c5).

01The problem with today's LLM evals
Slide at 01:00 · click any slide to enlarge · 3 more from this section below

The problem with today's LLM evals

  • Asawa argues current benchmarks evaluate every task instance independently, effectively asking models to forget everything between tasks, then aggregate those independent scores into leaderboards.
  • He defines continual learning as sample-efficient online learning that stays stable over long horizons, requiring both retention of prior information and adaptation to new information, and argues chaining existing independent benchmark instances together doesn't fix this because those instances share no latent structure to learn from.

02Three requirements for a continual-learning benchmark
Slide at 03:10 · click any slide to enlarge

Three requirements for a continual-learning benchmark

  • The talk sets three design criteria for any continual-learning task: headroom (the task must require online adaptation, not something a frontier model already knows from pretraining), shared structure (task instances must share latent structure so prior experience can help), and a learning mechanism (some signal in the environment, such as reward or error messages, that lets an agent actually learn).

“you need some sort of task that actually requires online adaptation or learning from the language models”

said at 06:08
03Metrics: reward, gain, and cost
Slide at 03:10 · click any slide to enlarge

Metrics: reward, gain, and cost

  • Continual Learning Bench 1.0 defines a per-instance reward for each task, but cumulative reward alone can confound continual-learning ability with base-model strength.
  • To isolate the effect of learning, every system is run twice: once maintaining state across the sequence, and once reset to a stateless baseline between instances.
  • Gain is the difference between stateful and stateless reward, and the benchmark reports reward, gain, and cost together as Pareto frontiers.

“Gain refers to the difference between stateful reward and stateless reward.”

said at 09:13
04Results: in-context learning wins, and why methods fail
Slide at 15:20 · click any slide to enlarge

Results: in-context learning wins, and why methods fail

  • Across six task domains (signal monitoring, codebase adaptation, epidemiology cohort studies, exploitable poker, database exploration, and sales prediction), vanilla in-context learning currently tops the leaderboard on both reward and the gain-versus-cost Pareto frontier, ahead of more elaborate context-management systems, though Asawa notes the task horizons may not yet be long enough to stress those systems.
  • Observed failures split into stability failures, where a system forgets a prior correction and reverts to an earlier bad prediction, and plasticity failures, where a system fails to recognize that new information (e.g., after a database migration) should update its stored notes.

05Where the field should go next

Where the field should go next

  • Asawa closes with his own view that today's continual-learning methods are built on top of frozen post-training checkpoints as an afterthought, calling it a sunk-cost fallacy, and says he is personally excited about parametric methods that treat continual learning as a first-order training phase rather than a bolt-on.

“I'm personally quite excited about the parametric methods for continual learning”
