How I automate my own job at Hugging Face using agents

This talk gives a concrete case for choosing a deterministic workflow versus a fully autonomous agent on the same real job (research outreach at scale), with named infra choices (Modal batch, GitHub Actions cron, LangFuse, Claude Agent S...

If you only read one thing

  • Niels first built a deterministic workflow (no agent framework) following Anthropic's early advice to start simple, then moved GitHub-issue follow-ups to a fully autonomous Claude Agent SDK agent once models improved, echoing Cursor's report of replacing 12,000 lines of workflow code with a 200-line skill.
  • The agent runs nightly via GitHub Actions cron and processes issues in parallel Modal batch containers; out of thousands of GitHub issues created, only two drew negative reactions.
  • His Daily Papers Twitter bot passed 90,000 followers with no manual involvement, and he now runs GLM 5.2 for the agent, which he says beats Opus 4.8 on post-training bench at lower cost.

01Why a deterministic workflow first
Slide at 06:50 · click any slide to enlarge · 3 more from this section below

Why a deterministic workflow first

  • Niels' community science team at Hugging Face manually filed GitHub issues asking researchers to move model/dataset weights from Google Drive, GitHub releases, or Dropbox onto Hugging Face for better discoverability, but this didn't scale against hundreds of daily arXiv papers.
  • He chose a deterministic, non-agentic workflow to automate the outreach, citing Anthropic's building-effective-agents guidance current at the time.

“Try to avoid building agents if you really don't have to. Start simple, start with a single LLM API.”

said at 05:43
02From workflow to autonomous agent for follow-ups
Slide at 09:40 · click any slide to enlarge

From workflow to autonomous agent for follow-ups

  • Months later he automated the reply-following-up step with a fully autonomous Claude Agent SDK agent rather than another workflow, after an Anthropic workshop argued models had become good enough for that shift; he cites a similar Cursor talk about replacing thousands of lines of custom workflow code with a short skill.
  • He does not disclose to researchers that the outreach is agent-generated, reasoning that flagging it as a bot would make people quickly close the issue.

“they replaced 12,000 lines of custom code, pretty sophisticated workflow, with a very simple 200 lines of code skill.”

said at 09:52

“to be honest, I don't disclose that it's an agent. Why? Because I think if people know it's a bot, then they might quickly like close the issue.”

said at 13:31
03Deployment infrastructure
Slide at 07:40 · click any slide to enlarge · 8 more from this section below

Deployment infrastructure

  • The nightly outreach workflow runs as a Python script on a GitHub Actions cron job; the follow-up agent runs on Modal using its batch processing feature, spinning up one container per GitHub issue in parallel.
  • He uses LangFuse for tracing and observability, to see prompts, inputs, outputs, cost, and latency.

“Every single container is basically one agent loop that is processing one GitHub issue.”

said at 11:57

“I use it mostly for the tracing part, the observability part, just to see what is the LLM doing, what are the inputs, what are the outputs”

said at 07:48
04Results: reach with minimal pushback

Results: reach with minimal pushback

  • Out of thousands of GitHub issues the agent has opened, Niels reports only two negative comments; most researchers, including ones from Apple and Google DeepMind, responded positively and published their weights or datasets on Hugging Face.
  • His separate Daily Papers Twitter bot, using the same underlying workflow, passed 90,000 followers without further manual involvement.

“out of the thousands of issues that are being created on Hugging Face, actually so far I've only had two negative comments.”

said at 14:01

“recently crossed 90,000 followers without any involvement of me.”

said at 18:40
05Open models are catching up
Slide at 11:20 · click any slide to enlarge · 8 more from this section below

Open models are catching up

  • Niels recently switched the follow-up agent from Claude models to GLM 5.2 served via Hugging Face inference providers, noting it performs well on Cursor's benchmarks and, on a post-training benchmark he cites, beats Opus 4.8 while costing less.

“Post-training bench is another one uh where it actually beats Opus 4.8 and it's cheaper.”

said at 11:26

Commentary (ours)

The two-negative-comments figure is self-reported and the sample is one team's low-stakes, opt-out-friendly use case (research outreach), so it may understate pushback risk for agents operating in higher-stakes or less receptive channels.
