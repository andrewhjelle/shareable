If you only read one thing

  • OpenRAG combines three existing open-source projects: Docling for document processing, OpenSearch for search indexing, and LangFlow for visual orchestration and agents (c1).
  • It defaults to the JVector KNN plugin instead of OpenSearch's built-in HNSW/IVF options specifically because JVector's disk-based architecture means the index doesn't need to fit in memory (c3, c4).
  • The whole stack, including Docling itself, can run fully offline with locally hosted models, which the speaker says makes air-gapped deployment possible (c6).

02Document parsing: multiple pipelines, including a single vision-language-model option
Slide at 04:00 · click any slide to enlarge · 3 more from this section below

Document parsing: multiple pipelines, including a single vision-language-model option

  • Docling routes different file types through different pipelines: a simple pipeline for straightforward text formats, an ASR pipeline for audio/video, and for PDFs either a standard pipeline of small focused models (layout analysis, table extraction, image extraction, optional OCR) or a newer, simpler VLM pipeline that uses the Granite Docling 258 million-parameter vision model to extract everything in one pass.

“There's also a VLM, a vision language model pipeline that uses the granite docling 258 million vision model to extract all of that in one go.”

said at 04:07
03Indexing choice: JVector over the default plugin
Slide at 06:10 · click any slide to enlarge · 4 more from this section below

Indexing choice: JVector over the default plugin

  • Rather than OpenSearch's built-in nearest-neighbor plugin (HNSW or IVF options), OpenRAG defaults to the JVector KNN plugin.
  • Its disk-based architecture means the whole vector index doesn't need to fit in memory, which the speaker frames as giving more headroom for scaling data servers.

“The default open search nearest neighbors plugin gives you options for HNSW or IVF vector indexes but open rag uses the JVector KNN plugin by default.”

said at 06:09

“disk KNN architecture means your whole index doesn't have to fit in memory giving you more options for scaling the data servers”

said at 06:42
04Agentic retrieval instead of fixed top-K
Slide at 07:40 · click any slide to enlarge

Agentic retrieval instead of fixed top-K

  • Rather than a traditional pipeline that embeds the query, pulls a fixed top-K of chunks, and hopes the answer is in there, OpenRAG's generation side hands the query to an agent with search tools and instructions, and the model itself decides what searches to run and how to use the results.

“The model is actually responsible for deciding what searches to perform and what to do with the results.”

said at 07:44
05Offline capability and connectors
Slide at 04:50 · click any slide to enlarge · 8 more from this section below

Offline capability and connectors

  • The entire stack, including Docling, can run offline using locally hosted models (e.g., Ollama), which the speaker says supports air-gapped deployments.
  • Separately, OAuth-based cloud connectors let users sync documents directly from Google Drive, SharePoint, or OneDrive rather than manually uploading them.
  • The project is described as open source end to end, with a Next.js front end and a Python backend.

“the entirety of open rag can be run offline using locally hosted models. Docling itself can be run offline so it can run in air gap situations.”
