If you only read one thing

  • The stated goal is driving down the cost of interacting with insurance while improving patient experience, not chasing agentic technology for its own sake (c1).
  • Onlay grounds its claims agents in X12, the existing insurance transaction standard (eligibility is a 270, imaging is a 275), because it's a public, strict schema instead of one an LLM would invent (c3, c7).
  • Insurance-company data has no ground truth — the phone system, browser, and X12 feed can all independently agree on the wrong answer — so every record is treated as semi-correct until downstream evidence updates it, while persistent memory is watched carefully so it doesn't quietly bias repeat users into doing the same thing every day (c4, c5, c6).

Why agentic execution in healthcare is harder than it looks

  • He uses check deposit as an analogy: solving handwritten digit recognition looks like it solves check deposit, but in practice there are many more pieces (character recognition across a check, matching account infrastructure, verifying the target account) before the transaction actually works.
  • He extends the same warning to model upgrades, swapping in a newer, more capable model isn't automatically better for a given system, since it may score better on general evals while performing worse on the specific situations the system was designed around, requiring evals and validation to be redone.

“you have to identify all sorts of characters in the check. You have to make sure it matches up with all these other pieces of the infrastructure”

03X12 as the harness that grounds the agent

X12 as the harness that grounds the agent

  • Vasant defines the agentic execution layer broadly as all the tools, permissions, checks, handoffs, and evals surrounding the model's reasoning, and argues LLMs work best when confined to a structure with clear, limited values they can predict.
  • In healthcare claims, that structure is X12, the existing, public transaction standard between providers and insurers, an eligibility check is a 270, an imaging-related transaction is a 275, which gives agents a known schema instead of one an LLM would invent on its own.

“x12 is exactly this so it provides this underlying structure this contract between what you're trying to communicate and the insurance company”

04Memory helps and introduces bias

Memory helps and introduces bias

  • Onlay stores memory in a database rather than locally (unlike consumer coding agents) to keep logical separation in an enterprise healthcare setting, and uses partner-level and user-level memory so the system can infer intent from short phrases based on a user's typical behavior.
  • But persistent memory across chats and days introduces bias risk, steering a user toward repeating what they did yesterday even when that's not what they want, so users need a way to break out of it.
  • Long agentic chains compound this risk: each additional step in a 50-step claim workflow is another chance to introduce and propagate an error, and can also become slow and expensive.

“as you introduce memory, you also persistent memory across chats, across days, you also introduce bias”

said at 12:01

“each time it each step is an opportunity to introduce an error and you can have problems”

said at 10:27
05Insurance data has no ground truth
Slide at 15:20 · click any slide to enlarge · 7 more from this section below

Insurance data has no ground truth

  • Vasant warns that data coming from an insurance company may originate from different internal teams or even different contracted companies, and that there's no ground truth, the phone system, browser portal, and X12 feed can all independently agree that a patient is covered and still turn out to be wrong when a claim is later denied.
  • Onlay's response is to treat any X12 record, regardless of its source, as its own internal 'semi-correct' version that's correct until downstream evidence proves otherwise, and to deploy models in a cost-conscious, skeptical way rather than defaulting to the most capable available model.

“we have to understand that there's no ground truth. They also within all of these systems, they can they can all actually agree on the wrong information”

said at 15:47

“you can boil all those transactions down to your own internal semi-correct X12. Correct until downstream evidence proves it otherwise”

“language models, small tiny models in a very skeptical conservative way. So, being AI filled is great, but you should also be very AI skeptical”
