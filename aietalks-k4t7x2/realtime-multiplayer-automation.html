If you only read one thing

  • GitHub Next's Agentic Workflows are markdown-defined automations with YAML front-matter guardrails (read/write permissions, allowed network destinations, "safe outputs") because prompting an agent not to do something isn't a real guardrail (c2, c3, c8).
  • These deterministic guardrails already enable things heuristics couldn't: the Home Assistant open-source project built an agent that walks a Python stack trace and closes issues that trace to third-party code; GitHub predicts background automation becomes a bigger category than interactive AI (c4, c5).
  • A 100-developer, thousands-of-hours study found hands-on-keyboard typing is only about 5% of an engineer's job, which is the stated rationale for Ace, a multiplayer chat + shared plan-doc tool for the other 95% (c6, c7).

01Why individual understanding breaks down at team speed

Why individual understanding breaks down at team speed

  • The speaker argues personal understanding was never sufficient for shipping code inside a team; alignment at the team level historically only had to happen at the end of a slower process.
  • As AI accelerates that process, small misalignments can snowball into wasted work, and wasted work now costs both time and tokens.

“my personal understanding was never sufficient for shipping code inside a team, right? Our understanding at an us level can only happen at the end of the process.”

02Agentic Workflows: markdown automations with deterministic guardrails
Slide at 05:20 · click any slide to enlarge · 8 more from this section below

Agentic Workflows: markdown automations with deterministic guardrails

  • Agentic Workflows are described as markdown documents (the source of truth, compiled into a GitHub Actions YAML artifact) that define scheduled or triggered automations, such as an always-on dependency upgrader built from a short natural-language prompt.
  • Because prompting an agent not to do something isn't an enforceable guardrail against prompt injection, permissions (what it can read/write), allowed network destinations, and "safe outputs" (e.g., limiting it to a single PR, or explicitly allowing it to do nothing) are specified deterministically in YAML front matter outside the agent's control.

“you're effectively letting the fox loose in the henhouse. It's not actually a guard rail.”

said at 07:42

“Never trust agents with secrets. If an agent can know a secret, that secret, you need to treat it as if it's already been compromised.”

“what I really want is a kind of super Dependabot that's always there, automatically looking in the background at my dependencies and figuring out how to upgrade me, including the code changes, the breaking changes”

03What became possible: the Home Assistant triager
Slide at 12:20 · click any slide to enlarge · 5 more from this section below

What became possible: the Home Assistant triager

  • Given these guardrails, GitHub says the open-source Home Assistant project built an Agentic Workflow that walks the Python stack trace of every submitted issue to determine whether the bug is first-party or third-party, and closes it automatically if it isn't their issue, something not possible with heuristics before AI.
  • GitHub predicts background automation of this kind will become a bigger category than interactive AI use.

“closes the issue if it's not their issue, right? That's something that was not possible before AI, not possible with heuristics, uh but is possible now.”

said at 12:21

“we actually believe that this is going to be a bigger category than interactive AI because automations that run in the background while you sleep, that's the ballgame”

said at 12:52
04Ace: multiplayer chat and shared plan docs
Slide at 13:40 · click any slide to enlarge · 8 more from this section below

Ace: multiplayer chat and shared plan docs

  • Ace is a Slack-like multiplayer interface where each session runs as a cloud micro-VM checked out to a branch, letting teammates discuss and direct an agent in the same shared surface rather than in individual, unshared chat sessions.
  • Its stated purpose is surfacing facts that aren't in the code itself (political considerations, team preferences) since agents can already infer anything that is in the code; plans are edited collaboratively as shared markdown documents rather than files only the requester can see.

“What this is good for is surfacing all the facts that are not in code. Anything that's in code, any fact that's in code, the agents can figure out by reading the code.”

said at 13:52
05The 5% problem
Slide at 20:00 · click any slide to enlarge · 3 more from this section below

The 5% problem

  • A longitudinal study of 100 developers over thousands of hours found hands-on-keyboard typing accounts for only about 5% of an engineer's job; the speaker frames Ace and Agentic Workflows as attempts to help with the other 95%, i.e. discovering system state and aligning with teammates, rather than just producing keystrokes faster.

“it's only about 5% of the job. Like, this was a longitudinal study conducted on like 100 developers over thousands of hours.”

said at 19:40
