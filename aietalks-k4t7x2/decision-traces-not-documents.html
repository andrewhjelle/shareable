Why your agents need decision traces, not just documents

SpeakerZach Blumenfeld · Neo4j Watchyoutu.be/B9h9ovW5H9U
MemoryContext engineeringAgentic engineering

If you only read one thing

  • A context graph adds decision traces and precedents on top of a standard knowledge base so an agent can justify an accept/reject decision, not just answer questions (c1, c2).
  • Graph embeddings let similar past decision traces be found by vector similarity, combined with semantic and structural hybrid search over precedents (c4, c5).
  • A new open-source CLI (create context graph) scaffolds a full-stack app with seeded data across six-plus agent frameworks and 22 built-in domains, with GitHub/Notion/Jira/Slack connectors (c6, c7, c8).
01What a context graph adds beyond a knowledge base

A knowledge base helps an agent answer questions correctly, but a context graph adds the information needed to make and justify better decisions. In the financial-analyst demo, an agent with only customer info, transactions, and policies could assign a risk score and recommend review; adding past decision traces and precedents let it answer accept-or-reject and explain why.

“the information required to not only answer questions correctly, but make better decisions”

02Entities, events, and context in the graph schema

The context-graph data model organizes information into entities (things that exist), events such as decisions, transactions, and approvals, and context such as policies and reasoning recorded from past human decisions.

“there'll be uh events, so decisions, transactions, approvals, things like that”

▶ watch at 03:36
03Finding precedents with graph embeddings and hybrid search

Where text embeddings encode words, a graph embedding encodes connected graph nodes -- including past decision traces -- into vectors, so similar decision traces can be surfaced by vector similarity, something hard to extract from plain documents. The demo layers this with hybrid search over precedents that considers both semantic and structural similarity.

“similar decision traces are now going to be able to be looked up by vector similarity”

▶ watch at 07:55

“we did a special of hybrid search, especially around those precedents, both on semantic similarity and structural similarity inside of the graph”

04A scaffolding CLI for context-graph apps

A new open-source command-line tool, comparable in spirit to create-react-app, scaffolds a full-stack context-graph application -- back end, front end, and seeded demo data -- for a chosen domain and agent framework. It supports Pydantic AI, OpenAI, LangGraph, Crew, Strands, and Google ADK, ships 22 built-in domains plus custom domain/ontology generation, and includes connectors to import data from tools like GitHub, Notion, Jira, and Slack.

05The memory package underneath it

The stack is built on Neo4j's agent memory package, which provides the three memory types a context graph needs: short-term (conversation/session context), long-term (extracted, resolved entities), and reasoning (the decision traces themselves). Turning raw text into the graph runs through staged extraction -- spaCy, then GLiNER, then an LLM fallback -- followed by a separate merging, deduplication, and enrichment step.

“a short-term memory, a long-term memory and reasoning”
