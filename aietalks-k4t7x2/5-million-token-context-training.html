Road to 5 Million Tokens: Breaking Barriers in Long Context Training

SpeakerMax Ryabinin · Together AI Watchyoutu.be/TUnPNY4E2fw
Infra & servingContext engineeringPost-training

If you only read one thing

  • Standard transformers hit two scaling bottlenecks with longer context: quadratic attention computation and linearly growing memory that becomes hard to manage without specific techniques.
  • Stacking FSDP, DeepSpeed Ulysses context parallelism, activation checkpointing, and CPU offload of transformer-block inputs takes an 8x H100 node from unable to fit model parameters up to a working 3M-token context.
  • Together AI's own 'Untitled Ulysses' technique, which reuses smaller attention buffers across chunked head groups instead of allocating one huge buffer, pushes this further to 5M tokens while matching the most memory-optimized existing implementations at 8B and 32B scale.
01Why long context training matters and where it breaks

The speaker cites two drivers of interest in long-context training: agentic applications wanting to use as much context as possible, and video generation needing temporal consistency across many frames/tokens. Extending a standard transformer's context runs into two bottlenecks: quadratic computation from pairwise attention interactions across the sequence, and memory that grows linearly with context length in a way that's still difficult to manage without specific optimization techniques.

“if you are taking a standard transformer-based language model and trying to extend its context, you can run into two bottlenecks”

“as you continue scaling your context, your memory keeps growing linearly, which is not as bad, but still pretty difficult to deal with”

02Stacking existing memory techniques

Starting from a Llama-3B-class model targeting 3M tokens on an 8x H100 node, the model parameters alone don't fit until fully sharded data parallelism (FSDP) chunks them across GPUs, but attention activations still overflow memory. Applying DeepSpeed Ulysses context parallelism, which computes each attention head on a different GPU across the whole sequence rather than the whole attention on every GPU, drops memory utilization by roughly 8x. Activation checkpointing (recomputing activations at the backward pass instead of storing them) cuts activation memory by a further factor of eight, and offloading unneeded transformer-block inputs to CPU (a technique the team credits to Unsloth) further expands the workable context window.

03Together's own contribution: chunked-head reuse

Together's own optimization, described as a deeper extension of Ulysses and referred to in the talk as 'Untitled Ulysses,' found that computing even one set of attention heads at a time already saturates a GPU's compute within one iteration, so heads assigned to a GPU can be processed in chunks that reuse the same buffer across iterations instead of allocating one large buffer up front, saving activation memory without hurting throughput at small scales.

“you compute attention over them, you store the partial result, then you follow up with the next stage, which can reuse all the buffers you've allocated at the previous stage”

▶ watch at 10:53
04Results and takeaway

The combined technique stack matches the most memory-optimized existing transformer training implementations at both 8B and 32B parameter scale while scaling further, reaching 5 million tokens and sometimes outperforming at shorter context lengths. The speaker's overall takeaway is that long-context training bottlenecks can appear in unexpected places, and profiling tools like the PyTorch profiler are valuable for finding them; the full method and further results are covered in the team's public paper.
