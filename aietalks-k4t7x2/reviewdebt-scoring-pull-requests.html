takeCoding agentsEvals & benchmarksAgentic engineering

Gives a deterministic (non-LLM-judge) scoring framework for whether a pull request is safe to merge with light review, built from five signal families rather than authorship alone

If you only read one thing

  • Industry data shows commits up 25% year over year while review comments dropped 27% in the same period, and median PR review time is up 441.5% on teams adopting AI coding agents.
  • Review debt is the accumulating gap between code an agent produced and code humans have actually reviewed, trusted, and understood, scored via five deterministic signal families rather than an LLM judge.
  • In a scan of 524 PRs across three public repos, AI-authorship rate stayed flat at 5-20% while review burden climbed, and complexity (large migrations, SDK rewrites, multi-team refactors) drove the high-burden cases, not authorship itself.

The talk argues rising PR throughput is a vanity metric masking a real drop in review coverage, and that a deterministic scoring layer, not an LLM judge, is what lets a team tell a well-shaped PR from a sprawling one (ours).

Throughput metrics look good but are vanity metrics

  • Faros AI's April 2026 Acceleration Whiplash benchmark (22,000 developers, 4,000 teams) found PRs per developer up 16% and median PR size up 63% (44 to 72 lines).
  • The speaker frames these as vanity metrics: PR count rises when one PR splits into seven, larger median size is bloat not benefit, and faster cycle time can mean reviewers are pushing back less, not shipping more safely.

Defining review debt and scoring it deterministically

  • Review debt is defined as the accumulating gap between code an agent produced and code humans have reviewed, trusted, and understood; it compounds like financial debt but the interest is paid in human attention.
  • The framework scores every PR using five deterministic signal families (size/coupling, test evidence gap, directory/ownership spread, AI authorship indicators, evidence/rationale gaps) rather than an LLM-as-judge, because LLM scores drift with model changes and aren't defensible in a leadership review.

04Cross-repo scan: volume drives burden, not authorship
Slide at 18:30 · click any slide to enlarge · 5 more from this section below

Cross-repo scan: volume drives burden, not authorship

  • A scan of 524 real PRs across three public repositories over 27-90 day windows found 228 cumulative senior-reviewer hours.
  • AI-authorship indicators fired on a flat 5-20% of PRs weekly across all three repos, but review burden varied heavily by repo (186 senior-reviewer hours in 27 days on one repo versus 43 on another), and the PRs landing in the highest-burden band were driven by structural complexity (large migrations, SDK rewrites, multi-team refactors), not by AI authorship.

“the scanner saw 524 real pull request in three public repos, 228 senior reviewer hours cumulative across three public repos that were scanned over 27 to 90-day windows”

Commentary (ours)

The framework's core move -- separating an AI-authorship flag from the actual burden signals -- is the part worth stealing even without adopting the tool, since it blocks the reflexive 'just review AI PRs harder' policy that treats a well-shaped agent PR the same as a sprawling one (ours).
