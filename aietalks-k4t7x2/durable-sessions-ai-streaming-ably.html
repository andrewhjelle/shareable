Why Your AI UX Is Broken (and It's Not the Model's Fault)

SpeakerMike Christensen · Ably Watchyoutu.be/YNJvm7t3yq8
Product & UXInfra & servingAgentic engineering

If you only read one thing

  • Direct HTTP/SSE streaming ties an agent's response to a single client connection, so it can't survive disconnects, follow a user across tabs/devices, or support cancel without also breaking resume (per Vercel's AI SDK docs, which state abort is incompatible with resume).
  • The pattern the speaker says the best AI products converge on is a "durable session" -- a shared, persistent resource between agents and clients, built here on Ably channels -- so any client can reconnect, replay, or steer the agent, and multiple sub-agents can write updates directly.
  • Swapping SSE for a bidirectional transport like WebSockets does not by itself fix multi-device visibility or multi-agent orchestration; clients still need a persistent connection to the shared session rather than to the agent's single request.

02Three capabilities separate a fragile demo from a production AI product

The talk frames the best AI products as investing in three foundational capabilities: resilient delivery (streams that survive disconnects), continuity across surfaces (a session that follows the user between devices), and live control (letting a client communicate with an agent while it is still working, as with Claude Code).

“companies shipping the best AI experiences really invest in three foundational capabilities”

▶ watch at 03:07
03Direct HTTP/SSE streaming couples everything to one connection

With the default direct-streaming pattern, the health of the response stream is tied to the health of the single client connection that opened it, so a dropped connection loses the stream. Because SSE is a one-way pipe from server to client, there is no upstream channel for a client to signal cancellation, so on connection close the agent cannot tell whether to buffer events for a later resume or treat it as a cancellation -- Vercel's AI SDK docs are cited as stating abort is incompatible with resume for this reason.

“the health of that stream is essentially tied to the health of that end client's connection”

04Durable sessions decouple the agent layer from the client layer

The proposed fix is a shared, persistent, stateful resource sitting between agents and clients, which the speaker calls a durable session. Built on Ably channels, this resource is independently addressable and persistent, meaning messages on the channel outlive the lifecycle of any individual connection, device, or agent, which is what allows a client to disconnect and later resume exactly where it left off.

“what this is is a shared resource that sits between the agent layer and the client layer, and it's a persistent and stateful medium through which agents and clients can interact”

▶ watch at 05:12

“the messages on the channel outlive the life cycle of any individual connection, any individual device, any individual agent”

▶ watch at 13:26
05Bidirectional transport alone doesn't fix multi-device or multi-agent visibility

Replacing SSE with a bidirectional transport like WebSockets solves cancel/resume but introduces new problems once a user interacts from multiple devices or tabs, since a second tab has no visibility into or upstream path to an in-progress response. A related problem appears in multi-agent orchestration: forcing a single orchestrator agent to both delegate subtasks and proxy granular progress updates from sub-agents back to the client adds architectural complexity the orchestrator shouldn't need to own.

“a bidirectional transport doesn't solve all of our problems automatically, and these problems arise when you try to interact from multiple devices”

▶ watch at 09:16

“There's a dual-purpose role of both orchestrating the task and delegating tasks, and also proxying back these sort of granular updates from these sub-agents”

▶ watch at 11:50

Commentary (ours)

The core move here is treating the AI response stream as a pub/sub topic rather than a request/response artifact -- which is a fairly standard distributed-systems pattern applied to a new problem. Worth checking whether teams without Ably's infra reach for a lighter-weight version (e.g. a Redis-backed channel) before adopting a vendor SDK for this (ours).
