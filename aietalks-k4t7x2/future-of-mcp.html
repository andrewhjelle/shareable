If you only read one thing

  • MCP has reached about 110 million monthly downloads, roughly double the growth rate React took to hit the same volume, pulled by frameworks like OpenAI's Agent SDK, Google's ADK, and LangChain, not just Anthropic's own clients.
  • For 2026, Soria Parra recommends a three-part connectivity stack per use case -- skills for reusable domain knowledge, MCP for rich semantics/auth/UI, and CLI or computer use for local sandboxed execution -- plus two client-side techniques: progressive tool discovery (defer loading tools until needed) and programmatic tool calling (have the model write code to compose tool calls instead of orchestrating them turn by turn).

022026 shifts from coding agents to general knowledge-worker agents

2026 shifts from coding agents to general knowledge-worker agents

  • Soria Parra frames 2025 as the year of coding agents, which he calls the easiest case for an agent because they are local, verifiable, and backed by a compiler.
  • He argues 2026 is about general agents doing knowledge-worker tasks that instead need connectivity across several SaaS applications and a shared drive, and recommends considering three distinct connectivity options when building an agent: skills, MCP, and CLI/computer use, each suited to different situations.

“there are three major things that you want to consider building an agent in 2026. It's skills, MCP, and of course, like CLI or computer use depending on your use case”

03Two client-side techniques to control context and latency

Two client-side techniques to control context and latency

  • Soria Parra recommends progressive discovery -- using tool search (available in the Anthropic API and other APIs) to defer loading tool definitions until the model actually needs them, rather than dumping every tool into the context window up front.
  • He also recommends programmatic tool calling (also called code mode): instead of having the model call one tool, read the result, then call another tool in sequence, give the model a code execution environment and let it write a script that composes multiple tool calls together, which MCP's structured output feature can support with type information.

“you should start using this progressive discovery pattern, which is to say, use something like tool search to defer the loading of the tools, and start loading the tools when the model needs it”

said at 08:45

“You don't want the model to go call a tool, take the result, then go and talk, call another tool, take the result, call another tool”

04A named anti-pattern for MCP server authors

A named anti-pattern for MCP server authors

  • Soria Parra criticizes the common practice of converting a REST API one-to-one into an MCP server, calling it cringe and something that results in bad outcomes.
  • He recommends designing for how an agent (or a human) would actually want to interact with a system, rather than mechanically wrapping existing endpoints.

“Every time I see someone building another rest to MCP server a conversion tool, I'm it's a bit cringe because I think it's just it just results in horrible things”

said at 12:20
05Protocol roadmap: transport, skills, and enterprise auth

Protocol roadmap: transport, skills, and enterprise auth

  • Soria Parra names three protocol-level items coming down the line: a stateless transport protocol developed with Google to fix streamable HTTP, which he says is hard to scale for large hyperscalers; shipping skills over MCP so a server author can ship usage knowledge alongside a large tool set without relying on separate plugin mechanisms; and cross-app access, letting users log in once with a company identity provider (Google or Okta) and use MCP servers without re-authenticating per server.
