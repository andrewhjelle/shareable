01Identity-aware proxy as the security model
Slide at 02:10 · click any slide to enlarge · 7 more from this section below

Identity-aware proxy as the security model

  • The speaker, a developer advocate at Pomerium (maker of an open-source identity-aware proxy, comparable to GCP's IAP), describes an identity-aware proxy as combining an identity provider, a policy engine, and a reverse proxy.
  • Even after putting OpenClaw behind this kind of proxy, the software still required a separate web-socket auth token and manual device pairing, which he found redundant.

“It's called an identity-aware proxy, something that came out of Google. Uh essentially, you've got an identity provider, a policy engine, and a reverse proxy”

02The trusted proxy auth mode contribution
Slide at 04:10 · click any slide to enlarge · 6 more from this section below

The trusted proxy auth mode contribution

  • He proposed and built a new 'trusted proxy' auth mode for OpenClaw (his first contribution to the project, merged after community support from a Caddy user and the maintainer Peter).
  • The config adds a trusted-proxies IP list and a trusted-proxy section specifying a user header (a JWT in his setup); prior to this, even proxy-secured OpenClaw still required pasting an auth token into the UI for the web-socket connection, which also leaked into the query string.

“there's trusted proxies. And this is essentially the proxy that is gating access to the control plane, the uh the gateway”

said at 04:13

“that just meant no more token for web socket connections and no longer needed to pair devices”

Commentary (ours)

The core lesson generalizes past OpenClaw: any agent control plane fronted by a proxy that already authenticates the user is carrying a second, weaker auth layer unless it explicitly trusts the proxy -- worth auditing other self-hosted agent tools for the same redundant-token pattern (ours).
