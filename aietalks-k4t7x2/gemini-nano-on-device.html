Gemini Nano on device

SpeakerFlorina Muntenescu & Oli Gaymond · Google DeepMind Watchyoutu.be/owH1f0N-keY

If you only read one thing

  • Gemini Nano shares its architecture with Gemma 4 but is optimized for Android hardware, and is delivered once system-wide via the AI Core service so all apps share one model.
  • Gemini Nano is currently only available on flagship-class devices like Pixel 9/10 and comparable OEM hardware; models run 1GB up to 3-4GB.
  • Battery impact exists but is manageable for typical interactive use (10-20 prompts/day); heavier batch workloads are pushed to background/overnight processing.
01What Gemini Nano is

Gemini Nano is Google's most efficient on-device model, sharing its architecture with Gemma 4 but optimized specifically for Android hardware. It's delivered through the AI Core system service, so a device has exactly one copy of the model and all apps share it through that service rather than each app bundling its own.

“this is our most efficient models model for on device tasks and it's using the same architecture as Gemma 4 that you probably have heard about”

▶ watch at 03:07

“with this it means that you only have one model on the device and then all of the apps are using that same model through this AI Core system”

▶ watch at 03:38
02Privacy and access path

On-device inference means input and output data isn't stored on the device at all and requests run in isolation from other apps' requests, which the speakers position as a reason to prefer on-device for sensitive data or offline scenarios. Developers access Gemini Nano through the ML Kit GenAI APIs, most notably the general-purpose prompt API (text and image input, text output).

“then the input and the output data is not stored on device at all. So it's all as private and secure as possible”

▶ watch at 04:40
03Device and model-size limits

Gemini Nano currently requires flagship-class hardware -- Pixel 9 and Pixel 10-generation devices plus comparable OEM devices -- because the shipped models run from roughly 1GB up to 3-4GB total, too large for most app developers to bundle themselves. Firebase AI Logic provides a hybrid fallback: run on-device when Gemini Nano is available, otherwise fall back to cloud models (Gemini Flash, Pro, Flash-Lite via Vertex AI or the Gemini developer API).

“The Gemini Nano models are only available on like Pixel 9, Pixel 10 kind of like that generation of devices not just on Pixel devices but also on other OEMs”

▶ watch at 05:41

“The new ones, the GenAI APIs, those ones require currently fairly flagship devices from the last couple of years”

▶ watch at 17:54
04Battery behavior in practice

Running Gemini Nano continuously does noticeably drain the battery, but the speakers report that typical interactive use of 10-20 prompts a day isn't a meaningful battery concern; heavier batch processing is instead pushed to background execution, often overnight while charging, with AI Core handling queuing and prioritization across apps.

“Yes, there is battery impact. If you are running this non-stop you are going to run down the battery fairly quickly”

▶ watch at 08:45

“Users maybe use it 10, 20 times a day. That sort of usage is really not you know concerning for battery life”

▶ watch at 09:16
05Building your own app vs. using Google's assistant

The speakers distinguish between building your own app against the on-device model APIs versus interacting with Google's own Gemini/Assistant app, which is a separate product; a developer's own app talking to the model directly doesn't route through the Gemini app at all.

“if you're building your own app, you wouldn't interact with the Gemini app. That's a completely different app, but rather you would interact with the model itself”

▶ watch at 13:57

Commentary (ours)

The single-shared-model-via-AI-Core design trades per-app flexibility for a system-level cost/battery amortization argument -- worth watching whether third-party OEMs converge on the same service pattern or fragment it (ours).
