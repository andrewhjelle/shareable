Prompt to Pipeline: Building with Google's Gen Media Stack

SpeakerPaige & Guillaume · Google DeepMind Watchyoutu.be/ns9f1fjLD7Y
Generative mediaProduct & UXLocal models

If you only read one thing

  • AI Studio's 'get code' button turns any working prompt/config into ready-to-use Python/TypeScript, and Gemini 3.1 Flash Lite costs about 25 cents per million tokens analyzed, roughly an order of magnitude cheaper than Gemini 3.1 Pro.
  • The book-illustration pipeline chains Nano Banana (images), VO (video), Lyria 3 (music) and TTS through a shared chat history so each model stays consistent with prior outputs; passing explicit reference images per character was needed to fix consistency errors that appeared without them.
  • Gemma 4 ships as four sizes (E2B/E4B effective models for phones/Raspberry Pi, a 26B MoE with 4B activated, and a 31B dense flagship) and was shown running an agentic swarm (one orchestrator plus 10 sub-agents generating SVGs) entirely on a local MacBook via an OpenAI-compatible endpoint.
01AI Studio: from prompt to working code

Paige demonstrated AI Studio's playground and 'build' features, showing Gemini 3.1 Flash Lite analyzing an hour-long YouTube video (uploaded via a plus-sign file picker, sampled at roughly one frame per second) to produce a timestamped table, and using code execution to draw bounding boxes around objects in an image via a sandboxed Python environment. She emphasized that whatever works in the AI Studio UI can be exported directly to app code with the 'get code' button, and gave pricing for Gemini 3.1 Flash Lite.

“the TLDDR is that if you can get it working in AI Studio, you can get it working as part of your app. All you have to do is click the get code button”

02Gemini's native multimodality and why the model lineup keeps splitting

Paige framed Gemini as differentiated by being natively multimodal on both input and output, understanding and generating text, code, images, and audio. In an opening discussion, she also argued that infrastructure people build to work around model limitations (vector databases for small context windows, fine-tuned models for specific languages, agent frameworks, MCP servers) tends to get absorbed into the model over time, citing that most people have already moved from building MCP servers to writing skills (markdown files) instead.

“everybody sprinting towards things like building MCP servers whereas now mostly people have kind of moved away from MCP servers and are adopting skills which are just fancy markdown files”

03Chaining Nano Banana, VO, and Lyria for an illustrated book pipeline

Guillaume built a live workshop pipeline that downloads an out-of-copyright book (The Wind in the Willows), uses Gemini with structured outputs to generate per-chapter and per-character image prompts, and calls Nano Banana to illustrate them, keeping a running chat history so the model retains style and character consistency. He noted that using only prior generated images as loose context produced inconsistent characters (e.g. the toad rendered differently across chapters) until he switched to explicitly passing each character's reference image alongside the prompt for that panel. He also demonstrated VO3.1 Light for video generation and Lyria 3 for music, and a text-to-speech trick for generating multiple distinct character voices from only two configured voice IDs by rewriting dialogue as a labeled play script.

“for each image that I'm going to create also give the reference images of what the character should be looking like. So that's it only has that those images in in its context instead of having all of the possible images that we did before”

04Gemma 4 running locally, including an on-device agent swarm

Ian Valentine introduced Gemma 4 (released the Thursday before the talk) as a four-model family: E2B/E4B 'effective' models for phones and low-end hardware like Raspberry Pi, a 26B mixture-of-experts model with 4B activated parameters, and a 31B dense flagship, with the two larger models designed to run on laptops or single-GPU clouds. He said the models perform comparably to models roughly 10x larger in parameter count. As a live demo, he served the 26B model locally via LM Studio on an OpenAI-compatible endpoint and ran one orchestrator model plus 10 local sub-agents each generating an SVG in parallel, then used the same local endpoint inside the open code coding harness to implement a game from a spec, debugging syntax errors interactively.

“it's a family of four models. So, we have what we call the effective models, the E2B and the E4B models. And these are models designed to run like on mobile phones, Raspberry Pies, Jets, and Nanos, kind of like very small low-end hardware”
