Bending a Public MCP Server Without Breaking It

SpeakerNimrod Hauser · Baz Watchyoutu.be/U00AOI1eJUE · 40 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Quotes are verbatim from the talk transcript with the time they were said.
patternMCP & protocolsAgentic engineeringWeb automation

Gives a concrete five-step pattern (curate tools, wrap descriptions, add deterministic guardrails, compose new tools from existing ones, or bypass the agent entirely for some steps) for adapting a third-party MCP server like Playwright's...

If you only read one thing

  • Playwright's public MCP server ships 21 generic, shallow-described tools; run vanilla on a spec-reviewer agent, it hallucinated a URL and failed to verify the requirement (c1, c8).
  • Recommends curating down to only the tools actually needed (21 to 16 in this case) and wrapping the remaining ones with tailored descriptions and sequencing hints, such as preferring the accessibility snapshot tool before other browser actions (c2, c3).
  • For sensitive actions (where screenshots get saved), add deterministic path validation that returns an agent-readable error instead of failing the whole run, and pull inherently non-agentic steps like login out of the agentic loop entirely (c4, c5, c7).

01Third-party MCP tools ship generic and shallow

Third-party MCP tools ship generic and shallow

  • Using Buzz's spec-reviewer agent (which reads a ticket and design, then uses Playwright's MCP server to check whether an implementation matches) as a running example, Playwright's server is shown providing 21 tools with shallow, catch-all descriptions like 'close the page,' since the maintainers can't know every downstream use case.
  • Run out of the box (V0), the agent hallucinated a URL and returned a failed verdict with a broken screenshot.

02Curate: remove tools the agent doesn't need

Curate: remove tools the agent doesn't need

  • The first improvement (V1) filters the tool list down to only what the use case requires, dropping from 21 to 16 tools by excluding actions like browser resizing or code execution that the spec reviewer never needs, reducing what the agent has to choose from.

“instead of 21 tools, which we used to have, I expect to see less. And so, we have 16.”

said at 17:14
03Wrap: rewrite descriptions and add sequencing hints

Wrap: rewrite descriptions and add sequencing hints

  • The second improvement (V2) wraps each remaining tool with a custom, use-case-specific description drawn from experience, including sequencing guidance like 'call the accessibility snapshot tool before calling hover or click' so the agent gets a text understanding of the page before acting.

“This tool we found to be especially helpful. It's uh it has kind of a misleading name. It's called the snapshot tool.”

said at 19:17
04Guardrail and compose: deterministic checks and agent-facing errors

Guardrail and compose: deterministic checks and agent-facing errors

  • The third improvement (V3) adds a deterministic path-validation check around the screenshot tool so the agent can't save images outside an approved folder; a failed check raises an agent-facing error message rather than crashing the run, so the agent can retry with a corrected path.
  • A fourth improvement (V4) composes a new 'evidence screenshot' tool on top of the existing screenshot tool with its own description and file-naming convention (embedding the ticket number).

“there is a possibility that the agents will go rogue and just store images in other places”

“we might raise an excep- exception, we don't return an exception. We don't want the whole agentic process to fail.”

said at 27:36

“we felt that maybe having a separate tool for that was uh was in order”

said at 29:11
05Bypass the agent for steps that don't need it

Bypass the agent for steps that don't need it

  • Login is treated as a deterministic function called before the agent starts, using JWT tokens injected into browser local storage, rather than letting the agent attempt the login flow itself, since every run of the spec reviewer always needs to log in and letting the agent handle it produced subpar results.

“There is no agentic flow for spec reviewer that does not begin with a login.”

said at 34:53
