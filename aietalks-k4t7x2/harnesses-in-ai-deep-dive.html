01What a harness is, and why it matters
Slide at 03:10 · click any slide to enlarge · 3 more from this section below

What a harness is, and why it matters

  • The speaker defines an agent harness as everything around the model that gives it grounding in reality, distinct from the machine-learning-world meaning of 'harness' as a test suite.
  • He argues the reason to build one is reliability: since most engineers rent a black-box frontier model with a limited context window, the harness is what makes the resulting agent behave predictably regardless of which model is behind it.

“The agent harness is everything around the model that gives it grounding in reality.”

“So why harness? Because the name of the game with harness is reliability.”

02Anatomy of a harness
Slide at 04:50 · click any slide to enlarge · 6 more from this section below

Anatomy of a harness

  • He breaks a harness into recurring parts: a tool registry (file read/write, bash execution), the model itself, primitives for managing/compacting context, guardrails (e.g. max steps), the agent loop, and a verify step.
  • Coding agents like Claude Code, Cursor, and Codex are cited as examples of harnessed agents built from these same parts.

“They have primitives for managing context. Almost every harnessed agent runtime today will compact its own context”

03Live demo: an agent lies until the harness catches it
Slide at 09:20 · click any slide to enlarge · 8 more from this section below

Live demo: an agent lies until the harness catches it

  • Building a bare-bones browser-use agent (Playwright-driven, GPT-3.5 Turbo, task: upvote the first Hacker News post) without changing the prompt, the agent hits an unhandled login screen, panics, and reports success anyway.
  • Adding a deterministic verify step that inspects the tool-call trace stops the false success report; adding a harness-level login handler (not an agent tool call) that injects credentials programmatically from outside the LLM's control lets the agent actually complete the task.

“So we we hit a login screen and then it kind of panicked and crashed. But look, it it lies. You see this?”

said at 09:17

“we fill in credentials and submit the button programmatically from the harness, not from the agent, deterministically and securely because this file has access to any secrets I want it to”

said at 16:05
04Where this is headed
Slide at 18:10 · click any slide to enlarge · 8 more from this section below

Where this is headed

  • The speaker frames 2025 as the year of agents and predicts 2026 as the year of harnesses, with 2027 potentially bringing dynamic, self-generated, on-the-fly harnesses an agent builds for itself before doing a task.
  • He points to IBM's open-source 'open rag' project as a current example of harness engineering providing enterprise-level security for RAG over siloed internal data.
