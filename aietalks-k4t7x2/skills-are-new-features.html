Skills are new features: Building Skill-Centric Harness

This talk gives a concrete architecture and set of failure modes for teams building their own agent harness with skill support outside of Claude Code/Codex, including what breaks when a skill library scales past a handful of skills or th...

If you only read one thing

  • In an agent-first product, skills replace screens/buttons/dropdowns as the feature unit: prompts define who the agent is, tools define what it connects to, and skills define how a task gets done.
  • Skill descriptions function as routing signals and must be written for user intent, and skills are version-pinned contracts to a specific model, so swapping models can silently break behavior even with zero skill changes, which is why skills need evals rerun on every model upgrade.
  • At enterprise scale, skill library governance (admission, ownership, boundaries, lifecycle, coherence) becomes non-negotiable, and the engineer's role shifts from shipping features to shipping the harness that runs them.

Skills replace screens as the feature unit

  • Miraje frames agent-first products through a who/what/how split: prompts define who the agent is, tools define what it can connect to, and skills define how a task gets done, replacing the buttons and dropdowns of a traditional UI.
  • Because skills can be authored by anyone with product knowledge, not just engineers, the engineer's role shifts from shipping features to shipping the harness that runs them.

02Minimum viable skill harness
Slide at 05:50 · click any slide to enlarge · 8 more from this section below

Minimum viable skill harness

  • A bare-minimum harness that supports skills needs only three components: a skill registry, a system prompt, and a basic file-read tool, plus bash or a sandbox if skills run scripts.
  • The registry's name/description/path gets concatenated into the system prompt using progressive disclosure, so the agent only loads the full skill body for skills it actually selects.

“You only need these three things like skill registry, a system prompt, and a basic file read tool.”

Descriptions are routing signals

  • Skill descriptions determine which skill the agent picks, so they must be written around the user's request rather than describing the skill's internals, and kept distinct so the agent doesn't confuse similar skills.

“that's why descriptions are called routing signals. And it's very important to keep your descriptions aligned to the user request and not about the skill itself.”

said at 09:23
04Skills are model-versioned contracts
Slide at 12:10 · click any slide to enlarge · 6 more from this section below

Skills are model-versioned contracts

  • After a model upgrade with zero changes to the skill files, FactSet's agent stopped obeying skills; the cause was that the new model attended more to the beginning of a skill and missed a critical instruction placed at the end.
  • Miraje's conclusion: skills are not documentation but contracts versioned to a specific model, so evals must rerun on every model upgrade, and skills without evals are wishful thinking.

“this like new model was very focusing on beginning of the skill and we had very critical instruction at the end of the skill.”

said at 12:04

“Skills are not the documentation and a lot of people treat them like that and skills are really the contracts versioned to a model.”

said at 12:36

“whenever you're upgrading a model, make sure to rerun uh your eval.”

05Governance at scale
Slide at 13:40 · click any slide to enlarge · 8 more from this section below

Governance at scale

  • Past roughly ten skills, the whole set no longer fits cleanly in a system prompt and needs shortlisting (embeddings/similarity search or a smaller routing model); past hundreds of skills, teams need a governance layer covering five aspects borrowed from code-review practice: admission, ownership, boundaries, lifecycle, and coherence.

“there are like five aspect of skill library governance and these are admission, ownership, boundaries, life cycle and coherence.”

said at 13:40

Commentary (ours)

The model-upgrade failure (attention bias toward the start of a skill file) is reported as one incident at FactSet; whether it generalizes across model families or is specific to the model pair they swapped between isn't established in the talk.
