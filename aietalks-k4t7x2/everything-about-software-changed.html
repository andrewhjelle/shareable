Everything we knew about software has changed

SpeakerTheo Browne · t3dotgg Watchyoutu.be/xUnRQ9vLXxo
Coding agentsAgentic engineeringProduct & UX

If you only read one thing

  • Each model era (Sonnet 3.5, Opus 4.5, Mythos) unlocked a qualitatively different capability -- reliable tool calls, long-running task completion, and self-orchestration into sub-agents respectively (c1, c2)
  • Browne argues project-scope tiers have shifted down one level: what was a startup is now a side project, and some conference startups' whole product 'could just be a markdown file' (c4, c5)
  • He argues breadth (competing with platforms like AWS or Slack) is now viable for small teams because users can fill gaps with their own agent-built features (c6, c7)
01Model eras and what each unlocked

Browne frames Sonnet 3.5 as the first model that did tool calls reliably enough for day-to-day coding, Opus 4.5 as the first to sustain long-running tasks without losing track, and Mythos as the first that understands itself well enough to spawn and coordinate additional models without custom orchestration tooling. He states the models are getting better faster than engineers are, so he argues teams must 'go bigger' rather than try to keep pace by getting better themselves.

“Having a model that couldn't just write the code and call tools, but could go way further.”

02Scoping tiers have shifted down

Browne argues what used to require a startup-level effort is now buildable as a side project, and describes automating a PR-triage workflow that runs as a scheduled markdown prompt piped to a coding agent. He says some conference companies' entire product could be reduced to a markdown file run on a cron.

“Now that the models are bigger, the tiers have shifted. Everything is now one tier lower.”

▶ watch at 10:52

“Do you know how many companies are at this event where their whole product could just be a markdown file? It's insane.”

▶ watch at 11:22
03Breadth becomes viable, citing Vercel and Slack

Browne contrasts Vercel's deliberate narrow-and-deep strategy against AWS's breadth, and argues that with agents, small teams can now build broad feature coverage quickly enough that gaps can be filled by users' own agent-built additions -- citing Slack, which he calls a mediocre product that became an agent-hosting platform through its bot APIs.

“But Vercel offers deeper features in the space they're in, which is full-stack front-end leaning servers.”
