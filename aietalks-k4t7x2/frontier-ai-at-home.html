Run Frontier AI at Home

If you only read one thing

  • Local inference is bottlenecked by memory bandwidth, not compute, and current software leaves large gains on the table -- fusing unnecessary kernels on Qwen 3.5 alone yielded a 30% speedup (c1, c2, c3).
  • On an intelligence-per-joule metric, local inference improved roughly 5x from hardware and separately from model gains over two years; the speaker predicts $5,000 consumer hardware will reach close to frontier-level performance within about 18 months to 2 years (c4, c5).
  • EXO clusters heterogeneous hardware (Macs plus an Nvidia Spark) and added RDMA to cut inter-device latency by 100x, splitting prefill and decode across devices for roughly a 2x speedup on large prompts in a live demo (c6, c9).
01Local inference has a lot of untapped software headroom

EXO found that running Qwen 3.5 locally on Apple silicon ran about 50% slower than the theoretical speed, caused by inefficient kernels being launched separately; fusing those kernels increased inference performance by 30%. The speaker also argues a good harness matters a lot for local inference because it keeps the prompt's static portions (system prompt, tools) cached across turns, reducing how much the compute-bound prefill stage matters relative to decode.

“we just did some pretty basic work to fuse that all together and increase the inference performance by 30%”

02Inference is memory-bound, unlike training

The speaker contrasts training, which is compute (flops) bound, with inference, where most operations at low batch sizes -- the typical case when running locally for a single user -- are memory bound. This makes memory capacity, memory bandwidth, and energy per byte moved the three variables that actually determine local inference performance.

“everything all the operations you're doing, depending on the model, is like most of those operations are memory bound”

▶ watch at 10:56
03The trajectory: consumer hardware closing in on frontier performance

Using an 'intelligence per joule' metric from Stanford's Hazy Research group, the speaker reports roughly 5x improvement from hardware gains over the past two years, compounding with a separate 3x from model improvements. 04EXO clusters heterogeneous hardware for real speedups

EXO's software clusters multiple Macs (and other hardware like an Nvidia Spark) over Thunderbolt, and recently added low-latency RDMA support that cut inter-device communication latency by roughly 100x, from about 300 microseconds down to single-digit microseconds -- necessary to make tensor-parallel model splitting practical across many synchronization points per token. In a live demo, splitting a large prompt's prefill stage onto a compute-heavy Nvidia Spark and its decode stage onto a memory-bandwidth-heavy MacBook produced roughly a 2x end-to-end speedup versus running the whole thing on the MacBook alone.

“with RDMA, it's 100 times faster. So, it's like single-digit microseconds”

05Cautions: fake breakthroughs and undirected optimization

The speaker warns that many viral local-inference demos rely on heavy quantization (e.g., running a model at 1 bit), which is deceptive since a smaller, unquantized model would perform better than the heavily quantized large one. He's also skeptical of using agentic auto-research to optimize inference hardware setups without a well-reasoned hypothesis, arguing it produces results that look like progress without necessarily being useful, and that a real breakthrough claim needs the scientific method: hypothesis, experiment, iteration.

“if you like quantize a model to one bit, then you're better off just using a smaller model and not quantizing it”

Commentary (ours)

The test-time-training aside is worth flagging separately from the rest of the talk: if inference-time weight updates became standard, the speaker's own argument implies it would break cloud-side batching economics entirely, which would be a much larger structural shift favoring local inference than any of the hardware or kernel gains discussed here (ours).
