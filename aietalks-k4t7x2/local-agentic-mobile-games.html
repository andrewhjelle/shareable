01No AI in the games themselves

The speakers open with a disclaimer that NYT's puzzles are made by people, not AI, that this will always be true, and that none of the shipped games (including Wordle Bot) have AI features. The work presented is framed explicitly as experimental exploration of agent capabilities such as solvability and playability, not a description of production game features.

02RL versus agentic systems for game AI

The talk distinguishes two historical approaches to game AI: reinforcement learning, which iteratively trains and changes a model's weights to specialize it for a particular game, versus agentic systems, which use language models reasoning in-context (no weight changes, no reward signal to optimize against) to interpret and act on the state of a game dynamically. A demo agentic version of Space Invaders is shown running a perceive-predict-decide-act loop entirely from an on-device model.

“So, RL changes the model itself and changes the weights in the model. Um the agentic system reasons over a space in the game, um and there's no reward system to grind out.”

03The on-device resource budget

Running an agent on a mobile device is described as constrained along three axes: space (fitting model weights, state history, and planning artifacts within device memory alongside rendering needs), time (an agent's planning has to complete inside each frame, i.e. within roughly 16 milliseconds at a 60Hz refresh rate, or the result is visible jank), and energy (battery life, given that current devices aren't yet optimized for agentic workloads). The talk describes managing these jointly as a constraint graph with techniques like soft-constraining some axes while penalizing overruns on others, particularly time.

“you get a new frame every 16 ms a pound if your refresh rate is 60 Hz. You need to actually fit the agent planning within that, and if you go outside of that budget”

04Accessibility as a live-tuned dial, not a static toggle

The accessibility portion grounds its design in WCAG 2.2's four pillars (perceivable, operable, understandable, robust) rather than inventing a new standard, and argues that fixed accessibility toggles are blind to a player's real-time state. The proposed system instead has an on-device agent continuously calculate dials like input tolerance and step granularity from live signals such as gaze tracking, shaky-tap detection, and handwriting recognition.

“This framework evaluates interactions across four human-centric pillars. Is this experience perceivable, operable, understandable, and robust?”

▶ watch at 12:56
05The agent as live layout auditor

Rather than only watching, the accessibility agent is described as acting: it measures the interface on the fly, catches WCAG-style violations such as tiny tap targets or broken keyboard focus traps, and dynamically resizes or fixes the live layout for that player, framed as the layout adapting to the human rather than the other way around.

“our agent is a live layout auditor. It measures the interface on”

▶ watch at 15:32
06Where this is heading

The talk closes by predicting that the future of on-device game AI is not one large centralized model but many small local models, each shaped by and personalized to the individual device and player it serves, contingent on faster chips, predictive models, longer-term personalized memory, and a shared cross-game state language that don't yet exist.

“the future of AI doesn't have to be one giant centralized brain. It can be billions of small local brains, each running on a personal device, each shaped entirely by the individual it serves.”
