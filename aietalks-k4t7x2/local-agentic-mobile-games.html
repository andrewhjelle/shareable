If you only read one thing

  • NYT states plainly that its published puzzles are made by people, not AI, and that none of its shipped games have AI features (Wordle Bot included); the agentic work described is experimental, not in production (c4).
  • The talk distinguishes RL, which changes a model's weights through training cycles, from agentic systems, which reason in-context with no reward signal to grind against, and frames on-device agents as bounded by a joint space/time/energy budget, including fitting planning inside each 16ms frame at 60Hz (c1, c2, c3).
  • For accessibility, the pitch is an agent that continuously tunes dials like input tolerance and step granularity against WCAG 2.2's four pillars and acts as a live layout auditor rather than relying on static accessibility settings, with local agents framed as the long-term direction over one centralized cloud model (c6, c7, c5).

02RL versus agentic systems for game AI

RL versus agentic systems for game AI

  • The talk distinguishes two historical approaches to game AI: reinforcement learning, which iteratively trains and changes a model's weights to specialize it for a particular game, versus agentic systems, which use language models reasoning in-context (no weight changes, no reward signal to optimize against) to interpret and act on the state of a game dynamically.
  • A demo agentic version of Space Invaders is shown running a perceive-predict-decide-act loop entirely from an on-device model.

“So, RL changes the model itself and changes the weights in the model. Um the agentic system reasons over a space in the game, um and there's no reward system to grind out.”

03The on-device resource budget
Slide at 08:40 · click any slide to enlarge · 8 more from this section below

The on-device resource budget

  • Running an agent on a mobile device is described as constrained along three axes: space (fitting model weights, state history, and planning artifacts within device memory alongside rendering needs), time (an agent's planning has to complete inside each frame, i.e. within roughly 16 milliseconds at a 60Hz refresh rate, or the result is visible jank), and energy (battery life, given that current devices aren't yet optimized for agentic workloads).
  • The talk describes managing these jointly as a constraint graph with techniques like soft-constraining some axes while penalizing overruns on others, particularly time.

“you get a new frame every 16 ms a pound if your refresh rate is 60 Hz. You need to actually fit the agent planning within that, and if you go outside of that budget”

said at 08:48

“there's a constraint function in of this for example constraint graph that takes into account all three of these areas”

04Accessibility as a live-tuned dial, not a static toggle
Slide at 13:10 · click any slide to enlarge · 4 more from this section below

Accessibility as a live-tuned dial, not a static toggle

  • The accessibility portion grounds its design in WCAG 2.2's four pillars (perceivable, operable, understandable, robust) rather than inventing a new standard, and argues that fixed accessibility toggles are blind to a player's real-time state.
  • The proposed system instead has an on-device agent continuously calculate dials like input tolerance and step granularity from live signals such as gaze tracking, shaky-tap detection, and handwriting recognition.

“This framework evaluates interactions across four human-centric pillars. Is this experience perceivable, operable, understandable, and robust?”

said at 12:56
05The agent as live layout auditor
Slide at 15:10 · click any slide to enlarge · 3 more from this section below

The agent as live layout auditor

  • Rather than only watching, the accessibility agent is described as acting: it measures the interface on the fly, catches WCAG-style violations such as tiny tap targets or broken keyboard focus traps, and dynamically resizes or fixes the live layout for that player, framed as the layout adapting to the human rather than the other way around.

“our agent is a live layout auditor. It measures the interface on”

said at 15:32
06Where this is heading
Slide at 17:30 · click any slide to enlarge · 1 more from this section below

Where this is heading

  • The talk closes by predicting that the future of on-device game AI is not one large centralized model but many small local models, each shaped by and personalized to the individual device and player it serves, contingent on faster chips, predictive models, longer-term personalized memory, and a shared cross-game state language that don't yet exist.

“the future of AI doesn't have to be one giant centralized brain. It can be billions of small local brains, each running on a personal device, each shaped entirely by the individual it serves.”

said at 17:04

Commentary (ours)

(ours) The disclaimer that shipped NYT games are AI-free and that everything shown is experimental is worth holding onto throughout: the accessibility and Space Invaders/mini-crossword demos illustrate a research direction on local agentic architecture, not features live in any current NYT game.
