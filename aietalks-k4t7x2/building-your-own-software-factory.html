Building your own software factory

SpeakerEric Zakariasson · Cursor Watchyoutu.be/rnDm57Py54A
Agentic engineeringCoding agentsMemory

If you only read one thing

  • Cursor frames AI-assisted coding on a six-stage autonomy ladder (Dan Shapiro's framework), from "spicy autocomplete" up to a "dark factory" where agents ship, test, and build code while a human manager only supplies intent.
  • Cursor's internal practice: install rules only when agents go off the rails rather than wholesale from a rules directory, build verifiable systems so agents can check their own work, and never let agents decide safety, security, database, or payments changes -- those stay human-owned.
  • Cursor rebuilt its own editor (Cursor 3, no VS Code) around multi-agent orchestration, scales cloud agents to an estimated multiple thousands per day, and runs an "agentic code owner" that auto-approves low-risk PRs to avoid blocking engineers on human reviewers.
01From autocomplete to a "dark factory"

The talk opens with Dan Shapiro's six-stage framework for software autonomy, from an early "spicy autocomplete" stage up through pair-programmer and manager-of-agents stages to a final "dark factory" stage where the human no longer has direct insight into the code and just supplies intent and goals while agents ship, test, and build. The speaker gives throughput (running agents continuously without needing sleep or food) as one motivation for building toward this.

02Rules should emerge from failures, not be installed wholesale

Rather than installing every available rule for a given tech stack from a rules directory, the speaker's internal experience and observation of users is that rules should emerge dynamically: when an agent goes off the rails on something specific, that's the signal to write a rule for it.

“what I found and what I'm seeing amongst our users and internally is that rules should just like emerge dynamically. Like if you're finding agents going off the rails, you should probably create a rule for that.”

▶ watch at 07:19
03Verifiable systems let agents check their own work

The speaker names building verifiable systems -- ways for agents to check their own work via unit tests, integration tests, or UI tests that click around in the DOM to reproduce end-user behavior -- as the area deserving the most additional investment.

“which I think people should be spending a lot more time is like building verifiable systems how can um the agents themselves like verify their own work”

▶ watch at 09:56
04Worker becomes manager: async at scale, but humans keep the risky decisions

As more work moves to agents, the speaker describes a shift from synchronous pairing to asynchronous oversight, where work happens in the background and the human checks in on multiple agents rather than writing code directly. The explicit limit on this delegation: safety, security, database, and payments/authentication decisions should stay human-decided rather than being outsourced to agents.

“going from sync to async because most of the work is going to happen in the background and you can still tap in and see what's going on uh for different agents”

▶ watch at 17:17

“don't outsource important decisions. Like make sure you're staying in the loop for important decisions. Um whether this is like uh safety or security or databases or payments and authentication”

▶ watch at 31:19
05What this looks like in practice at Cursor

Cursor rebuilt its editor from scratch as Cursor 3, dropping the VS Code base in favor of an agent-first, multi-agent-orchestration interface. The speaker estimates the company runs cloud agents at a scale of multiple thousands per day once teams have isolated VM environments set up, and describes an internally built "agentic code owner" that assesses PR risk level and auto-approves low-risk changes to avoid blocking engineers on human review.

“this is cursor uh three. Uh we launched this a couple of weeks ago, and it's a complete rewrite of cursor. There's no VS code anymore.”

Commentary (ours)

The gap between the six-stage autonomy ladder and Cursor's own admission that most teams sit at level two or three, with Cursor itself only partly at level four, is a useful calibration point against "dark factory" marketing language elsewhere in the ecosystem (ours).
