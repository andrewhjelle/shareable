Can Oncology Workflows Run Without Human Touch?

Blueprint · full operating modelHealthcare AIVertical AIAgentic engineering

Risa Labs runs a four-agent oncology pipeline (eligibility, auth status, medical necessity, submission) with cross-source verification, deterministic checks, and a self-healing RPA loop escalating clinical judgment.

If you only read one thing

  • A single LLM extraction pipeline over patient notes was not enough to remove humans from review because LLM extraction is indeterministic and cannot be blindly trusted.
  • Cross-referencing two independent sources (authorization letters plus a payer-rule knowledge base) let the team only auto-approve cases where both sources agreed, enabling true no-touch processing for a subset of orders.
  • A four-agent pipeline (eligibility, auth status, medical necessity, submission) plus deterministic checks and a self-healing RPA loop is progressively growing the no-touch share of orders while escalating clinical judgment calls to a human.

Why this talk is a blueprint, not a take (ours)

Scope: A four-agent pipeline (eligibility, auth status, medical necessity, submission) that processes oncology prior-authorization orders end to end, from patient data intake through payer submission.

A system that automatically clears a growing share of prior-auth orders with zero human touch by requiring two independent evidence sources to agree before auto-approving, and routes only genuinely ambiguous clinical judgment calls to a human. The same four agents are described as reusable building blocks that can be recomposed into other workflows such as eligibility-only checks or retroactive auth backfills.

Prerequisites the talk implies:

  • A second, genuinely independent evidence source for cross-referencing LLM extraction (here: historical auth letters and a payer-rule knowledge base built from portal checks)
  • Structured or semi-structured patient data (notes, policy criteria, a biomarker graph) that an LLM can extract from
  • An RPA layer with a reusable action library and per-payer config generation to reach many payer portals without bespoke integrations
  • A self-healing mechanism to detect and repair automation breakage when a payer portal changes

What the talk does not say:

  • No cost, team size, or build-time figures given for the pipeline
  • No stated failure rate or error rate for the no-touch path, only that a growing share of orders qualifies
  • No detail on how confidence scores are calibrated or thresholded for escalation
  • No description of how the payer rule knowledge base is kept current between monthly portal checks

If you were to replicate one thing first: Identify one high-volume, document-heavy review step in your workflow and check whether a second, independent evidence source already exists that could confirm an LLM extraction before attempting any auto-approval.

Single-source LLM extraction was not enough

  • An initial LLM extraction pipeline over patient notes classified drugs into the three auth categories, but the team found notes often lacked sufficient data and that LLM extraction is an indeterministic process, so its output could not be blindly trusted for no-touch approval, only used to improve human review efficiency.

03Cross-referencing evidence sources to build confidence

Cross-referencing evidence sources to build confidence

  • The team added two independent data sources: historical authorization letters, and a payer-rule knowledge base built from a SQL database of portal checks and LLM extractions covering which drugs a given payer does not require authorization for on a monthly basis.
  • Where the LLM extraction and an independent source agreed, the team could confidently mark an order no-touch; this eliminated entire orders where all drugs fell into these two categories.

05Results and architecture summary
Slide at 05:30 · click any slide to enlarge · 8 more from this section below

Results and architecture summary

  • The full pipeline runs four agents (EV, auth, necessity, submission) atop a deterministic decision engine and a self-healing RPA loop that mitigates automation breakages during production hours.
  • The speaker summarizes the approach as starting with deterministic checks, applying agents only where rules cannot decide, and using multiple sources of evidence rather than a single source to build confidence for no-touch processing.

Commentary (ours)

The core mechanism here (never trust single-source LLM extraction for an auto-approval decision; require independent corroboration) generalizes well beyond healthcare to any compliance-adjacent automation, though it depends on a second, genuinely independent evidence source existing at all, which won't be true in every domain (ours).
