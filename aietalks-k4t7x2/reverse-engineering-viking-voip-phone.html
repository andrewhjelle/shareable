Reverse Engineering a Viking VOIP Phone Protocol with Claude Code

SpeakerBoris Starkov · Eleven Labs Watchyoutu.be/V-L0INGTEOg
Coding agentsAgentic engineering

If you only read one thing

  • Claude Code nmapped the phone, brute-forced all two-letter command codes to find ~80 valid commands, then reverse engineered a one-byte checksum by correlating known payload data against captured responses (c1, c3, c5).
  • When credential writes didn't persist after reboot, Claude set up a Windows VM plus a Mac-side TCP proxy to man-in-the-middle the vendor software's traffic and find the missing persistence command (c4, c6).
  • The presenter, a non-security-engineer, says the reverse engineering wouldn't have been possible at all without Claude Code, not just faster (c7); the resulting protocol knowledge was packaged as an open-sourced Claude Code skill (c8).
01The setup: an old phone nobody could crack a year earlier

A Windows-XP-only Viking VOIP phone booth (built with Twilio and Eleven Labs voice) had sat unused for a year after three senior engineers plus ChatGPT failed to get it working on Mac hardware. The presenter connected the phone via router to his Mac and let Claude Code explore it directly rather than trying to find vendor software.

“three senior software engineers and a Claude uh sorry, ChatGPT at the time, they couldn't figure out how to make it work”

▶ watch at 02:08
02Brute-forcing an undocumented protocol

Claude Code port-scanned the phone, found the control port, and discovered the phone used two-letter command codes returning an error echo for invalid ones. It then wrote a program to try every two-letter combination, finding about 80 valid commands out of the full set.

“when you send a random string to the phone, it returns uh this ER and then the string itself”

▶ watch at 05:44

“it turned out that most of them returned error codes, but 80 of them returned actual like something else, meaning they're actual valid commands”

▶ watch at 06:16
03Persistence problem forced a man-in-the-middle setup

Credentials written to the phone worked but were lost on reboot because they were only stored in temporary memory, and brute-forcing three-letter commands found no persistence command. Claude Code's fix was to run the vendor software in a Windows VM, proxy its traffic through a TCP proxy on the Mac (since the VM had no direct internet/Wi-Fi bridge), and log the intercepted traffic to find the missing command.

“It set up a TCP proxy on the Mac so that the uh traffic from the virtual machine”

▶ watch at 09:22
04Cracking the checksum and closing the loop

The intercepted persistence command (TS) had a binary payload where every field made sense except a one-byte checksum. Because the byte-length was small enough to brute-force and the input data plus expected result were known, Claude Code derived the checksum as a simple one-byte addition/subtraction and confirmed it by testing more values, letting the phone be reprogrammed directly without the VM afterward.

“checksum turned out to be only uh one byte. So, it's something that you can brute force as well”

▶ watch at 10:56

“it actually like managed to find it and then it confirmed it uh by running uh by running more values through it”

▶ watch at 11:58
05Outcome: impossible without the agent, now a shareable skill

The presenter states this reverse engineering wasn't just faster with Claude Code, it was possible at all for him as a non-security-engineer, and estimates total token spend at $10-100 on Eleven Labs' corporate account. He packaged the resulting protocol knowledge as an open-sourced Claude Code skill so others with the same phone hardware don't need to repeat the Windows VM process, and suggests the approach generalizes to other undocumented hardware.

“it's not just it made it 10 times faster, it just made it possible because I'm not a security security engineer whatsoever”

▶ watch at 15:09

“I used Eleven Labs our corporate tokens. So, I I yeah, I think it was in order of between 10 and 100 dollars”

▶ watch at 16:33

Commentary (ours)

The persistence-and-checksum arc is a fairly clean demonstration of agent-driven binary-protocol inference from black-box input/output pairs rather than static analysis -- worth watching whether this kind of workflow gets formalized into a general-purpose reverse-engineering skill/tool rather than a one-off build (ours).
