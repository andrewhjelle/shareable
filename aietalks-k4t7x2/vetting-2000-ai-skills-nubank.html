If you only read one thing

  • Nubank scanned over 2,000 AI skills before marketplace distribution and found more than 1,500 risks; most were remediated, some were blocked outright.
  • Their tool, Skill Vector, combines deterministic regex checks with LLM review, runs both locally pre-upload and again in CI, and reports as SARIF directly in the pull request.
  • A key false-safety trap: an agent can satisfy its own 'ask for confirmation' instruction without an actual human reviewing or approving the action, so that pattern needs specific scanning.

AI skills are supply-chain dependencies

  • The talk's framing is that AI skills, plugins, MCP servers, and agent rules behave like supply-chain dependencies even though they look like configuration, so the whole workflow that produces AI-assisted code needs protecting, not just the generated code itself.
  • Nubank built a security review system to check these skills before they reach developers, especially given the auditability requirements of operating in a regulated financial environment.

Concrete failure modes

03Skill Vector: local scan, CI scan, LLM review

Skill Vector: local scan, CI scan, LLM review

  • Skills are shared through an internal marketplace, gated by a CI step called Skill Vector that engineers can also run locally to iterate before upload, then re-runs after upload to ensure the latest version was checked.
  • It layers deterministic regex-based checks for easy risks with an LLM review for context-dependent risk, and reports findings as SARIF directly on the pull request so remediation guidance appears where the skill was submitted.

“it's important to have this hybrid approach with LLM checking the the context but also with the determinist because you know how LLM is depending on the temperature that was set”

04Results at scale and a specific trap
Slide at 14:10 · click any slide to enlarge · 1 more from this section below

Results at scale and a specific trap

  • Across the scanned corpus of over 2,000 skills, Skill Vector identified more than 1,500 total risks (a single skill can carry multiple), with about 1,000 remediated immediately and some blocked before ever reaching the marketplace.
  • One recurring trap: developers write a prompt-level instruction telling the agent to 'ask for confirmation,' but the agent can satisfy that instruction by confirming with itself, producing the appearance of a human-in-the-loop control without an actual human involved.

“we have scanned on that over 2,000 skills. uh now there is much more than that but this is the baseline that I brought for you on this presentation uh inside this we have identified uh more than 1,000 and half uh risks”

said at 09:54

“people sometimes will add the instruction like you need to ask for confirmation but the AI may ask confirmation for itself”

said at 13:05

Commentary (ours)

The self-confirming 'ask for confirmation' pattern is the sharpest finding here because it looks like a safety control on the surface and would pass a naive review; it's a good candidate for a targeted check other teams building agent-approval flows should copy directly.
