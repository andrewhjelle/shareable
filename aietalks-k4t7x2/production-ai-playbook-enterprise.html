The Production AI Playbook: Deploying Agents at Enterprise Scale

SpeakerSandipan Bhaumik · Databricks Watchyoutu.be/ObTPqBGsEbA
Agentic engineeringEvals & benchmarksInfra & serving

If you only read one thing

  • Recommends building evaluation and observability infrastructure before picking a model; a banking chatbot project selected its model only in week 7 of an 8-week POC.
  • Three-layer evaluation architecture (deterministic checks, LLM-as-judge semantic checks, behavioral checks like duplicate tool calls) catches failures a single accuracy metric misses.

01Three gaps behind failed AI production launches

The speaker describes a recurring pattern: teams pick a model first, build a demo on curated data, get leadership sign-off, then fail once real production traffic hits. He attributes this to three gaps: no observability into agent decisions, no defined evaluation metric tied to the business, and no governance for who is accountable when AI fails.

“if we can't see what it is actually doing, if we can't trace every decision that it's making, it's no use in production”

02Five pillars, evaluation first

The proposed framework has five pillars: evaluation, observability, data foundation, orchestration, and governance, ideally built in that sequence. Evaluation means defining success in numbers (target accuracy, deflection rate) before writing code, building a golden test set from real support-agent answers, and automating comparison of live responses against it.

“Before touching any code, before discussing about any models, any features, you have to think about when we build this system, how do we measure”

▶ watch at 05:13
03Three-layer evaluation architecture

Evaluation splits into deterministic checks (format/regex, cheap and already solved), semantic checks (LLM-as-judge for groundedness and relevance), and behavioral checks (whether an agent made redundant or looping tool calls). He gives an example where an agent answered a balance question correctly but made three duplicate database calls, which is fine in a demo but costly at production volume.

“three API calls in demo environment is fine, but in production, when you get thousands of queries from users every day”

▶ watch at 12:11
04Data foundation and observability data

He splits data work into 'question data' (what the agent needs to answer users) and 'tracking data' (tracing/observability data), and reports spending 60% of typical project time here because agents act on bad data confidently rather than flagging it, unlike humans. Databricks' stack (cloud storage, Delta Lake, Unity Catalog) centralizes both question data and cross-framework tracing data for dashboards, LLM judges, and audits.

“in my typical project projects, I spend 60% of my time, uh and I see I see a lot of organizations spending a lot of time here”

▶ watch at 15:09
05Orchestration patterns and governance

He names three multi-agent orchestration patterns: orchestrator-worker (centralized control, easy debugging), choreography (independent agents on a message bus, lower latency, parallel execution), and human-in-the-loop for below-threshold confidence. Governance covers audit trails, PII detection, prompt versioning as change management, and model change management, since providers upgrade models and enterprise-specific evaluation is needed to judge whether an upgrade is safe.

“every request goes through the orchestrator, so you have got central control. If something goes wrong, you can go to the orchestrator logs”

▶ watch at 20:19

“It cannot be just change to a prompt and commit to get. It has to be is it has to go through proper change management processes as you do with code”

▶ watch at 23:20
06Case study: banking chatbot

A retail banking client had spent about $85K over 6 months on a chatbot POC that failed, unable to diagnose why. Rebuilding with the framework, the team built the evaluation layer in weeks 1-2 (200 real-agent cases, an 85% accuracy target), the data foundation in following weeks, and only selected the model in weeks 7-8. Six weeks post-launch, a policy change caused stale vector-database embeddings to feed outdated answers, visible via dropping CSAT and traced to the specific failure.

“we already detected 47 PII breaches during the testing phase by applying this layer”

Commentary (ours)

The claim that data foundation work eats 60% of project time is a useful counterweight to model-centric AI planning discourse -- worth testing whether that ratio holds outside regulated/banking contexts where data governance is already heavy (ours).
