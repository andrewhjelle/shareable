If you only read one thing

  • Recommends building evaluation and observability infrastructure before picking a model; a banking chatbot project selected its model only in week 7 of an 8-week POC.

Why this talk is a blueprint, not a take (ours)

Scope: A five-pillar framework (evaluation, observability, data foundation, orchestration, governance) for taking agentic AI systems from demo to enterprise production, illustrated with a retail banking chatbot rebuild.

A sequencing argument: build the evaluation and observability layers and a golden test set before choosing a model, then add orchestration and governance. On the banking case study, that produced 87% accuracy against an 85% target, a 62% deflection rate, and roughly $1M in annual savings, plus a documented incident (a stale vector-database policy update) detected and fixed within days because tracing and an eval dashboard were already in place.

Prerequisites the talk implies:

  • A defined, numeric success metric agreed with the business (accuracy target, deflection rate) before any model is chosen
  • A golden test set built from real human-agent answers, with a process to add new cases as failures occur
  • Tracing/observability infrastructure covering every agent decision, since regulators in some industries will not allow production AI without it
  • A data strategy that treats question data (what the agent needs to answer) and tracking data (traces) as two separate but connected pipelines
  • An ITSM integration so the incident playbook can alert the right person automatically

What the talk does not say:

  • No cost, team size, or timeline for standing up the Databricks stack (Delta Lake, Unity Catalog, Agent Bricks) itself, separate from the banking project timeline
  • No detail on how the human-in-the-loop confidence threshold is calibrated, beyond the general warning that too high or too low both fail
  • No comparison to a non-Databricks stack, so the numbers cannot be separated from the vendor platform they were built on
  • No discussion of whether the 60%-of-time-on-data-foundation figure or the sequencing generalizes outside banking and other heavily regulated industries

If you were to replicate one thing first: Before selecting a model, write the numeric definition of success for one narrow use case and assemble a small golden test set (the case study used 200 real agent answers) to evaluate any model against.

Three gaps behind failed AI production launches

  • The speaker describes a recurring pattern: teams pick a model first, build a demo on curated data, get leadership sign-off, then fail once real production traffic hits.
  • He attributes this to three gaps: no observability into agent decisions, no defined evaluation metric tied to the business, and no governance for who is accountable when AI fails.

Three-layer evaluation architecture

  • Evaluation splits into deterministic checks (format/regex, cheap and already solved), semantic checks (LLM-as-judge for groundedness and relevance), and behavioral checks (whether an agent made redundant or looping tool calls).
  • He gives an example where an agent answered a balance question correctly but made three duplicate database calls, which is fine in a demo but costly at production volume.

05Orchestration patterns and governance
Slide at 20:10 · click any slide to enlarge · 3 more from this section below

Orchestration patterns and governance

  • He names three multi-agent orchestration patterns: orchestrator-worker (centralized control, easy debugging), choreography (independent agents on a message bus, lower latency, parallel execution), and human-in-the-loop for below-threshold confidence.
  • Governance covers audit trails, PII detection, prompt versioning as change management, and model change management, since providers upgrade models and enterprise-specific evaluation is needed to judge whether an upgrade is safe.

Case study: banking chatbot

  • A retail banking client had spent about $85K over 6 months on a chatbot POC that failed, unable to diagnose why.
  • Rebuilding with the framework, the team built the evaluation layer in weeks 1-2 (200 real-agent cases, an 85% accuracy target), the data foundation in following weeks, and only selected the model in weeks 7-8.
