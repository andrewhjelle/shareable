A Song of Types and Agents

SpeakerRoberto Stagi · Ratel Watchyoutu.be/UlFB6efYN5Q
Agentic engineeringCoding agentsOpen source

If you only read one thing

  • TypeScript passed Python as GitHub's most-used language in August 2025, both years attributed by GitHub to AI-driven growth.
  • Coding agents (Claude Code, Cursor, Codex) default to producing TypeScript, and that default is compounding as more TypeScript code trains the next generation of agents.
  • Building agents in TypeScript lets a team use one language and one Zod schema across agent loop, backend, and UI instead of syncing Python and JS across a service boundary.
01Python still owns training, TypeScript is taking the application layer

The speaker distinguishes the infrastructure/training layer of AI (model training, research, GPU serving) from the application layer where AI features get shipped inside products. He argues Python remains dominant for the former but TypeScript has owned the application/UI/backend layer for a long time and is now absorbing the agentic layer too.

“the brain of the of the agent and all the of all the AI world is actually still owned by Python. All the training, the research, the GPU serving is all Python's”

“TypeScript doesn't just own, you know, the UI or the back end. Started owning also the agentic layer of our application”

02GitHub's language rankings flipped in one year

Python became GitHub's top language in 2024, which GitHub's report attributed to AI. In August 2025, TypeScript passed Python as the top language, and GitHub's report gave the same reason: AI. The speaker ties the swap to coding agents (Claude Code, Cursor, Codex) becoming established and defaulting to TypeScript output.

“in August 2025, TypeScript TypeScript actually passed Python as the most used language on GitHub”

▶ watch at 04:06

“What changed between 2024 and 2025 was actually coding agents. The coding agents grew up like we saw established um we saw the players establishing themselves like Lava Cloud Code, Cursor, Codex”

▶ watch at 05:42
03Why TypeScript for agents, concretely

He gives four reasons to build agents in TypeScript: coding agents are trained on more TypeScript so their TypeScript output quality compounds; NPM offers the deepest package ecosystem (auth, payments, UI, infra); one language covers agent loop, tools, backend, and UI instead of splitting into a Python service plus a separate JS frontend; and a single Zod schema can type the backend, model, and UI instead of maintaining two type systems across a service boundary.

“NPM comes with everything, uh pretty much everything, like authentication, payments, UI, infra”

▶ watch at 08:21

“you can have one single code base for the whole application. Because you can use TypeScript for your agent loop, for the tools, for the back end service, for the UI”

▶ watch at 08:52

“if you use TypeScript, you can use Zod as a single schema throughout all your application, which is very convenient. You can define a type once”

▶ watch at 10:27
04Ecosystem growth and the closing recommendation

He cites the Vercel AI SDK growing from 1.6 million to 15.1 million weekly downloads in one year (roughly 9-10x) as evidence of TypeScript's AI ecosystem surge. His closing recommendation is to keep training models in Python but build agents and applications in TypeScript, citing Jeff Atwood's line that any application that can be written in JavaScript eventually will be.

“in just 1 year, it went from 1.6 million to 15.1 million downloads per week, which is between 9 and 10x in just 1 year”

▶ watch at 10:58

“keep training in Python. As I said, I don't see that's one going away soon. But please consider building the agents and the applications in TypeScript”

▶ watch at 13:33

Commentary (ours)

The GitHub-ranking flip is real but the causal story (coding agents drove it) is asserted, not measured against a counterfactual -- worth checking whether TypeScript's rise predates the coding-agent wave GitHub credits it to (ours).
