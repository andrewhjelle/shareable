A Song of Types and Agents

SpeakerRoberto Stagi · Ratel Watchyoutu.be/UlFB6efYN5Q · 14 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. takeAgentic engineeringCoding agentsOpen source

Argues the application/agent layer of AI stacks is shifting to TypeScript while training/inference stays Python, with GitHub's own 2025 report and coding-agent adoption as evidence

If you only read one thing

  • TypeScript passed Python as GitHub's most-used language in August 2025, both years attributed by GitHub to AI-driven growth.
  • Coding agents (Claude Code, Cursor, Codex) default to producing TypeScript, and that default is compounding as more TypeScript code trains the next generation of agents.
  • Building agents in TypeScript lets a team use one language and one Zod schema across agent loop, backend, and UI instead of syncing Python and JS across a service boundary.
▣The system in one picture (ours, from the slides and the transcript)

This traces the speaker's argument from a stable Python training layer to a TypeScript-agent recommendation; the causal claim that coding agents drove the GitHub ranking flip is asserted, not measured against a counterfactual (ours).

Python still owns training, TypeScript is taking the application layer

GitHub's language rankings flipped in one year

  • Python became GitHub's top language in 2024, which GitHub's report attributed to AI.
  • In August 2025, TypeScript passed Python as the top language, and GitHub's report gave the same reason: AI.
  • The speaker ties the swap to coding agents (Claude Code, Cursor, Codex) becoming established and defaulting to TypeScript output.

“in August 2025, TypeScript TypeScript actually passed Python as the most used language on GitHub”

03Why TypeScript for agents, concretely
Slide at 08:20 · click any slide to enlarge

Why TypeScript for agents, concretely

  • He gives four reasons to build agents in TypeScript: coding agents are trained on more TypeScript so their TypeScript output quality compounds; NPM offers the deepest package ecosystem (auth, payments, UI, infra); one language covers agent loop, tools, backend, and UI instead of splitting into a Python service plus a separate JS frontend; and a single Zod schema can type the backend, model, and UI instead of maintaining two type systems across a service boundary.

“NPM comes with everything, uh pretty much everything, like authentication, payments, UI, infra”

said at 08:21

“you can have one single code base for the whole application. Because you can use TypeScript for your agent loop, for the tools, for the back end service, for the UI”

said at 08:52

“if you use TypeScript, you can use Zod as a single schema throughout all your application, which is very convenient. You can define a type once”

said at 10:27
04Ecosystem growth and the closing recommendation
Slide at 11:10 · click any slide to enlarge · 7 more from this section below

Ecosystem growth and the closing recommendation

  • He cites the Vercel AI SDK growing from 1.6 million to 15.1 million weekly downloads in one year (roughly 9-10x) as evidence of TypeScript's AI ecosystem surge.
  • His closing recommendation is to keep training models in Python but build agents and applications in TypeScript, citing Jeff Atwood's line that any application that can be written in JavaScript eventually will be.

“in just 1 year, it went from 1.6 million to 15.1 million downloads per week, which is between 9 and 10x in just 1 year”

said at 10:58

“keep training in Python. As I said, I don't see that's one going away soon. But please consider building the agents and the applications in TypeScript”

said at 13:33
