Your SaaS Bill Just Got a Second Meter. You're About to Pay It.

SpeakerNate B Jones · Nate B Jones Watchyoutu.be/adNErrz2aA0
Business & strategyAgents

If you only read one thing

  • Salesforce, Microsoft, and ServiceNow are each keeping the seat and turning on a second meter for agent work: Salesforce's AgentForce hit $800M ARR (up 169% YoY) billing by agentic work units, Microsoft's Agent 365 governance license runs $15/user/month (c1, c2).
  • SAP's 2026 API policy contractually restricts outside agents from planning or executing sequences of SAP API calls, so agent access to some enterprise systems is becoming a negotiated right, not a given (c4).
  • Before renewal: negotiate agent access before usage is mission-critical, demand exportable usage data and a fixed rate card, and ask whether the vendor lets you cut seats when an agent absorbs the work (c5, c6, c7).
01Three vendors, same move: keep the seat, add a meter

Salesforce reports AgentForce hit an $800 million ARR run rate, up 169% year-over-year, with 2.4 billion agentic work units processed and billing tied to those actions rather than tokens. Microsoft's Agent 365 went generally available at $15 per user per month, with a governance license that manages how agents act inside a Microsoft environment. Nate frames this as the same underlying move across vendors: the human seat stays, but a second meter for delegated agent work turns on alongside it.

02Token usage is scaling past what per-seat planning assumed

As evidence of how fast usage is climbing, Nate cites a developer who burned 8 billion tokens in a single month, a scale he says wasn't happening in 2025. He argues this makes it hard for builders and procurement teams to plan around a stable cost envelope when the underlying consumption keeps compounding.

“a developer just this past week who has used 8 billion tokens in the last month.”

03Some vendors are closing the door on outside agents

SAP's 2026 API policy draws a hard line on how customers and third-party systems can use SAP APIs, including restrictions on AI systems that plan, select, or execute sequences of API calls outside SAP-endorsed architectures. Nate's read: for agents touching SAP data, the first question becomes contractual, not technical.

“line around how customers and third-party systems can use SAP APIs.”

▶ watch at 06:38
04What to ask for, and when to ask it

Nate's checklist for a fair agent license includes exportable usage data and a rate card that can't shift mid-term. His procurement advice is to negotiate agent access before usage becomes embedded in daily workflows, since waiting until the agent is load-bearing removes your leverage. He also tells builders to explicitly ask vendors whether the commercial model changes when an agent reduces the number of human seats needed.

“Usage data needs to be exportable. The rate card needs to be exportable.”
