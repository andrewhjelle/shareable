CrabRAG: Why Automated Assistants Need Graph Memory, Not More Tokens

If you only read one thing

  • Markdown-file memory (used by Open Claw, Goose) makes agents reload large, repetitive context each round and can't capture relationships between facts (c1, c2, c3).
  • In a live A/B demo on a segmented home-lab network, a vector-store agent gave vague, unhelpful answers to two security questions while a Cogney/Neo4j graph-store agent gave precise, correctly-scoped answers using multi-hop traversal (c6, c7, c8).
  • Graph memory is explainable and auditable because you can inspect which nodes fed the answer, and Chin argues Claude can already write the Cypher and build the entity extractors needed to get started (c4, c5).

01Markdown-file memory hits a token ceiling
Slide at 03:20 · click any slide to enlarge · 8 more from this section below

Markdown-file memory hits a token ceiling

  • Chin describes common agent memory patterns (Open Claw's CLAUDE.md plus memory/tool/daily files, Goose's MCP memory server) as ultimately just markdown files on disk.
  • He says his own agents load at least 100k tokens per round because the pattern is to load everything in the hope something in it will be useful, which he calls repetitive and wasteful of context.

“It's very repetitive because they they basically load up everything in the hopes that something will be useful in the context.”

“if your whole memory is a bunch of markdown files, you're wasting a lot of tokens”

02Vector search finds similarity, not relationships
Slide at 08:20 · click any slide to enlarge · 8 more from this section below

Vector search finds similarity, not relationships

  • Vector databases (PGVector, LanceDB) let an agent store embeddings and pull back related information via similarity search, which Chin frames as an improvement over plain markdown recall.
  • But he says similarity in vector space is not the same as an actual relationship between facts, which produces hallucinations and breaks down on multi-hop reasoning chains.

“what vectors give you, which is similarity in vector space, is not the same as actual relationships. And so, you get hallucinations”

said at 08:17
03Head-to-head demo: vector store vs. graph store on a home lab
Slide at 13:30 · click any slide to enlarge

Head-to-head demo: vector store vs. graph store on a home lab

  • Chin built a digital twin of his home lab network as two memory stores from the same source markdown, one in a vector database and one in a Cogney-backed Neo4j graph, then queried both live and offline (no dynamic network access).
  • On a question about exposed end-of-life software, the vector agent said it couldn't find specific details, while the graph agent correctly named the exposed host and its outdated OS version.
  • On a second question about exposed management ports, the vector agent told Chin to go check the firewall config himself, while the graph agent named the two specific services (HAProxy and OpenVPN) actually exposed to the WAN.

“Couldn't find specific details. Excluded by policy for more precise information.”

04Graphs are auditable, and Claude can build them
Slide at 10:30 · click any slide to enlarge · 8 more from this section below

Graphs are auditable, and Claude can build them

  • Chin describes graph memory as accurate, explainable, and auditable because a developer can inspect the specific nodes and edges that produced an answer and adjust extraction or de-duplication if it's wrong.
  • He adds that a developer doesn't need to be a graph expert to start, saying Claude can write Cypher and build entity extractors well enough to get going as long as you know the basic data model you want.

“graphs are they're accurate. So, they give you very precise information. Explainable because you can look at the graph which got returned. And auditable because now you can actually say these are the this is the context.”

said at 10:52

“Claude can write Cypher better than I can. Claude can extract build entity extractors and it can do pretty much everything you need to do to get started with graphs today”

said at 11:23
05Why it matters past a home lab
Slide at 17:50 · click any slide to enlarge · 3 more from this section below

Why it matters past a home lab

  • Chin extends the demo's stakes to larger settings such as an enterprise data center or a financial services company's customer records, arguing that once the data no longer fits inside a roughly one-million-token context window, markdown-file memory isn't sufficient and a structured memory system is needed instead.

“if you're doing anything at at large scale where it doesn't fit into the 1 million context window of the modern models, you really need a better memory system than just throwing things in markdown files”

said at 17:41

Commentary (ours)

The demo is a compelling A/B illustration but it compares Chin's own graph-memory setup (built on his co-authored Graph RAG book and Neo4j's own Graph Academy content) against a comparatively unoptimized vector-store baseline, so the size of the gap shown here may not generalize to a vector store that's been tuned with better chunking or hybrid retrieval (ours).
