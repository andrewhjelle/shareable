Lays out Prime Intellect's open-source post-training stack (Verifiers V1, Prime RL) and gives concrete cost/throughput numbers for large-scale async RL runs, useful for deciding whether to build in-house RL post-training infrastructure v...

If you only read one thing

  • A full-scale async RL run on GLM-5 (28 nodes, 131K context, coding tasks) costs about $50K for a 1,000-step run over 3 days, which the speaker frames as cheap relative to typical enterprise token spend.
  • Async RL lets rollouts finish long after they start and still land in a training batch, with the team typically operating around 16 steps off-policy on average.
  • Verifiers V1 splits environments into a task set, harness, and runtime so any real coding-agent harness (Codex, Claude Code, custom Python) can be dropped into RL, eval, or SFT without modification.

02Environments now separate task, harness, and runtime
Slide at 08:10 · click any slide to enlarge

Environments now separate task, harness, and runtime

  • The overhauled Verifiers V1 library decomposes an environment into a task set (data and scoring rules, harness-agnostic), a harness (the agent loop, which can be a simple tool loop or a full CLI coding agent like Codex or Claude Code), and a runtime (where the harness executes, locally or in sandboxes).
  • This same environment definition is reused for evals, RL, SFT data generation, and on-policy distillation.

“evals are the thing that opens the door to post-training. And so environments and evals are essentially the same thing.”

said at 07:17
03On-policy distillation is used to build multi-skill models
Slide at 08:50 · click any slide to enlarge · 8 more from this section below

On-policy distillation is used to build multi-skill models

  • When a team wants one model to be good at several different tasks, the recommended pattern is to train separate RL experts on the same base model for each skill, then distill each expert back into a single checkpoint, which the speaker says is generally more reliable than training on everything at once.

“train individual RL experts on top of the same base model and then do distillation from those teachers into the same uh, checkpoint”

said at 07:48
04Reward shaping has to fight runaway chain-of-thought length
Slide at 18:30 · click any slide to enlarge · 8 more from this section below

Reward shaping has to fight runaway chain-of-thought length

  • Models will keep extending their reasoning chains if allowed, so reward design typically needs an explicit length penalty or conciseness bonus, computed using variance across multiple samples in a group rather than a fixed token target, since the right length is unknown up front and changes per problem and over training.

“models will love to like think and think and think if you let them”

said at 19:06
05Async RL scaling numbers
Slide at 30:00 · click any slide to enlarge · 8 more from this section below

Async RL scaling numbers

  • The team argues synchronous RL training is the wrong choice because it forces waiting on the slowest rollout; Prime RL is async from the ground up and tolerates rollouts finishing long after they start, averaging about 16 steps off-policy.
  • On a recent GLM-5 run, a training step across 28 nodes with 131K context took under 5 minutes, meaning 1,000 steps in 3 days at roughly $50K in rental compute -- expensive in absolute terms but comparable to a month of production token spend for many teams.

“some people I think have their reasons for wanting to do synchronous training. I don't agree with them.”

Commentary (ours)

The 16-step average off-policy tolerance is a concrete number worth tracking as a rule of thumb for how far async RL training can drift before instability -- if that number holds across labs it becomes a useful sanity check when evaluating other RL infra claims (ours).
