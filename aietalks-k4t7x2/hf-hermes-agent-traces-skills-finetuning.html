Self-Training Agents: Hermes Agent, HF Traces, Skills, MCP & Finetuning

SpeakerMerve Noyan · Hugging Face Watchyoutu.be/OV56RddyFuU

If you only read one thing

  • Hugging Face skills let an agent vibe-train or fine-tune a model end to end -- it calculates required VRAM, asks about instance size and validation split, then launches the job on HF infra.
  • A new 'traces' dataset repository type stores Codex, Claude Code, or Pi agent sessions in a parsed, explorable viewer, which can later be used to train a model.

01Open weights as an operating premise

The talk frames open source as differential for machine learning: open-weight models can be shrunk, quantized, and fine-tuned, and deploying them to edge devices or browsers keeps end-user data local. The speaker ties this to the recent, publicly visible Claude performance degradation as an example of why closed-model behavior can change without users knowing, and cites GLM 5.1 as an open model she uses in her own coding setup.

“it's absolute guaranteed privacy for your end user because you can deploy it to edge devices, browsers without the data going somewhere else”

“you see for instance the latest GLM 5.1 is absolutely crashing it and I'm actually using it in my coding setup”

02Vision capabilities and local serving are commoditizing

The speaker predicts labs will increasingly ship vision capabilities in open models on day zero, citing Gemini 4, Qwen 3.5, and Chimera 2.5 as recent vision-language releases. Running these locally now takes a few lines of code via vLLM, MLX, or llama.cpp/llama-server, and the Hub's GGUF hardware-compatibility data shows a quantized Gemma model fitting inside a 24GB L4 GPU at 4-bit.

“So I foresee that all of these models will be over time released day zero with vision capabilities.”

“the Gemma for larger model if you quantize it to four bit it fits inside an L4 GPU with the 24 gigabytes of VRAM”

03Hermes agent and traces

The speaker singles out Hermes agent, usable locally or via Hugging Face inference providers, as her preferred agent to pair with open models, recommending GLM 5.1 specifically. Separately, Hugging Face Hub added a 'traces' dataset repository type that stores parsed Codex, Claude Code, or Pi agent sessions, viewable in the dataset viewer and usable later for training.

“One of my most favorite things these days is Hermes agent, and I will just die on this hill.”

04Skills that train and fine-tune models

Hugging Face skills let an agent 'vibe train' a model on a chosen dataset with just a natural-language instruction. In a demo, asking Claude Code to fine-tune Qwen-2-VL on a vision-language dataset triggered the agent to ask about instance choice and validation split, then calculate the VRAM required for the given batch size before launching the job on HF infra.

“there is skills which allow you to even vibe train models.”

▶ watch at 05:46

“The model actually, like in the back end, the agent actually uh, calculates the amount of VRAM required to run”

▶ watch at 13:39
05Applying it: OCR at scale

As a worked example, a colleague's project OCR'd 30,000 Hugging Face papers using open OCR models run as jobs, all orchestrated through prompting: picking a benchmark-ranked OCR model, having the agent write the processing script, and having a skill handle instance sizing and cost estimation.

“So, we OCR 30 30,000 papers uh using Codex open OCR models and jobs all through prompting, which is a bit crazy.”

▶ watch at 16:49

Commentary (ours)

The through-line across the skills demoed (vibe-training, OCR-model selection, VRAM sizing) is that Hugging Face is positioning its skills as the layer that absorbs infra-selection judgment calls a practitioner used to make by hand -- worth checking how these skills behave when the recommended defaults are wrong, since the talk only shows success paths (ours).
