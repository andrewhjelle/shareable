Your Agent Didn't Fail. Your Harness Did.

SpeakerVinoth Govindarajan · OpenAI Watchyoutu.be/BInpv7lGp1o · 18 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. patternAgentic engineeringMemoryContext engineering

This talk gives a checklist of concrete failure modes and a five-question audit for anyone operating a production agent, using real OpenClaw GitHub issues as case studies

If you only read one thing

  • Core claim: most production agent failures are harness failures, not model failures; the most dangerous failure shape is a silent success, where the user-visible reply looks fine but the durable state was never recorded, leaving no error boundary to notice.
  • Using real OpenClaw issues, the talk documents five recurring failure modes: state holes (delivered but not remembered), overlapping writers (last-writer-wins silently erasing concurrent updates), dangling tool calls (the agent waits forever on an event that never arrives), approval drift (expired approvals treated as still valid), and missing edge proof (internal success without confirmed user-visible delivery).
  • Recommendation: audit one production agent trace with five questions -- what woke it up, what state did it inherit, what authority did it use, what executed, and what evidence survived -- because a transcript proves what the agent said, not what the system actually did.

01Silent success is the dangerous failure shape

Silent success is the dangerous failure shape

  • Govindarajan opens with an incident where an agent told a user it had recorded a refund for the next turn, the interface looked healthy, but the fact never persisted.
  • He argues this is worse than a crash because a crash gives a visible error boundary, while a silent success gives the user no reason to doubt the reply even though the system's state is now wrong.

“I want to convince you all that most of the production failures are not most of most of the agent failures are not model failures. Those are harness failures.”

The harness's production contract

  • He frames the harness's job with a three-part contract: the model proposes an action, the harness commits the state transition and checks authority, and a receipt proves what actually happened, distinct from the transcript of what the agent said.

“Here's a production contract for the talk. A model proposes the harness commits and the receipts proves it.”

03Five failure modes from real OpenClaw issues
Slide at 08:00 · click any slide to enlarge · 7 more from this section below

Five failure modes from real OpenClaw issues

  • Drawing on public OpenClaw GitHub issues, the talk catalogs: overlapping writers, where two correct operations both succeed but the second silently erases the first because last-writer-wins is not a consistency model; dangling tool calls, where a session has a tool call with no matching result and the run waits on an event that never arrives; approval drift, where an expired approval gets treated as still valid, showing that a model's request for an action is not the same as authority to execute it; and missing edge proof, where an internal component reports success but the user-visible surface never confirms delivery.

“Two correct rights can still produce one wrong outcome. and last writer wins is not a consistency model.”

said at 07:50

“In this dangling tool call issue, the session contains a tool call but no matching tool result. A process may have died. The connection may have dropped.”

“The general lesson is simple. Capability is not execution.”

04The five-question receipt audit
Slide at 14:10 · click any slide to enlarge · 4 more from this section below

The five-question receipt audit

  • Govindarajan closes with a recommended audit to run on one production agent trace: what woke it up, what state did it inherit, what authority did it use, what executed, and what evidence survived.
  • He argues these questions expose whether a fluent-sounding conversation actually corresponds to a correctly executed, provable production run.

“Here is the audit I want you to run when you get back to your team. Pick one agent system, not all of them.”

said at 14:08

Commentary (ours)

The talk builds its case entirely from public OpenClaw issues as a case study rather than the speaker's own production system, which makes the failure taxonomy broadly applicable but means the specific fixes described aren't verified against OpenAI's own internal agents.
