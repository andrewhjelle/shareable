patternCoding agentsAgentic engineeringProduct & UX

Describes a lightweight pattern for checking on and steering coding agents from a phone without abandoning an existing tmux terminal workflow or trusting a third-party relay server

If you only read one thing

  • Remobi is a progressive web app that runs a server on the user's own machine and mirrors an existing tmux session to the phone, rather than requiring a new mobile-specific workflow.
  • It's positioned against alternatives like Happy (Claude Code-only, relies on a relay server the speaker doesn't fully trust) and manual SSH terminal apps (key management, no touch controls for tmux).
  • Remote access defaults to Tailscale; the speaker warns that exposing the server directly to the public internet is a compromise waiting to happen.

The problem: wanting to check on agents without a new app

  • The speaker built Remobi because he wanted to check on and steer running coding agents from his phone but didn't want to adopt a dedicated tool.
  • He contrasts it with Happy, which supports Claude Code only and uses a relay server he isn't sure he trusts, and with Claude Code's built-in manual session handoff, which requires manually switching and doesn't support other agents like Codex.

tmux as the underlying workflow

  • His own setup runs multiple coding agents at once inside tmux panes on a remote dev machine he SSHes into, with custom key bindings and status-bar widgets he built without knowing tmux internals, generating the configuration through an agent instead.
  • Remobi is designed to plug into this existing tmux setup rather than replace it.

How Remobi works on mobile

  • Remobi is a progressive web app (works on iOS and Android) that talks to a server the user runs on their own machine, showing the same tmux panes and windows with touch gestures (double-tap to zoom into a pane, scroll within panes).
  • The installer sets up a skill that either configures tmux for a new user or maps Remobi's touch controls onto an existing tmux setup.

Remote access and security tradeoffs

  • Remobi connects the phone to the home server over the internet, defaulting to Tailscale, though Cloudflare tunnels or ngrok can be substituted.
  • The speaker states plainly that exposing the server directly on the public internet compromises the machine, putting the security burden on the user's choice of tunnel.

“if you If you If you just put it on the public internet, you've pwned your computer”

“I use Tailscale to do it, but you could use Cloudflare tunnels, ngrok, whatever you like”

Commentary (ours)

The 'don't change your workflow' framing is the interesting part -- most mobile-agent tools ask you to adopt their session model, while this one treats tmux as the source of truth and mirrors it, which is a smaller trust surface if you already live in tmux (ours).
