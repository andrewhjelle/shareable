01Snorkel's data-quality thesis applied to agentic tasks

Snorkel, founded in 2019 out of a Stanford AI research lab, has centered its work on the claim that data quality is critical to model outcomes. This talk extends that thesis into the agentic space, treating task quality and data quality as effectively the same problem when building terminal-bench-style containerized agentic tasks for training and evaluation.

“the core thesis has been that the quality of data is critical and that you the data that you're looking at you want to make sure is is top quality”

02What counts as a quality task

Snorkel defines task quality around four criteria drawn from environments like Harbor and OpenEnv: the task is achievable, non-trivial, functionally correct (the logic behaves as expected), and the environment itself is reliable. Tasks that pass all four tests are 'accepted' and used for training; tasks that fail any of them are 'rejected.'

“that the task is achievable, that is non-trivial, uh, that is functionally correct, that the logic actually plays as expected, and then the environment itself is reliable.”

▶ watch at 03:38
03Accepted tasks are harder, and fail more meaningfully

Testing accepted versus rejected tasks against Sonnet 4.5 and Codex-family models, Snorkel found accepted tasks averaged twice as many tool calls, lower pass rates, and more output tokens, indicating genuinely harder tasks rather than noise. Breaking failures into categories (e.g. logic error vs. incomplete task vs. environment problem), the team found accepted tasks produce 'cleaner' failures -- ones caused by real task difficulty rather than broken or underspecified environments.

“we found that uh our accepted tasks averaged twice as many tool calls, uh, demonstrating more difficulty, more steps needed, and, uh, and more engagement with the external tools.”

“the accepted tasks are producing cleaner failures. These are failures due to the task itself being more difficult, truly more difficult that that the steps that it needs to to accomplish are are more difficult”

04Same model, same compute, 5x the improvement from quality alone

Snorkel ran an RL training run with identical model, compute budget, and task count, differing only in whether the task set was accepted (high quality) or rejected (low quality). The low-quality task set improved the base model by about 1%; the high-quality set improved it by about 6%, a roughly 5x difference attributable to task quality alone.

“the low-quality tasks only improved the base model by about 1% improvement, but the improvement was about a 6% improvement with the higher-quality tasks.”

“that uplift of the 5x uplift difference based on on on on just quality is really striking from our point of view.”

05How Snorkel keeps quality high

Snorkel attributes its ability to filter for quality to keeping human domain experts in the loop when generating tasks and data. In Q&A, the speaker identified underspecified test definitions -- where the expected outcome isn't stated up front but backend tests check for unstated requirements -- as a leading cause of rejection, and described a platform combining human annotators with LLM judges against shared rubrics to scale quality assessment and track inter-annotator agreement.

“we have a strong feeling that the expert in the loop is an important element of delivering data quality.”

Commentary (ours)

A 5x swing in RL improvement from task-set quality alone, with model and compute held fixed, is a bigger lever than most teams spend time on -- it suggests that curating/rejecting training tasks may matter more than swapping base models or tuning hyperparameters for agentic RL, though the result is self-reported on Snorkel's own acceptance criteria rather than an independently replicated benchmark (ours).
