Ship Real Agents: Hands-On Evals for Agentic Applications

SpeakerLaurie Voss · Arize Watchyoutu.be/Xfl50508LZM · 124 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Quotes are verbatim from the talk transcript with the time they were said.
patternEvals & benchmarksAgentic engineeringCoding agents

A live-coded eval workshop (Claude Agent SDK + Arize Phoenix) that shows concretely when a cheap deterministic code eval is enough versus when an LLM-judge eval is needed, and why two different built-in judges can disagree completely on ...

If you only read one thing

  • In a live demo, a simple deterministic code eval (checking whether the agent's report mentioned the requested stock ticker) caught a real failure a skim wouldn't: the agent tried to write its report to disk as if it were Claude Code, and the eval passed only 11 of 13 test cases.
  • Two built-in LLM judges gave opposite verdicts on the same 13 outputs: a correctness evaluator scored 0 of 13 because the judge model's training cutoff made it treat the agent's 2026 financial figures as implausible, while a faithfulness evaluator (checking outputs against the agent's own research) scored 13 of 13.
  • Citing an Anthropic case where Claude Opus initially scored 42% on the CoreBench benchmark because the eval rejected the answer 96.124991 as wrong when the target was 96.12 (fixing the eval raised the score to 95%), the talk argues judge quality should be benchmarked against human inter-rater agreement -- often as low as 0.2 to 0.3 -- rather than against perfection.

02Two built-in LLM judges disagreed completely

Two built-in LLM judges disagreed completely

  • A built-in correctness evaluator scored every one of the 13 outputs as incorrect; reading the explanation showed the judge model assumed it was still 2025 (its training cutoff) and flagged the agent's forward-looking 2026 figures as implausible.
  • Swapping to a faithfulness evaluator, which checks the report against the agent's own research output rather than the judge's world knowledge, scored all 13 as faithful.

“the output presents highly specific financial figures for Q1 financial year 2026, uh, but the problem that it keeps having is that it thinks it's 2025 because it is a model trained in 2025”

03Judging the judge

Judging the judge

  • The talk argues that LLM judges should be checked against a human-labeled golden data set, and that the bar for agreement should be human inter-rater reliability, which is often only 0.2 to 0.3, not 1.0.
  • It cites an Anthropic case where Claude Opus scored 42% on the CoreBench benchmark because the eval was overly strict about numeric precision (rejecting 96.124991 against a target of 96.12); fixing the eval raised the measured score to 95%.

“inter-rater reliability is often as low as 0.2 or 0.3 of the time. Uh so two experts, the same output, the same rubric, and they will disagree.”

04Sizing the eval suite and prioritizing fixes

Sizing the eval suite and prioritizing fixes

  • For estimating how many test examples are enough, the speaker gives a concrete confidence-interval calculation: 200 samples at a 3% observed defect rate produce a 95% confidence interval of roughly 0.6% to 5.4%.
  • He also presents an impact hierarchy for where to spend fix effort, ranking data-quality fixes above prompt changes, model selection, and hyperparameter tuning.
