Your Voice Agent Doesn't Need a Frontier Model

SpeakerJoel Allou & Ornella Bahidika · Microsoft Watchyoutu.be/fnLBmfsI_Fg
Voice & realtimeAgentic engineeringInfra & serving

If you only read one thing

  • Voice agents need to start talking in about 950ms or the pause reads as broken; a frontier model that reasons for a full second has already lost the room regardless of answer quality (c1).
  • Ace extracts all lesson-tracking, student-modeling, and next-step decisions out of the model into a state machine, handing the model only a per-turn summary so it only has to talk (c2).
  • A side-by-side demo showed Opus 4.7 taking multiple seconds to reason through an answer versus Haiku 4.5 with the scaffolding responding in about 900 milliseconds (c3, c4).
01The latency budget is milliseconds, not IQ

The speakers frame the design constraint for a voice product as latency rather than intelligence: a voice agent needs to start talking in about 950 milliseconds, and a frontier model that spends a full second reasoning has already lost the user's attention no matter how good the eventual answer is.

“The AI model need to start talking in about 950 milliseconds. A frontier model that think for a full second has already lost the room”

▶ watch at 00:33
02The model only talks; everything else is extracted

Ace's model doesn't decide what happens next in the lesson, doesn't track what the student knows, and doesn't explain what's next itself; a separate system handles those functions and hands the model a summary each turn so the model's only job is speaking.

“It doesn't track what the student knows. It doesn't explain what's next. We have a system in place to do that, and they hand the model a summary every turn”

▶ watch at 01:08
03Demo: frontier reasoning latency vs. scaffolded small model

A side-by-side demo showed Opus 4.7 answering a simple question by visibly reasoning for multiple seconds before responding, versus the same question run on Haiku 4.5 with the team's scaffolding, which answered in about 900 milliseconds.

“answer comes in about 900 milliseconds. And so that's the beauty of building around the model”

▶ watch at 03:40
04The scaffolding is the real cost, paid once

The speakers acknowledge the approach isn't free: a small model like Haiku 4.5 without scaffolding drifts on long structure and needs strict rules to stay organized, but that scaffolding cost is paid once in code rather than on every conversational turn.

“A small model like the Haiku 4.5, if it doesn't have any scaffolding, tend to drift on long structure and really needs strict rules in order to be able to stay organized”

▶ watch at 04:12
05The rule: pick the fastest model your budget allows

The stated rule of thumb is to pick the fastest model the latency budget allows, then spend the remaining engineering effort building the scaffolding (state machine, reasoning process, scenario handling) around it rather than relying on a larger model to reason its way through.

“Pick the fastest model that your latency budget allows and then spend the rest of your time actually building the scaffolding”
