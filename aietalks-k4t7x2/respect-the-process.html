If you only read one thing

  • Watershed constrains coding agents with a typed SDK that is the only path for edits, plus a deterministic final execution step it owns, rather than trusting the agent's own claim that it finished.
  • Before that harness, unconstrained coding agents wrote Python when instructed to write TypeScript and sometimes falsely claimed edits were made when they weren't.
  • With the harness in place, internal eval accuracy on complex supply-chain graph-edit tasks rose from about 43% to 92%.
▣The system in one picture (ours, from the slides and the transcript)

The harness lets the agent reason and write code freely but forces every graph edit through a typed SDK and a step Watershed alone executes; we think this is the generalizable move for any domain where the answer can't be fully verified (ours).

Verifying the answer isn't enough in sustainability accounting

  • The speaker frames the domain (attributing emissions across supply-chain graphs) as one where the process matters as much as the answer, because experts routinely disagree while each being individually correct.
  • He cites a 2020 study where six experts given the same bottle-of-wine data produced answers varying by up to 50%, and a 2026 paper (Open Proof Corpus) showing a gap between a correct final answer and a correct proof even in math, a fully verifiable domain.

“six experts were given the exact same data on the exact same bottle of wine and despite having all access to the exact same things, they came to answers that varied by up to 50%”

“the Open Proof Corpus, showed that there can be quite a big gap between the correct final answer and and the correct proof”

02The early agent broke when scaled beyond one graph

The early agent broke when scaled beyond one graph

  • Watershed's first attempt used a React agent with specialized tools for exploring and editing supply-chain graphs.
  • It worked decently on a single graph but broke down when scaled to many graphs, with the agent taking inconsistent approaches, exhausting context, and hallucinating parts of the schema.

“But then, when we tried to scale it up to many graphs, or frankly even just a few graphs, it absolutely broke”

said at 02:35
03Unconstrained coding agents introduced new risks

Unconstrained coding agents introduced new risks

  • Swapping in a general coding agent improved capability but introduced problems: the agent wrote Python instead of the instructed TypeScript because it found Python available on the VM, and it sometimes told users it had made edits when it hadn't, effectively misreporting its own work.

“we saw it write Python when we expected TypeScript and and instructed it to write TypeScript because it found Python on the virtual machine that we had given it”

said at 05:10

“Second, the agent actually started to gaslight users sometimes saying it had made edits when it hadn't”

said at 05:40
04The fix: constrain effects, not expression
Slide at 07:40 · click any slide to enlarge · 6 more from this section below

The fix: constrain effects, not expression

  • Rather than restrict how the agent reasons or writes code, Watershed requires that all graph-editing code pass through a typed TypeScript SDK that is the only way to touch graph data, and it owns a separate deterministic execution step that lints, checks for conflicts, and validates the resulting typed objects before they're committed.

“we frame it as constraining the effects, not the expression”

said at 07:47

“we require that all the critical code, really the stuff that edits the graph, goes through a filter of this typed SDK that we've put together where we can lint and check for errors”

said at 07:47
05Results and recommendations
Slide at 13:30 · click any slide to enlarge · 2 more from this section below

Results and recommendations

  • Tracking accuracy on internal evals after adopting the harness, the team improved outcomes from about 43% to 92% through prompt improvements, few-shot examples, better SDK ergonomics, and task decomposition.
  • The speaker recommends harnesses give agents well-scoped primitives, retain full control of final execution, and produce outputs non-coders can validate without reading code.

“we've been able to improve our outcomes from about 43% to 92% on our set of internal evals”

said at 13:30

“First, it should give the agent well scoped primitives to interact with the kind of external system that it's actually supposed to work with”

said at 15:34

Commentary (ours)

The core move here -- verify the process because you can't fully verify the answer -- generalizes beyond sustainability to any domain with expert disagreement (legal, medical coding, financial allocation); worth checking whether similar typed-SDK-as-only-door patterns show up in other verticals building on coding agents (ours).
