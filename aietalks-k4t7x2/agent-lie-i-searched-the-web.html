Your Agent's Biggest Lie: "I Searched the Web"

SpeakerRafael Levi · Bright Data Watchyoutu.be/btxGmN8RvNU · 15 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. takeWeb automationAgentic engineeringSecurity

Shows a live head-to-head demo of an LLM without web tools fabricating results on five real anti-bot-protected sites (LinkedIn, Amazon, Instagram, TikTok, Rightmove) versus succeeding with a scraping MCP

If you only read one thing

  • LLMs without real web access will fabricate search results, citations, and product links rather than admit failure, because they're optimized to please users.
  • Live demo: GPT-5 without an MCP scored zero of five successful site accesses (Rightmove, LinkedIn, Instagram, Amazon, TikTok); the same prompts with Bright Data's MCP succeeded on the sites shown.
  • Cloudflare's AI Labyrinth traps detected bots and feeds them fake data instead of blocking them outright, compounding hallucination risk for agents that don't detect the trap.

01Why agents fabricate web results

Why agents fabricate web results

  • The speaker argues LLMs are tuned to please users and rarely say 'I can't,' so when a request is blocked (CAPTCHA, empty page, anti-bot wall) the agent invents an answer instead of reporting failure.
  • He cites roughly 60% of ChatGPT citations not resolving and users being sent links to products that don't exist.

“LLMs are programmed to please people, please users. So they make enough things and this is the biggest issue right now I'm seeing with LLMs”

Live demo: five sites, no MCP vs. with MCP

  • Running identical prompts against Rightmove, a LinkedIn company page, Instagram, Amazon, and TikTok, GPT-5 without web tools failed on all five with no live web access.
  • The same prompts run through Bright Data's MCP (66 tools including search engine, markdown scraping, batch search, and a fingerprinted scraping browser) succeeded on the sites demoed live (Rightmove, LinkedIn, Instagram, Amazon product).

04How the MCP avoids detection and stays legal
Slide at 08:10 · click any slide to enlarge · 8 more from this section below

How the MCP avoids detection and stays legal

  • The scraping browser mimics human behavior (pre-recorded mouse movement, human-like typing) so Cloudflare doesn't trigger a bot challenge, and has built-in CAPTCHA solving.
  • The company restricts itself to publicly available data and does not scrape behind logins, which it considers illegal under typical terms-of-service agreements, citing ongoing lawsuits from LinkedIn and Amazon against scrapers.

“there's mouse movement pre-recorded, there's typing when it types it's like it's uh mimics a real human behavior”

said at 10:59

“we only deal with public data. So, when you guys are using us, you are”

05Practical tool-loading and cost guidance
Slide at 13:10 · click any slide to enlarge · 5 more from this section below

Practical tool-loading and cost guidance

  • Asked whether an agent needs all 69 exposed tools, the speaker recommends loading only the 2-3 needed (e.g., scrape-as-markdown and search) to avoid flooding context with irrelevant tool definitions.
  • The free tier allows 5,000 requests per month, framed as sufficient for an MVP or small experiment, with pay-as-you-go available beyond that.

“if I need just to scrape markdown and search, I would just literally load two tools. Uh otherwise you're flooding contacts with irrelevant data”

said at 13:33

Commentary (ours)

The framing that hallucination is often a masked tool-failure rather than a model-reasoning failure is a useful diagnostic lens -- worth checking whether other 'agent lied to me' complaints in the wild trace back to the same silent-block pattern rather than genuine reasoning errors (ours).
