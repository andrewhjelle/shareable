01The hardware: unified memory, not just more GPU

The hardware: unified memory, not just more GPU

  • DGX Spark (referred to in the talk's audio as "Jetson Spark") is built around the GB10 Grace Blackwell superchip, combining CPU and GPU in a unified memory architecture with 128GB of memory, which the presenter says lets developers run models up to roughly 200 billion parameters locally on a desk-sized system.
  • It runs the same NVIDIA AI software stack used in production, intended to let workflows move from desktop to data center with minimal changes.

“It's powered by the GB10 Grace Blackwell superchip, combining CPU and GPU with a unified memory architecture.”

02Throughput measurements across model sizes and quantization

Throughput measurements across model sizes and quantization

  • Using an automated benchmarking harness (Docker isolation, three warm-up runs, 1-second GPU metric logging) serving models through vLLM, the presenter measured completion tokens/sec across a 1.5B to 14B range.
  • The 1.5B instruct model delivered 61.73 tokens/sec; a 14B model quantized to NVFP4 (4-bit floating point) still reached 20.19 tokens/sec despite being nearly 10x larger, while the same 14B model unquantized dropped to 8.40 tokens/sec.

03Quantization's effect on responsiveness (time to first token)

Quantization's effect on responsiveness (time to first token)

  • The presenter separates raw throughput from time-to-first-token (TTFT), calling TTFT the metric that defines perceived responsiveness.
  • The NVFP4-quantized 14B model was measured at 3.4x faster time-to-first-token than the same unquantized 14B base model, which the presenter attributes to NVFP4 increasing "intelligence per byte" moved rather than to raw compute.

04Capacity vs. bandwidth, and when to use it locally

Capacity vs. bandwidth, and when to use it locally

  • The stated key takeaway is that memory capacity (fitting a large model) and memory bandwidth (how fast data can be moved to feed compute) are separate constraints; the 128GB unified memory fits large models, but bandwidth still governs throughput.
  • The presenter recommends the local setup for steady-state workloads, privacy-sensitive data, and rapid prototyping, with the option to scale the same stack out to cloud or data center once ready.

“A key takeaway here from this data is that memory capacity is not the same as the memory bandwidth.”
