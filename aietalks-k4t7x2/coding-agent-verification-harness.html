Your coding agent doesn't always follow your rules

SpeakerTalha Sheikh · Checkout.com Watchyoutu.be/MpZzWMdmQCE · 10 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Slides below are frames from that recording, reproduced for reference and study; rights remain with the speaker and the conference. patternCoding agentsAgentic engineeringEvals & benchmarks

Argues that instructions and specs, no matter how good, don't guarantee a coding agent actually did the task, and that deterministic post-hoc verification (via hooks) is the missing layer

If you only read one thing

  • Giving an agent more or better instructions is not the same as verification; the speaker built a tool (Vector) that deterministically checks Claude's output via hooks after each session.
  • Verification guardrails reportedly let smaller/cheaper models (like Haiku or open-source) reach usable output, trading model cost for harness investment.
  • The speaker frames this as an industry-wide pattern: Anthropic, OpenAI, and others are each building their own verification/harness layers, so it needs to become a shared, language-agnostic contract.

01The problem: agent says done, but is it done right
Slide at 01:10 · click any slide to enlarge

The problem: agent says done, but is it done right

  • The speaker describes repeatedly telling Claude Code to fix issues after it reported a task complete, concluding that he was acting as the deterministic enforcement layer himself, manually checking whether output matched what he actually wanted.
  • He built a tool called Vector that uses Claude hooks to automatically check output whenever a session finishes, retrying with feedback until defined test cases pass.

“So, what that means is like I am the enforcement. I am the enforcement layer. I have to tell Claude on what exactly you need to do and how exactly this needs to be enforced”

said at 01:03

“I built my own vector, I call it my own product called vector V1, and it deterministically checks Claude's output”

said at 01:34

An Anthropic engineer said future models won't need this

  • After presenting Vector at events, an Anthropic engineer told the speaker that future, smarter models/agents would remove the need for external enforcement, citing a project (referred to as Project Methuselah) meant to be capable enough to solve tasks without it.
  • The speaker's response is that increased model capability is not the same as increased reliability, and that better instructions, specs, or context still isn't the same thing as verification.

“doesn't it increases in capability, but that's not necessarily the same thing as reliability. Sure, the models make it may become a lot more capable, but are they more reliable”

“in giving thought instructions is not the same thing as giving it verification. So, you can give as much instructions as you want, very good instructions, very little instructions, but you still will need to verify”

03Guardrails can let you use cheaper models
Slide at 07:00 · click any slide to enlarge

Guardrails can let you use cheaper models

  • With enough deterministic guardrails, the speaker argues a smaller model like Haiku or an open-source model can reach a usable output, whereas a frontier model like Opus without guardrails is the most expensive path.
  • Adding more guardrails means investing more time in the harness itself but can reduce inference cost.

“if you use a frontier model like an Opus Opus model that can get you a task, okay, cool, that will be the most expensive one. You can have Vector with a little bit of guardrails, but it gets you a little bit cheaper”

said at 04:38
04Everyone is building their own enforcement pattern
Slide at 07:40 · click any slide to enlarge · 2 more from this section below

Everyone is building their own enforcement pattern

  • Talking to more people, the speaker found that Anthropic, his own company, Meta, and others were each building separate enforcement systems, which don't transfer between organizations.
  • He argues the pattern needs to be language-agnostic and runnable at multiple points: mid-conversation, at conversation end, before commit, inside multi-agent workflows, on async operations, or via an LLM-as-judge check.

“Anthropic is building their own stuff. My company is building their own stuff about enforcement. Facebook is building their own stuff. Meta is every company is building their own thing”

said at 05:39

“it has to be language agnostic. It has to be something that I can be shared by everybody else, and everybody can bring their own version of enforcement to it”

said at 06:10
05Industry examples and the shift from coding to verifying
Slide at 07:50 · click any slide to enlarge · 3 more from this section below

Industry examples and the shift from coding to verifying

  • The speaker cites Anthropic's 'executor advisor pattern' (one agent codes, another advises/verifies), OpenAI's harness engineering, and companies like Cudo doing comprehensive automated code review as instances of the same feedback-loop idea.
  • He summarizes the shift as: the value used to be seen as the code produced, but is now in the verification system designed around it.

“what we thought was like the value is in the code that we create. But it's actually now in reality is what we're seeing here is the verification that we design”

said at 08:14

Commentary (ours)

The claim that guardrails let you drop to a cheaper model is asserted from personal build experience rather than a controlled comparison, so treat the cost-savings framing as directional, not measured (ours).
