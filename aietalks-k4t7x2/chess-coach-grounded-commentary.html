If you only read one thing

  • LLMs hallucinate at chess on their own, so the app grounds commentary in Stockfish evaluations, positional/tactical detectors, and a human-move-probability model (Maya) rather than letting the LLM reason freely.
  • Bad commentary reports flow from the app through Slack into a running Cloud Code session via an MCP-based 'channel', which runs a triage skill before a human signs off on the PR.
  • Sub-3-second latency using Gemini 3 Flash is a hard product constraint; across 16 eval scenarios Gemini Flash passes about 75%, Claude with more thinking about 60% but slower.

Why LLMs can't play chess on their own

  • The speakers trace chess-AI history from Claude Shannon's 1949 type-A/type-B engine framing through Deep Blue and AlphaZero to LLMs, which they say hallucinate when playing chess directly, illustrated by a Kaggle Game Arena tournament where Grok lost badly.
  • They note this isn't an architectural limit: DeepMind trained a transformer to predict position evaluations instead of next tokens, reaching grandmaster strength, but such models aren't trained on language and can't explain their moves.

“and people started playing chess against the LLMs, and quickly turned out that they can't really play chess.”

Grounding commentary in Stockfish, detectors, and a human-move model

  • The game-review pipeline runs Stockfish for the objective best move, then extracts tactical and positional context (forks, pins, skewers, doubled pawns) via custom detectors.
  • It also uses Maya, a University of Toronto research model that predicts the probability distribution of moves a human at a given rating would actually play, to judge how hard a move is to find.
  • All of this structured data is fed to the LLM, whose job is restricted to translating it into English rather than reasoning about the position itself.

“the LLM's job is only to translate this information uh into English, because we really don't want it to try to figure out too much on its own, because it quickly leads to hallucination.”

said at 08:18

“they have trained a chess engine, uh it's a neural network that predicts the moves that humans would play in certain positions.”

03Closing the loop with an autonomous coding agent
Slide at 10:20 · click any slide to enlarge · 4 more from this section below

Closing the loop with an autonomous coding agent

  • When a user flags commentary as bad in the app, the report posts to Slack and is injected into a persistent Cloud Code session through a 'channel', described as a research-preview MCP server for injecting events into a running session.
  • The session runs a commentary-triage skill that investigates the position, can modify prompts or detectors, regenerates commentary, and asks the developer questions in Slack before a PR is submitted and merged from a phone.

“Channel is a new feature in the research preview that is essentially an MCP server that can inject events into a running Cloud Code session.”

said at 10:19

“It runs a commentary triage skill that we created that outlines its process how it should go about to investigate what's going what's wrong in the position.”

04Latency vs. quality trade-offs for a consumer app

Latency vs. quality trade-offs for a consumer app

  • Because users expect near-instant feedback after finishing a game, the team targets sub-3-second generation and uses Gemini 3 Flash, citing roughly a 1-second time-to-first-token and about 3-second end-to-end latency on average.

“So we we're aiming for sub 3 seconds to generate our coach sort of feedback. How do we do this? We use Gemini 3 flash.”

05Evaluating commentary quality across models
Slide at 14:00 · click any slide to enlarge · 8 more from this section below

Evaluating commentary quality across models

  • The team built 16 chess scenarios covering tactical patterns, blunders, and hallucination limits, run across models via OpenRouter and graded against the two speakers' own chess judgment.
  • Gemini Flash passes about 75% of scenarios, Claude with more thinking gets under 60% with much longer latency, and GPT-5 mini trades lower latency for lower accuracy.
  • A general lesson offered is to keep the data-extraction pipeline separate from language generation.

“Currently we have 16 different scenarios that we created. These are around themes like tactical patterns, blunders, and sort of limiting hallucination.”

“we we ran all three models Gemini, Cloud, and and GPT-5 and you know typically Gemini flash is about 75%.”

“Number one, you really important to separate that sort of data pipeline from the language generation.”

Commentary (ours)

The team treats the LLM strictly as a translation layer over deterministic chess analysis rather than a reasoning engine, which sidesteps the hallucination problem other LLM-chess demos hit -- this pattern (symbolic backend + LLM-as-narrator) is likely reusable for other domains where an LLM's job is to explain a decision made by an existing expert system (ours).
