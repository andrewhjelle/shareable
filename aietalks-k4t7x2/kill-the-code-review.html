How to Kill the Code Review

SpeakerAnkit Jain · Aviator Watchyoutu.be/YgEv7IQzGdM
Coding agentsAgentic engineering

If you only read one thing

  • Code churn is up 861% and over 30% of changes now merge with no review at all, while review wait times have grown 4x. (c1,c2,c3)
  • AI reviewing AI-written code with nobody actually reading the output just relocates the bottleneck; the fix is reviewing captured intent and evidence, not the diff. (c4,c7)

01Review is now the bottleneck

Code volume is growing faster than teams can review it: code churn is up 861%, the incident-to-PR ratio is rising, and review wait time has grown roughly 4x. Over 30% of changes today merge without any review at all.

“There is 861% code churn. That means we are like producing more code.”

02AI reviewing AI, nobody reading

Teams already run AI code review tools in the PR UI, but the human in the loop is often just skimming and merging once the AI signs off. Jain calls this a misconfiguration: when AI reviews and nobody reads, the process has been set up wrong.

“when AI reviews and nobody reads, we have configured the wrong thing”

▶ watch at 02:35
03Why spec-driven development falls short

Spec-first workflows (write the spec, hand it to an agent, verify the output) repeat the 1970s waterfall model's flaw: no feedback loop. Issues surface only during implementation, the spec never gets updated, and because LLMs aren't deterministic, the code still diverges from what was specified.

“spectrum development is a great uh methodology, but it falls short in day-to-day software development.”

▶ watch at 05:12
04Building an AI slop registry

Recurring review comments should be codified into a registry that automatically flags the same issue in future PRs instead of requiring a human to write the comment again. Jain's homework for the audience: mine your last 1,000 review comments and build a registry from the ones that repeat.

“Every recurring comment is now a guardrail that you don't have to review again.”

▶ watch at 07:49

“Go home and mine your last 1,000 review comments and build out a AI slot register for the things which are repeatable.”

▶ watch at 14:12
05New review surface: intent, not diff

In the system Jain's team is building, session interactions with the coding agent become acceptance criteria, which combine with the slop registry to generate a test plan; a verification system runs that plan and produces evidence. Reviewers then evaluate that evidence and the architectural decisions, not the line-by-line diff.

“now reviewers are reviewing the intent, not the diff.”

▶ watch at 13:08

Commentary (ours)

The shift from diff-review to intent-review assumes the captured session (prompts, acceptance criteria) is a reliable record of what was actually decided; whether that holds under real engineering time pressure, versus decisions made verbally or async, is the open question the talk doesn't fully address (ours).
