If you only read one thing

  • The 'one developer, two dozen agents' vision assumes software is built by individuals, but as implementation gets fast and cheap, agreeing on what to build becomes the real bottleneck, and most coding agents' local plan mode is 'completely unshared with other people.'
  • This causes coordination debt -- agents touching the same files, developers duplicating work -- even as teams now report 'shipping five features a day instead of half of one.'
  • GitHub Next's prototype ACE puts multiplayer chat, shared micro-VM coding sessions, and collaborative plan editing under one roof so non-developers can align with agents before and during implementation, not just at PR review.

The single-player agent assumption

  • The speaker frames the 'one person with a fleet of terminal agents' image of peak productivity as flawed because it assumes software is built by one person.
  • Believing individual output alone leads to great software is compared to '9 women make a baby in one month' logic -- more individual output doesn't fix problems that require communication and coordination, it makes them worse.

02Alignment, not implementation, is the bottleneck
Slide at 02:20 · click any slide to enlarge · 2 more from this section below

Alignment, not implementation, is the bottleneck

  • With implementation now fast and cheap, the speaker argues the hard question shifted from how to build something to whether to build it, making team agreement on what to build the new bottleneck.
  • But the collapse of the implementation window means teams think they no longer need to plan, so early alignment touchpoints (Slack threads, draft PR discussions) disappear.

“The hard question is no longer how to build it, it's should we build it? Agreeing on what to build is the new bottleneck”

said at 02:32

“that implementation window has now collapsed. And because implementation is no longer as expensive and time-consuming, we think we don't need to plan as much. So most of those early touchpoints actually disappear”

03What gets lost: unshared plans and coordination debt
Slide at 04:40 · click any slide to enlarge · 3 more from this section below

What gets lost: unshared plans and coordination debt

  • Most coding agents have a local plan mode that stays completely unshared with teammates, so no one vets the plan before it ships.
  • The result is coordination debt: hairy merge conflicts from agents touching the same files, and developers duplicating work because two people picked up the same task independently.

“Unhelpfully, most coding agents also have this local plan mode that is completely unshared with other people”

said at 04:36

“And also coordination debts. This is when you get really hairy merge conflicts because agents will touch in the same files or developers even doing duplicated work because they both picked up a thing and tried to finish it in one day”

said at 05:08
04ACE: a shared multiplayer coding environment
Slide at 06:40 · click any slide to enlarge · 8 more from this section below

ACE: a shared multiplayer coding environment

  • GitHub Next's research prototype, ACE (Agent Collaboration Environment), is a multiplayer chat-like interface where each session is backed by its own micro-VM and Git branch, letting teammates and agents work in a shared sandboxed environment rather than isolated local terminals.

“we've been building a new research prototype that explores how we might solve some of these problems. It's called ACE, stands for Agent Collaboration Environment”

said at 06:40

“Each session is more than a chat channel though. It is also backed by a micro VM”

Faster output raises the bar on craft
