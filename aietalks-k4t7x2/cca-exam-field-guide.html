Anthropic's CCA Exam as a Field-Guide for Agentic Engineering

01What the exam covers

The Claude Certified Architect exam, released in March, is scenario-based, timed, and proctored; individuals can pay $99 to take it once every six months. It scores five weighted domains -- agentic architecture (27%), Claude Code configuration (20%), prompt engineering/structured output, tool design and MCP integration, and context management/reliability -- drawn from six production scenarios, four of which are randomly selected per sitting.

02Anti-pattern: skipping the stop-reason check

In the customer-support-agent scenario, the anti-pattern is letting an agent's tool-use loop run and using its output without checking why the model stopped. Because the model itself cannot execute tools -- it only proposes parameters for your code to run -- the loop must branch on the stop reason (tool-use vs. end-of-turn vs. out-of-tokens) to know what to do next.

“What you want to do is you want to loop with something called the stop reason”

▶ watch at 07:48

“The problem is the LLM can't do anything. It is just a probabilistic next word predictor. It can't execute tools.”

▶ watch at 08:50
03Anti-pattern: one overloaded agent instead of specialists

In the multi-agent research scenario, the anti-pattern is a single agent loaded with every available tool. Coyle recommends narrow, single-purpose sub-agents instead, each given only the slice of claim/evidence it needs -- both to keep context (and cost) down and because agents pooling full context and reasoning traces tend toward group-think, converging on one idea rather than critiquing independently.

“No, no, don't put everything in there. Limit what's going to go in there because then you're going to get a much more accurate system.”

▶ watch at 14:02

“there's a tendency to have group think. And all the agents seem to kind of devolve into one idea.”

▶ watch at 15:02
04Managing context and cost at scale

For developer-productivity and CI scenarios, the fix for unbounded context growth is to fork sub-tasks into separate threads and return only a summary to the main context, with an automatic compact triggered once token count crosses roughly 150,000. For non-interactive CI pipelines, batch mode trades a guaranteed same-day turnaround (up to 24 hours) for roughly half the token cost.

“Context fork. So, you're forking the agent into a like a separate thread where whatever the agent does and thinks and adds tokens to does not come back and pollute the main uh the main context.”

▶ watch at 16:06

“if you have more than 150,000 tokens, then what you want to do is you can run a compact”

▶ watch at 16:38

“you can take your prompts, you can take your work, and you can put them in a batch and for 50% fewer token cost you will get the result they promise in at at least 24 hours”

Commentary (ours)

Coyle frames these as exam-prep anti-patterns, but they read as a reasonable general-purpose agent-architecture checklist independent of the certification -- worth revisiting even for people who have no interest in sitting the exam itself.
