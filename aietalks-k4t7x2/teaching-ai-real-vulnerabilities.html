Teaching AI to Find Real Vulnerabilities

SpeakerProf. David Brumley · Bugcrowd Watchyoutu.be/ZFxh7sqbUZo
SecurityEvals & benchmarks

If you only read one thing

  • Frontier models are trained to hack the same way top human hackers are taught: a graduated ladder of target and exploitation difficulty, illustrated by Richard Zhu going from novice to a $375,000 Pwn2Own win in two years (c1).
  • LLM-as-judge doesn't work for cybersecurity because models will always claim they succeeded, so grading needs a deterministic oracle; real open-source programs usually have more than one vulnerability, and naive single-bug benchmarks let models reward-hack by repeatedly finding the easiest one, including in DARPA's own $60M Cyber Grand Challenge (c2, c3, c4).
  • The fix is an 'audit task' that asks the model to find all vulnerabilities rather than one, scored on precision and recall; tested against 41 real Chrome V8 vulnerabilities, Mythos reached full sandbox-escape arbitrary code execution 73% of the time, including on bugs experts had thought too hard to exploit in practice (c5, c6, c7, c8).
01Teach models the way we teach human hackers

Brumley opens with Richard Zhu, a 17-year-old who taught himself hacking by reading write-ups and practicing on a graduated scale of easy-to-hard problems in picoCTF, then two years later became the first person to hack a Tesla at Pwn2Own, winning $375,000 in cash and the car. He argues the same graduated-ladder approach, spanning target difficulty (toy problems to hardened targets) and exploitation difficulty (crash, then memory read/write, then full code execution), is what's used to train frontier models to hack.

“he was the first one to hack a Tesla. So, he walked out of this contest with $375,000 in cash and a brand new Tesla”

02LLM-as-judge fails; you need a deterministic oracle

Brumley says that unlike some other domains, cybersecurity can't rely on an LLM judge because models being evaluated will always claim they successfully hacked the target. Instead, each task pairs a containerized vulnerable program with a deterministic grading oracle -- for example, whether a submitted input actually triggers a crash -- and the model is asked to exploit the vulnerability rather than merely describe it, so hallucinated findings can be distinguished from real ones.

“The LLMs will always say they were successful hacking”

▶ watch at 07:16
03Real programs have multiple bugs, so single-bug benchmarks get reward-hacked

Existing benchmarks like CyberGym typically assume a program has exactly one vulnerability, but Brumley says that assumption rarely holds for real open-source software. When multiple vulnerabilities exist, models default to repeatedly finding the easiest one, which stunts learning; he cites DARPA's Cyber Grand Challenge, where 50% of the hand-curated challenges turned out to contain unknown, unintended vulnerabilities despite a $60 million design effort.

“the LLM will just continue to find the easiest vulnerability, and that really limits its trajectory as far as what it can learn”

04The audit task: ask for all vulnerabilities, score precision and recall

Brumley's alternative is the audit task, which flips the prompt from 'find the vulnerability' to 'find all vulnerabilities,' giving the model freedom to submit multiple proofs, including ones for bugs the designers didn't know about. A deterministic grader uses stack-backtrace uniquification (the same technique Microsoft and Apple use for crash reports) to distinguish separate bugs, then scores the model on precision and recall against the known set, which normalizes for unknown vulnerabilities and prevents both easy-bug fixation and spam submissions.

“flip the question from just find a bug to find all vulnerabilities discovered”

▶ watch at 13:25
05Testing on Chrome's V8: results and the open-science dilemma

Because a V8 vulnerability can be used to attack Chrome, Edge, Node.js, and Cloudflare Edge Workers, Brumley's team built a 16-step capability ladder from triggering a crash up to full out-of-sandbox arbitrary code execution and ran it against 41 verified real V8 vulnerabilities. While most frontier models could trigger a crash at similarly high rates, only arbitrary code execution separated them: Mythos reached full sandbox escape 73% of the time versus Gemini and Kimi at 0%, and in several cases took exploitation routes experts had thought impractical, evidence the results weren't memorized. Because Mythos produced non-public weaponized exploits, Bugcrowd withheld its transcripts from the public release, which Brumley frames as an unresolved open-science tension.

“if you can find a vulnerability in V8, you can exploit all these systems”

Commentary (ours)

The 73% vs 0% split on arbitrary code execution is a much sharper signal than the ~95% crash-trigger rate every model hits, which is Brumley's central point: a benchmark that stops at 'did it crash' can't distinguish models at all on a hard target, and only the full exploitation ladder reveals the real capability gap (ours).
