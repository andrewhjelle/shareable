02The 'leaky bucket' problem: investigation time is a black box
Slide at 03:20 · click any slide to enlarge · 8 more from this section below

The 'leaky bucket' problem: investigation time is a black box

  • She describes a recurring pattern where performance issues are ignored until they become a crisis, largely because the investigation phase to find and scope an issue is unpredictable in duration and hard to prioritize.
  • The team built a weekly automated agentic workflow, running against real production context, to score and flag high-ROI performance opportunities without requiring someone to stop and investigate manually.

“that mostly happens because the research phase is a black box. It could take an hour or weeks and we have to pay that debt”

said at 03:36
03Three failure modes the workflow had to guard against
Slide at 08:10 · click any slide to enlarge

Three failure modes the workflow had to guard against

  • Walter names three recurring problems with agent-proposed fixes: 'plausible unverified' fixes that sound right but don't actually work when tested, difficulty with complex ClickHouse queries, and 'lazy fixes' like catching an exception instead of addressing its root cause.
  • Solving these required grounding the agent in actual production data rather than letting it theorize.

“the agent would suggest a fix. It sounds right. It would look fairly real and then after we verified it it it just didn't work”

said at 08:47
04Closing the loop: fix, rerun tests, verify impact, then hand to a human
Slide at 09:50 · click any slide to enlarge · 4 more from this section below

Closing the loop: fix, rerun tests, verify impact, then hand to a human

  • The workflow's key step is that the agent applies a fix, reruns tests, and confirms the measured impact on the affected flow before a human reviewer ever sees it, so the human is reviewing a verified result rather than a proposal.
  • Walter says this shifted the team from opening dozens of unreviewed PRs (which no one wanted) to a prioritized, human-readable report surfacing only the highest-ROI, lowest-risk opportunities.

“the agent actually fixes it reruns the tests and sees the impact that it had on that specific flow that was optimized”

05Function-level production context, not just service metrics
Slide at 11:50 · click any slide to enlarge · 6 more from this section below

Function-level production context, not just service metrics

  • She describes building 'prod-to-code' context that connects runtime data to the function and file level where coding agents actually reason, rather than leaving it at the service/endpoint level metrics like P90 latency, CPU, and memory.
  • This was paired with a query language over that data plus a set of reusable 'skills' for specific investigation types (500 errors, memory spikes) to reduce variance in results.

“our context is running on a function level, and it is also connected to the endpoint or event consumer or cron job that ended up starting this task”

said at 11:52
06Autonomous automation requires a much higher trust bar than interactive coding
Slide at 22:20 · click any slide to enlarge · 1 more from this section below

Autonomous automation requires a much higher trust bar than interactive coding

  • Walter closes by distinguishing agentic engineering used interactively, where a human is present to steer and catch mistakes, from an autonomous automation that runs unsupervised.
  • She says reaching the point where the team trusted the automation's output required crossing roughly 80-90% confidence, which she calls dramatically different from using an agent directly as an engineer.

“getting to that agentic engineering automation level requires crossing towards the 80-90% trust, and it's something that is dramatically different than using an agent directly as an engineer”
