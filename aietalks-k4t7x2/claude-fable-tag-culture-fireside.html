If you only read one thing

  • Anthropic's internal version of Claude Tag lands 65% of the product engineering team's PRs, with humans still reviewing core/critical code via code owners while Claude Code reviews the outer-layer changes (c2, c4).
  • The Claude Code system prompt was cut about 80% for frontier models (Fable, Opus 4.8), partly by removing few-shot examples that Cat Wu says were constraining rather than helping newer models (c3).

From manual permission prompts to auto mode

  • Cat Wu described that with the first Claude Code and Sonnet 3.7, she read every permission prompt carefully and often said no; model generations since then let the team delegate more implementation work and shift toward auto mode, which she said she only started defaulting to about three weeks before the talk.
  • Thariq Shihipar noted software engineering ambition has risen correspondingly, since the tools now support attempting bigger projects.

“you would give it this task and you would have to closely monitor every single little thing that it tried to do. Uh I remember I would read every permission prompt extremely carefully. I would frequently say no”

Claude Tag: proactive, multiplayer, shared memory

  • Claude Tag lives in team collaboration tools (launched in Slack the prior week), is multiplayer by default so teammates can jointly steer a session, and is proactive rather than reactive, e.g. monitoring a channel for bug reports and opening PRs without being manually invoked.
  • It has channel-level shared team memory, and Anthropic's internal version currently lands 65% of the product engineering team's PRs.

“our internal version of claw tag lands 65% of our product PRs right now”

Reducing human code review

  • Code owners still manually review changes to the most critical core areas of Claude Code and other products, but for outer-layer changes, code review is increasingly done fully by Claude Code itself, reached over a six-plus-month trust-building process: incident reviews feed back into updating code review and adding regression evals so future changes don't reintroduce the same class of bug.

“for the changes that are at the outer layers, we actually have quad code review fully review those”

80% system prompt reduction

  • The Claude Code system prompt was reduced by about 80% for the most frontier models (Fable and Opus 4.8), while older models keep the full prompt since Anthropic now runs different system prompts per model.
  • Cat Wu said removing few-shot examples was surprisingly helpful because newer models were more creative without them, and the team shifted from hard 'do not do this' constraints toward giving more context and fewer absolute instructions, since edge-case-violating hard rules can confuse the model when they conflict with later user instructions.

“some of the patterns we saw is that um we were over constraining Claude, right? So I think the initial like maybe Opus 4ish kind of models wanted a lot of examples and uh removing examples was extremely helpful”

said at 21:42
05Auto mode's mechanics and safety testing
Slide at 31:30 · click any slide to enlarge · 8 more from this section below

Auto mode's mechanics and safety testing

  • Auto mode uses a Sonnet classifier that judges each tool or bash call against the user's instructions and conversation context (e.g. it will deny a git push if the user said not to push, but allow one if requested), and integrates with sandboxing to decide whether a request should be allowed to escape the sandbox.
  • It has been used and hardened inside Anthropic since January, with extensive internal evals and commissioned red-team testers building adversarial prompt-injection environments; Anthropic plans to publish evals for it in the coming weeks.

“there's a or a bash call, uh there's a sonet classifier that is judging the tool and also the context of the conversation, your instruction”

said at 32:55

“We've done extensive bashing. We have thousands of eval. We've commissioned many red team teamers to create adversarial environments in order to trick cloud code into doing bad actions. and we've mitigated every single issue that they found”

Commentary (ours)

(ours) The claim that few-shot examples now hurt frontier-model prompting (versus the long-standing advice to always give examples) is the most operationally actionable point in the talk if it generalizes beyond Claude Code's own system prompt, but it's stated as an internal observation, not backed by a published eval, so it's worth testing rather than adopting outright.
