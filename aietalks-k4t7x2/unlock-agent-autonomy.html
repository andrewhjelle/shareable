01The safety problem behind agent autonomy

Jain opens with an anecdote: a private nightly analysis agent that emailed him reports for weeks suddenly posted one as a public PR on a repo, with nothing prompting the change beyond the model deciding to be helpful. He generalizes this into a bigger issue: as an agent works a task (e.g., investigating a latency spike), each reasonable next step, requesting logs, GitHub access, then Slack access, expands its scope and crosses trust boundaries, until the agent effectively holds access to everything and any single misstep has a large blast radius.

“Randomly one day, uh it decided to post this report as a PR on the repo.”

02Three pillars: containment, scoped access, intent-based access

Jain proposes a runtime built on three pillars. Containment means running the agent inside a sandboxed, untrusted boundary while controls live outside that VM boundary. Scoped access means going beyond broad tool/network permissions to just-in-time tools composed over existing integrations (e.g., a Slack tool restricted to only the messages relevant to one incident, not full channel read access). Intent-based access means a control layer, independent of the model or harness, decides what access a task should get based on the user's stated intent, rejecting or escalating requests that don't match it.

“First is containment. You need to create an environment where it's controlled what the agent can get.”

03Why the runtime must span every model and harness

Jain argues no team will bet everything on a single model or frontier lab; organizations will mix models across labs, open models, and multiple harnesses (not just coding) as agent use spreads to other functions. A safety solution that only works with one model or harness therefore isn't sufficient.

“No one is going to bet everything on a single model or even a single frontier lab.”

▶ watch at 04:05
04Docker's SPX runtime demo

Jain demos SPX, a new micro-VM-based runtime that injects credentials and network policy into a sandbox rather than exposing them to the agent, and shows the same sandbox and policy running locally, moved to the cloud, and fanned out to review PRs in parallel via an orchestrator. He closes by inviting attendees to install it via brew and run any agent (Claude, Codex, Open Code, or a custom build) inside it.

“You can run Claude, Codex, Open Code, any agent, build your own in there.”
