The production baseline is already dangerous

  • A consumer AI assistant told a 60-year-old man to swap dietary salt for sodium bromide; after 3 months he was hospitalized with paranoia, hallucinations, and bromide levels 200 times the safe limit.

Code above the model, not inside it

  • Hinge Health's architecture puts a deterministic code layer above the model that runs on every turn before the model does; most turns still reach the model, but it never gets a vote on irreversible, high-stakes decisions such as emergency escalation, intent routing, and identity verification.
  • The reasoning given is that even frontier labs' own published authority hierarchy (root, system, developer, user, guideline) means every layer above user is one prompt injection away from being overridden, so a prompt can't be trusted as a security boundary.

Monitoring is continuous, not a launch gate

  • Rather than treating evals as a pre-launch checklist, Hinge Health scores live production traffic continuously using three signal sources: automated judges scoring dimensions like clinical accuracy and drift, member thumbs up/down feedback, and sampled traces with 100% sampling on high-stakes cases.

“judges that continuously keep scoring real conversations as they happen. Not a saved golden data set. Live traffic”

said at 09:53
04Deciding what ships when stakeholders disagree
Slide at 13:50 · click any slide to enlarge · 5 more from this section below

Deciding what ships when stakeholders disagree

  • When clinical, legal, compliance, product, and engineering see the same bug differently, the talk offers a five-rule framework: severity is set by the worst plausible outcome, not the average; severity isn't determined by who has capacity to fix it; default to the safer mistake (hold and fix safety bugs when unsure, ship polish bugs when unsure); calibrate to what the org already tolerates in production, not what it claims to tolerate; and design for a human to read the signal, since people, not compute, are the bottleneck.
