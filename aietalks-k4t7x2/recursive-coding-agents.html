Recursive Coding Agents

01The problem is management, not intelligence

The speaker frames today's coding agents as 'mismanaged geniuses' -- a phrase from Alex Zeng, Z Li, and Omar Khattab at MIT -- where the missing layer is how work gets specified, verified, and reused, not raw model capability. He illustrates this with a personal example of Claude Code emptying his Solana wallet the day after producing a nearly working SaaS app from one prompt.

“today's agents are mismanaged geniuses. The intelligence is there, and the missing layer is how do we specify and manage and reuse and verify the work”

02What recursive language models (RLMs) are

In an RLM, the full prompt is externalized as a variable (a file or files) rather than loaded directly into context, and the agent operates on it symbolically inside a REPL (Python in the original paper), optionally recursing into sub-RLMs to decompose the problem. The speaker calls this a marriage of reasoning and code execution and the next paradigm of test-time compute.

“RLMs are the new reasoning models and I see this as the next paradigm of test time compute, inference time compute, whatever you want to call it”

▶ watch at 04:09
03RLMs beat frontier LLMs on hard benchmarks

On the Long CoT benchmark, which requires holding a long reasoning thread that defeats most frontier reasoning models, a small model (Qwen3 59B) run as an RLM with code and recursive sub-agent calls beat Opus and GPT-5.4 running as plain LLMs. Separately, the Symbolica team's Agentica RLM harness scored over 30% on ARC-AGI-3 within hours of release, versus roughly 2-3% for frontier models as LLMs, prompting the ARC Prize team to decline running the private evaluation for RLM harnesses.

“a very small model, Qwen 3.59B, you could run this on a laptop, uh can actually beat So, Qwen 3.59B as an RLM can beat Opus and um and GPT-5.4, all the top frontier models as LLMs on these long reasoning tasks”

“the uh Symbolica team showed 30-something percent. This is crazy. They blew it out of the water within hours using RLMs as a framework”

04Claude Code became an RLM via dynamic workflows

The speaker notes that Claude Code's newly released dynamic workflows (covered in the blog post 'A Harness for Every Task') made it recursive and, per RLM co-author Omar Khattab, qualify it as an RLM for the first time. He built two example Claude Code dynamic workflows -- one a hardcoded map-reduce (not an RLM) and one recursive deep-research-over-a-filesystem pattern (an RLM).

“Hey, congratulations Anthropic, uh Cloud Code is finally an RLM now that you have dynamic workflows”

▶ watch at 16:11
05OpenProse as a portable alternative

OpenProse is a markdown-based 'programming language' compiled by the coding agent itself (not the computer), letting any agent with a filesystem and sub-agents become an RLM without relying on Claude Code's dynamic workflows. It lets a workflow author declare sub-agent work explicitly and attach skills and tools as required dependencies for each sub-agent, and it also has a feature to turn a 'golden session' into a reusable, repeatable Prose workflow.

“there's a way in Pros to actually wire those in as dependencies to ensure that um not only that the way the work is done um is what you want”

▶ watch at 19:19

“I built a system where you can take a golden session for Cloud Code, Codex Pi, whatever you want. And it's a Prose program that will actually have the agent deconstruct that session and turn it into a reusable Prose workflow”

Commentary (ours)

The Symbolica/ARC Prize dispute is a useful signal that benchmark leaderboards and agent-harness capability are already diverging in ways that will force separate 'tool-calling allowed' leaderboards; worth watching whether other benchmarks follow the same split (ours).
