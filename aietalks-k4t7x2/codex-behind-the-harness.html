Codex, behind the harness

A guided tour of the open-source Codex harness (Rust, Apache-2): how context gets built, how actions run safely, and why the interesting harness features keep migrating down into the Responses API.

SpeakerDominik Kundel · OpenAI Watchyoutu.be/shRR1e2HXMk
harness designcontext engineeringsandboxingauto-reviewresponses apiwebsockets

If you only read one thing

  • The whole Codex harness is open source (Rust; Apache-2 on the repo) — usable as a blueprint or as your actual harness, with an open app-server protocol on one side and the Responses API on the other.
  • The craft is in the budgets and escape hatches: tools load deferred via tool search, skills are capped at 2% of context, approvals go to a read-only auto-review subagent instead of you.
  • The strategic tell: every standout harness feature eventually ships down into the Responses API — OpenAI is standardizing the harness layer, not hoarding it.
01Facts — what the talk actually says

Two protocols, one open harness

A message leaves your UI over the app-server protocol (the same one powering the Codex app, community front-ends, and Kundel's Codex-in-Doom stunt), lands in the Rust harness, and goes to inference over the Responses API — which now has an open schema and a governance body, with Ollama, LM Studio and NVIDIA on board. Any Responses-compatible model can sit behind the Codex harness.

“the Codex harness and everything I'm showing you is actually open source”

▶ watch at 01:06

Context is a budget

Context construction optimizes three things — size, flexibility, cacheability. The two mechanisms worth stealing: tools marked deferred stay out of the window entirely until tool search pulls them in (exposed in the API since GPT-5.4), and the skills list is hard-capped at 2% of the context window — descriptions shrink as the list grows.

“we actually cap the available skills list at 2% of your context total”

▶ watch at 06:15

Actions: script the computer, don’t click it

Computer use flipped from one-action-per-call to code execution: Codex writes Playwright in a persistent node REPL, learns a page’s structure once, then scripts the rest. Files go through the trained-in apply_patch; everything else is shell (ripgrep ships with the harness; on Windows the model natively writes PowerShell).

“the agent can script its own interactions with whatever computer implementation you want to have”

▶ watch at 08:48

Safety without approval fatigue

Sandboxes per OS — Seatbelt, Bubblewrap, and a custom-built open-source Windows sandbox. On top sits auto-review: when the agent tries to escalate, a read-only subagent (no further subagents allowed) judges the action against your actual authorization, a risk taxonomy, and the transcript — deleting a .git folder you asked about is fine; exfiltrating a file is not.

“cover all of the things that are harder to predict that an agent might do ... while keeping things like data exfiltration outside of it”

▶ watch at 13:07

When inference stops being the bottleneck

GPT-5.3 Codex Spark on Cerebras runs at 1,000 tok/s — at that speed the network is the constraint, so the Responses API grew a WebSocket mode with stateful context: only deltas cross the wire. Loops (/goal) inject a continuation prompt until the model itself declares the goal done — hence concrete, verifiable goals. And compaction runs server-side, trained into the model.

“inference was no longer the bottleneck. It was actually the network.”

▶ watch at 15:51

“have very concrete and very [verifiable] prompts, so that it's easy to detect when things are done”

02Context & cross-talk

Against the Anthropic talk (same stage, same week)

  • Agree: hours-to-days agent runs are the design assumption, and both attach a sidecar judge agent to the loop — though for different jobs (auto-review judges safety escalations here; Anthropic’s grader judges task completion).
  • Split: OpenAI’s bet is open harness + open protocol — fork it, self-host it, the API absorbs the good ideas. Anthropic’s flagship bet is the opposite: managed, Anthropic-run infrastructure (their Agent SDK remains the self-host rung below it).
  • Contrast (not a disagreement): different bottlenecks in different architectures — at Codex’s inference speeds the network dominates (hence WebSockets); in managed sandboxes container startup dominates (hence brain/hands decoupling). And the model-harness coupling runs both directions: OpenAI trains the model with its harness features — exactly the coupling Anthropic’s staleness thesis says needs re-auditing each release.

Extrapolation (ours)

If harness features keep sinking into the Responses API on OpenAI’s side and into managed platform on Anthropic’s, the hand-rolled agent loop ages into legacy code. The durable skill is what sits above the harness — task design, context curation, verifiable goals. Bet accordingly: build thin on top of either stack, keep your domain layer portable between them. (Two vendor talks, n=2 — directional, not law.)
