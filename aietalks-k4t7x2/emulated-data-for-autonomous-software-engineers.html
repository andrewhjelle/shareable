01The capability gap is a data gap

Wang states that model capability has never regressed when higher-quality data was introduced, framing infrastructure-reasoning weaknesses (e.g., understanding MVCC issues that contributed to a real DynamoDB outage) as a data problem rather than a fundamental model limitation. Current frontier benchmarks like SWE-bench Pro and Terminal-Bench only test in-codebase diffs over 50-100 turns, missing the PM-style customer conversations, iterative approach testing, and multi-year infra ownership real engineers do.

02Simulating whole companies, not just code diffs

Citing the DynamoDB outage that took down US East 1 and much of the internet, Emulated builds containerized environments simulating entire software companies: organizational context (projects, incidents, customer conversations) plus infrastructure failures that only appear at scale (network failures between nodes, data corruption, clock skew). The resulting environments are described as far more complex and long-horizon than a simple code diff.

03Single-node sandboxes hit a wall

Wang argues single-node containerized sandboxes work for simulating a distributed cluster on one machine, but break down once a task requires actual resource provisioning — you can't simulate services like EC2 or Cloud Run inside a single sandbox, and enterprise-grade requirements (throttling, auth, DNS, billing, deployment rollback) compound the gap.

“this is already where the single node sandbox starts breaking down. How do you provision resources within a single sandbox? You can't exactly simulate something like EC2 or Cloud Run”

▶ watch at 08:22
04The multi-node, real-infra future — and its costs

Emulated's proposed answer is a multi-node sandbox with access to real cloud resources ('cloud in a box'), which changes post-training pipeline design substantially. Open problems Wang flags include the time cost of provisioning (spinning up a full stack like AWS Lambda can take hours, awkward to fit inside an RL rollout) and the persistent sim-to-real gap even with real infrastructure, since live customer traffic and at-scale failure modes are still hard to reproduce.

“what this is is um a multi-node sandbox with access to real infra, real cloud resources. Uh we kind of put a cloud in box”

Commentary (ours)

Emulated's own framing (naming the company after 'emulating the real world with full fidelity') is a strong claim about what current benchmarks miss, but the talk offers no benchmark numbers showing that training on their multi-node environments actually improves agent reliability in production — the case for the approach here is architectural/conceptual, not yet empirical (ours).
