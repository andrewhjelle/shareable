patternCoding agentsAgentic engineeringProduct & UX

Names several specific, low-cost interventions for an agent-authored codebase (architecture.md, a design-doc gate, agent-first tooling) rather than one end-to-end system with connecting numbers.

If you only read one thing

  • The team building BAML runs without code review or standardized tooling, defining slop as any code nobody reads, and instead relies on an agent-readable architecture.md and a design-doc tool with a rule that code can be slop but writing cannot (c1, c2, c3).
  • TypeScript's stated design goal targets human productivity, not agent productivity, and the speaker argues specific language behaviors (implicit string coercion in sorting, for example) are slop baked into the language that AI-generated code keeps hitting (c4, c5).
  • BAML's pitch: a compiler that infers exhaustive error types, agent-first tools that collapse multi-step code lookups into one call, and functions callable across host languages like Python (c6, c7, c8).

No code review, no standards

  • The speaker's team has built a programming language (BAML) for three years without code reviews or standardized AI tooling across engineers.
  • He defines slop as any code that goes unread, and argues that is unavoidable once a codebase is largely agent-authored.

“Slop is just any code you don't read.”

02Agent-readable architecture docs and gated design docs
Slide at 01:30 · click any slide to enlarge · 8 more from this section below

Agent-readable architecture docs and gated design docs

  • Instead of enforcing a shared workflow, the team wrote a small architecture.md file, deliberately not called CLAUDE.md, meant to describe things that won't change for months or years so any model can orient itself.
  • Design writing gets a stricter rule than code: it must be readable by humans, backed by a versioned design-doc tool with Slack notifications and a requirement that people actually read a doc before it ships.

“We built an architecture.md file. Instead of using Claude.md, just pick something that every model can just understand.”

said at 01:31

“we have a very simple rule in our team. Code can be slop, writing cannot.”

03TypeScript wasn't designed for agents
Slide at 07:10 · click any slide to enlarge · 8 more from this section below

TypeScript wasn't designed for agents

  • The speaker points out that TypeScript's own stated design goal balances correctness against human productivity, not agent productivity, and argues that specific TypeScript behaviors (such as coercing values to strings during comparison-based sorting) count as slop built into the language itself that any AI-generated code built on top of it will inherit.

“TypeScript's main design goal is to strike a balance between correctness and productivity”

said at 07:16

“This is slop baked into the language. And whether you like it or not, the systems will have slop if you build using these tools.”

said at 08:17
04Agent-first tooling replaces grep-and-guess
Slide at 12:20 · click any slide to enlarge · 8 more from this section below

Agent-first tooling replaces grep-and-guess

  • The talk demos tools built specifically for agents rather than adapted from human-IDE tooling: a single call that returns a function's docstring, source, and every call site (replacing several grep calls), and a compiler that infers exhaustive error types so it can prove whether an error path is handled rather than leaving it to guesswork.

“We can make something that used to be multiple tool calls a single tool call all of a sudden.”

said at 12:25

“error types now get inferred without you ever having to do any guesswork”

said at 16:34
05BAML as a cross-language, type-safe layer
Slide at 18:10 · click any slide to enlarge · 8 more from this section below

BAML as a cross-language, type-safe layer

  • BAML functions are presented as directly callable from a host language such as Python with full type safety, including async variants, closures, and generics passed across the language boundary.
  • The talk closes by arguing the underlying layers of software development — version control, databases, and the programming language itself — may need to be rebuilt for a world where agents, not humans, write most of the code.

“What if every function in ML is immediately accessible in the language of your choice?”

said at 18:05

“I think we do need a new Git. I think we do need a new database, and yes, I think we need a new programming language.”

said at 20:39

Commentary (ours)

(ours) The concrete claim worth stress-testing is the TypeScript critique: it's a specific, checkable argument (implicit coercion, human-productivity-oriented design goal) rather than a general complaint about older languages, and it's a reasonable lens for auditing any language a team plans to lean on heavily for agent-generated code.
