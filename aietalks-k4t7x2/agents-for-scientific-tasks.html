Autonomous Agents for Scientific Tasks

SpeakerSina Shahandeh · Radicait Watchyoutu.be/XLEYtv3cMlw
Agentic engineeringHealthcare AICoding agents

If you only read one thing

  • Coding agents on open-ended, long-horizon scientific tasks tend to saturate at a performance ceiling because they run out of good hypotheses, not because implementation is hard.
  • Explicitly decomposing a problem into a documented hierarchy of components (data, architecture, training loss, metrics) gives the agent a scaffold to reason over and propose more radical changes, like switching from 2.5D to 3D convolutions.
  • On a real .NET codebase, this and related graph/subgraph techniques produced a 40% reduction in tool calls for code search, per a companion talk on graph techniques Shahandeh references.
01Agents saturate on hypothesis generation, not implementation

Shahandeh contrasts the 'auto researcher' pattern (an agent hill-climbing a model metric, as in Karpathy's original repo) with open-ended, long-horizon scientific tasks, where agents are good at implementation and running experiments but plateau because they run out of new ideas, what he calls 'research taste.' He notes top human researchers keep improving over time in a way current agents don't.

“the problem is they ran out of ideas uh or you know what people call them research taste”

02The example problem: CT-to-PET image translation

At Radicait, the team trains a model to generate a synthetic PET scan from a CT scan, avoiding the time-consuming real PET scan process, by learning which tissues would absorb more radioactive tracer. Shahandeh frames the underlying model-training loop as the same hill-climbing optimization problem, which desaturates at a certain point and then needs a genuinely new idea to progress further.

“we do an ML through ML model image translation one can kind of change the modality learn the structure of the body and infer what would happen in a PET scan if the hyper the activity of the tissues”

03Explicit hierarchical decomposition unlocks bigger ideas

His technique is to have the coding agent explicitly decompose the problem into a documented hierarchy of subcomponents (data, architecture, training loss, metrics, operational scripts), generated via a prompt that has the agent create linked hierarchy documents in the codebase. With that hierarchy as scaffolding, the agent can reason about and propose changes to each component rather than only tweaking hyperparameters, which in one run led it to propose switching the model from 2.5D to 3D convolutions.

“decompose the problem into its subcomponents but it's an explicit act”

04Adversarial/collaborative review with a second, stronger reasoning model

Shahandeh describes closing the loop with a second model, used adversarially or collaboratively, to critique the hypothesis and implementation, citing his use of an 'Oracle CLI' that packages code and data to send to a more powerful reasoning model for review. He reports better hypothesis generation and more effective critique from this loop, applied both to the model-training problem and to a separate CT/PET image-registration alignment problem.

“I've seen a much better improvements during the especially the hypothesis improve generation”

05Multimodal scientific perception is the current bottleneck

He argues that implementation is largely solved for simulated, boxed problems, but current multimodal models lack the trained perception to reliably identify subtle scientific signals, such as a small nodule in a CT scan, because they aren't trained on scientific imaging data. He predicts that as models get better post-trained at compartmentalizing problems, explicit hierarchical decomposition tricks like his will become less necessary over time.

“no LLM today is able to identify these very well because they're just not simply trained on scientific images and scientific data”

“going forward with the newer models that are much better post-trained to compartmentalize the problems and break down the problems”
