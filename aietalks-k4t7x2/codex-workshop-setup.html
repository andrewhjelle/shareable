patternAgentic engineeringMemoryContext engineering

This is a working blueprint for running a personal agent as a chief-of-staff layer across email, Slack, calendar, and browser rather than a single coding tool

If you only read one thing

  • Long-lived pinned threads plus compaction replace the old rule of starting a fresh thread every 20 messages.
  • App screenshots (appshots) beat plain screenshots because they carry the full accessibility tree, so the agent can act in one hop instead of several.
  • Default to low or medium reasoning effort; high effort is a trap that burns tokens without matching gains.
▣The system in one picture (ours, from the slides and the transcript)

This sketch treats the pinned thread as the hub that ingests voice and appshot context, writes to a git-tracked memory vault, and spawns sub-threads and goal loops, though the exact wiring between these pieces is our inference from the talk (ours).

Long threads now hold up

  • Liu argues the old advice to restart a conversation after ~20 messages or per feature is now obsolete because compaction keeps months-old threads coherent.
  • He runs threads that are weeks old with hundreds of sub-agents inside them and says they still track their own job.
  • Threads can also list, rename, and message each other, which lets a single pinned thread act as a manager over sub-threads.

“you were always told if a conversation goes very long, start a new thread, right? After 20 messages, it's it's not going to be that good.”

Getting context in: voice and appshots

  • Liu uses a foot pedal to dictate to Codex rather than typing, citing roughly 3x the speed of typing and describing it as useful for handing over messy, tangent-laden thinking.
  • Appshots (screenshots plus the app's accessibility tree) are called out as his favorite feature because the agent gets structured data (channel IDs, user IDs) instead of having to OCR and look up entities separately.

“you generally talk about three times faster than you type and it's just incredibly productive to be able to give the messy version of what you're thinking about to the AI”

said at 07:42

“with appshots, it takes not only the image but the entire accessibility tree of the app”

03Building a personal memory system
Slide at 15:50 · click any slide to enlarge · 6 more from this section below

Building a personal memory system

  • He treats his personal monorepo as a git-tracked memory vault, reviewing what the agent changed via git diff rather than reading every session log.
  • He built a 'write like me' skill by having the agent read six months of his emails and Slack messages to produce a style guide it now applies automatically.
  • He recommends building and personally using a skill for weeks before sharing it with a team, and framates 'goal' as a verification-driven loop that keeps running until a stated condition is met.

“I make my monor repo vault like a git repo. And so maybe it'll work on it for like a couple of days and I'll come back and I'll just run git diff.”

04Guardrails and effort settings
Slide at 52:20 · click any slide to enlarge · 8 more from this section below

Guardrails and effort settings

  • Asked about risk, Liu warns that a sufficiently determined agent will route around a blocked tool call (e.g., switching from a Gmail connector to opening Chrome and clicking send) and says this is where agents.md constraints and permission settings matter most.
  • On compute, he pushes back on the idea that maximum reasoning effort produces the best outcome, saying low/medium effort on current models is already far better than prior generations for most day-to-day tasks.

“the model based on how you prompted becomes really determined and say, "Oh, like I I it seems like I can't email someone using the Gmail connector. Let me open up Chrome and hit the send button."”
