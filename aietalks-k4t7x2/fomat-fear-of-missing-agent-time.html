Let's Talk About FOMAT: Fear of Missing Agent Time

SpeakerMichael Richman · Cmd+Ctrl Watchyoutu.be/W-SX_srBa3Y
Agentic engineeringProduct & UX

If you only read one thing

  • Coding agent task duration is trending from 5-45 minutes today toward 5 hours or 5 days, making it impossible to just 'check back in a bit' the way people do now (c1).
  • Richman built Command and Control, a mobile/web/watch app that lets him monitor, resume, and launch coding-agent sessions (Claude Code, Codex, Cursor, GitHub Copilot) from anywhere via a control-plane layer talking to a per-agent daemon (c2, c3).
  • He personally cannot track more than two or three concurrent agent sessions before losing track of which one needs attention, and treats push notifications plus a stand-up-style overview dashboard as the fix (c4, c5).
01Agent idle time will get much longer

Richman says coding tasks currently take roughly 5 to 45 minutes, a window short enough that people can predict when to check back in, but argues that window is only going to get longer -- toward tasks running 5 hours or eventually 5 days -- at which point you can no longer predict when the agent needs you or when it's done.

“if a task is running for 5 hours or eventually 5 days, you can't just check back in a bit. You need to know when it needs you and you need to know when it's done”

▶ watch at 01:36
02Command and Control: a cross-agent, cross-device session manager

Richman built Command and Control because nothing existed to let him work with coding agents outside the terminal or IDE. It runs on iPhone, Android, web, and even a watch, and lets him subscribe to sessions for push notifications, resume a session from any device with the same conversation state, and launch brand-new sessions remotely -- he describes starting his day issuing prompts from bed.

“it lets you monitor and interact with agent sessions and launch new sessions from anywhere. From your phone, from the web, even from your watch”

▶ watch at 04:11
03Architecture: per-agent daemon plus a control-plane layer

Each supported agent platform (Claude Code, Cursor, Codex, Gemini, Open Code) runs a Command and Control daemon alongside it that monitors the agent's lifecycle and reports status changes (blocked, needs help) up to a control-plane layer, which the UI talks to. The daemon layer is open source and coding-tool agnostic, and the control plane aggregates sessions regardless of whether they run on a dev machine or a cloud VM.

“they talk to a control plane layer. They monitor life cycle of the agent. When things change, it's blocked, it needs your help. It communicates up to the control plane layer”

▶ watch at 11:30
04Session overload is a real cognitive limit, not a hypothetical

Richman says he personally cannot keep track of more than two or three concurrent agent sessions before losing track of which one needs attention or what state each is in, despite having thousands of historical sessions logged in the app. Command and Control's fix is grouping sessions (push-notification subscribed, 'on my radar,' recent) plus a dashboard that generates a stand-up-style summary from each session's last few messages.

“I don't know about you, but I cannot keep track of more than two or three sessions at a time. As soon as I get to four or five, I don't know what session two is doing anymore”

▶ watch at 04:05

“you can get a kind of stand-up summary of the most recent sessions. And this is just using the last several messages to kind of give you an overview of what's been going on”

▶ watch at 10:45

Commentary (ours)

Richman frames this as a UX problem but it's really a scheduling/attention-allocation problem once agent runtimes exceed human working-memory span for tracked tasks -- the 'agent choreography' framing (moving between agents rather than one flow state) is a real shift in what 'being productive' looks like for engineers, worth watching whether it becomes standard vocabulary (ours).
