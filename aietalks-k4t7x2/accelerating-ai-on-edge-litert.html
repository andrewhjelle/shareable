Accelerating AI on Edge

Details Google DeepMind's on-device stack for Gemma edge models (2B/4B): new agent capabilities (function calling, structured JSON, chain-of-thought), the LiteRT cross-platform runtime, and reported performance numbers including NPU acce...

If you only read one thing

  • Gemma edge models (2B at roughly 1-2GB RAM, plus a larger 4B) now add built-in function calling, structured JSON output, and a chain-of-thought "thinking mode," moving on-device models from chatbot-style toward more autonomous agents.
  • LiteRT, Google's on-device runtime built on TensorFlow Lite (also accepting converted PyTorch/JAX models), runs across 100,000+ apps with billions of active users, using the same model format on Android, iOS, macOS, Linux, Windows, web, and IoT.
  • Reported performance: NPU acceleration is projected to give roughly a 10x performance improvement over CPU/GPU on real-time workloads like AR/TTS, and LiteRT's runtime is reported up to 35x faster than Llama on mobile.

01Edge models move from chatbots to agents

Edge models move from chatbots to agents

  • The talk frames the Gemma edge model line's evolution as a shift from chatbot-style capabilities toward more autonomous, reasoning-capable agents.
  • The smaller of the two headline on-device models uses roughly 1 to 2GB of RAM, with a larger, more RAM-hungry variant intended for bigger platforms like laptops or IoT devices.

“So, the big evolution with Gemini 4 is going to be really moving from like chatbot type capabilities to more autonomous agents that also support reasoning capabilities and more sophisticated features.”

02Why deploy on-device: latency, privacy, cost

Why deploy on-device: latency, privacy, cost

  • On-device deployment is pitched for real-time camera/video use cases where latency matters, for privacy-sensitive use cases like summarizing sensitive documentation, for offline use with poor connectivity, and as a hybrid option to offset cloud token costs.

“Privacy is also critical for any use cases where, you know, you have sensitive details, you're doing some kind of summarizing uh, documentation which is sensitive, offline use cases where you have poor connectivity”

03New agent capabilities: function calling and structured output

New agent capabilities: function calling and structured output

  • The newer edge models add built-in function-calling support for tool calling, letting a model that starts inferencing on-device call out to other local APIs, alongside native structured JSON output built into the model architecture rather than achieved through prompt engineering, and a new chain-of-thought "thinking mode" surfaced in Google's gallery app.

“function calling built-in support for tool calling and also essentially models to interact with other local APIs”

said at 04:07
04LiteRT: one runtime, many platforms, real scale

LiteRT: one runtime, many platforms, real scale

  • LiteRT is Google's on-device framework, built on the TensorFlow Lite model format and also accepting converted PyTorch and JAX models.
  • It is described as one of the most widely deployed on-device frameworks, with over 100,000 apps and billions of active users, running the same cross-platform model format on Android, iOS, macOS, Linux, Windows, web, and IoT devices.

“It has uh 100,000 plus apps, billions of active users, and also lots of daily interpreter invocations.”

“your models are still going to run on Lite RT, and these models, the same model format is cross-platform. So, it's not just Android, but you can run it on iOS, macOS, Linux, Windows uh Windows, web,”

05Reported performance: NPU acceleration and comparisons to Llama

Reported performance: NPU acceleration and comparisons to Llama

  • For real-time AR/TTS-style workloads, NPU acceleration (with completed integrations for Qualcomm and MediaTek) is projected to give roughly a 10x performance improvement and reduce energy use.
  • Separately reported figures include up to a 13x boost from new accelerators in some cases, around 56 tokens per second on iOS, and a runtime described as up to 35x faster than Llama on mobile, at par on desktop, and about 3x on IoT.

Commentary (ours)

The NPU (~10x), accelerator (13x), and Llama-comparison (35x mobile, 3x IoT) figures are all vendor-reported in the talk with no benchmark methodology, hardware, or model-size details given on slide, so they should be read as Google's own marketing figures rather than independently reproducible benchmarks (ours).
