What if the harness mattered more than the model?

SpeakerAditya Bhargava · Etsy Watchyoutu.be/2e9ANoOEn28
Agentic engineeringCoding agentsLocal models

If you only read one thing

  • On Harness Bench (106 tasks, same model), scores swing from 52.4% to 76.2% depending solely on the harness -- a 20+ point gap that the speaker says matters more for weaker models.
  • Aditya Bhargava built a new agent-building language, Agency, arguing good harnesses need language-level support (typed tools, interrupts, partial function application) rather than a framework bolted onto an existing language.
  • He walks a coding agent through incremental harness upgrades -- tools, safety handlers, partial function application, a reason-act-observe loop, sub-agents, self-optimization -- each measurably improving the same model's performance on the same bug-fix task.
01How much the harness actually matters

Citing the Harness Bench benchmark (106 tasks, same model, different harnesses), the speaker reports scores ranging from 52.4% to 76.2% depending only on the harness used, and notes the effect is larger for weaker models -- meaning a strong harness can substitute for a stronger, proprietary model.

“scores range from 52.4% to 76.2%. So, more than a 20-point difference, and only the harness changed.”

02Building a language-level harness: Agency

Concluding that existing frameworks couldn't do what he wanted, the speaker spent six months building Agency, a new TypeScript-and-Python-inspired language purpose-built for defining agents and harnesses, arguing that a good harness requires language-level support rather than a library bolted onto an existing language.

“I've spent a good part of that 6 months building a new language called Agency, which is a language for building agents.”

▶ watch at 03:40
03Making agent actions safe without slowing them down

Agency's partial function application locks arguments (like a file directory) that the model isn't allowed to change or even see, constraining what an agent's tools can touch without requiring a human to approve every action -- addressing the tradeoff between giving an agent enough capability to act and too much capability to be unsafe.

“with partial function application, what we do is we take that read function and call the partial on it. And give it a directory.”

▶ watch at 16:10
04Sub-agents and self-optimization

The talk demonstrates sub-agents as ordinary functions the top-level agent can call in parallel, which adds capability without bloating a single agent's context window. It also demonstrates a built-in optimizer that systematically measures and improves prompts against a stated goal, starting from a measured baseline objective rather than manual trial and error.

“sub agents are cool because they let you add new capabilities without bloating context.”

▶ watch at 24:35

“the baseline objective is 0.2 and it's going to try to improve upon that.”

05The harness-building ladder

The speaker frames an agent as a model plus a harness, and demonstrates the same model and task improving across seven stages: give it tools, make the tools safe, make it autonomous without losing safety, make it reason in a feedback loop, give it sub-agents, and have it self-optimize.

“an agent is a model plus a harness for this talk, at least.”
