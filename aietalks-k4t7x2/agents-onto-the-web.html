Bringing agents onto the world wide web

SpeakerPaul Klein IV · Browserbase Watchyoutu.be/GqoNrUz8hEU
Web automationComputer useAgentic engineering

If you only read one thing

  • Klein argues there is a capabilities overhang in computer use: models are good enough, but the harness/engineering work to extract that capability hasn't been done, unlike coding where harnesses like Factory and Cursor already beat baseline model results (c1, c2).
  • Reliable browser agents need three things: multimodal tool use (coding + computer use combined), harness engineering (skills, memory, published site skills via browser.sh), and consistent infrastructure (same layout/viewport every run) (c3, c4, c5).
  • Three problems remain industry-wide and unsolved: agent authentication (how an agent logs in on your behalf), agent trust/identity (no 'Verisign moment' yet for certifying trusted agents), and infrastructure consistency at scale (c6, c7).
01The web wasn't built for agents, and progress has stalled on infrastructure, not models

Klein argues the web was built for people, making automation inherently brittle (page changes, token-inefficient text, broken browser environments). He rejects the idea that stalled progress on browser agents is a model problem: models have improved sharply on long-context tasks and computer-use benchmarks over the past year via increased RL investment in computer-use environments.

02The real bottleneck is harness engineering, and it's a solvable capabilities overhang

Citing Karpathy's 2023 description of the harness as the scaffolding (code interpreter, multimodal I/O, browser, subagents) around a model, Klein says harness engineering already works in coding: Factory achieves above-baseline results versus the same underlying model used directly in Claude Code. He argues the same overhang exists in computer use, and any company (not just frontier labs) can build a harness for its domain and outperform the raw model.

“there is a massive capabilities overhang in computer use. The models are good enough, but we haven't done the engineering work to solve it”

03Three ingredients of a reliable browser agent

Klein lists three requirements: multimodal agents that mix computer use with code generation (e.g., writing a script to replay intercepted network requests rather than always clicking), harness engineering that gives agents memory and pre-published site skills so they don't rediscover a workflow every run (Browserbase's browser.sh publishes such skills), and reliable, consistent infrastructure so an agent sees the same viewport/layout every time it hits a site, since inconsistent rendering (e.g., mobile vs. desktop layout) produces inconsistent results.

“They're multimodal, they're harness engineered, and they have reliable infrastructure”

04Unsolved problems: agent authentication and agent trust

Klein flags authentication as the next major unsolved problem: agents need a secure way to log into websites on a user's behalf, with early attempts including sharing passwords directly, service accounts with limited permissions, and new proposals like WorkOS's AuthMD for agent sign-up flows. He also flags trust: CAPTCHAs are no longer effective at distinguishing good agents from bad bots, and he says the industry lacks a 'Verisign moment' — a certificate-issuer model for establishing that a given agent and its vendor are trustworthy.

“Chrome just added WebMCP, which I think is really, really cool. Websites can now publish MCP servers within their page that your agent can take advantage of without pre-installing the actual MCP”

“there needs to be almost like a Verisign moment for web agents where who can be the certificate issuer in saying my agent is trusted in this agent vendor is trusted”
