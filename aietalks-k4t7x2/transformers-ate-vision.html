How Transformers Finally Ate Vision

SpeakerIsaac Robinson · Roboflow Watchyoutu.be/VhfAVA3BG2I
Evals & benchmarksInfra & servingLocal models

If you only read one thing

  • Vision transformers beat convolutional networks despite having zero built-in inductive bias, because of massive ViT-specific pretraining (MAE, DINOv2/DINOv3) plus speedups borrowed from LLM infrastructure like flash attention.
  • The field detoured through windowed attention (Swin) and a pure convolutional network (ConvNeXt) that briefly beat ViT on ImageNet but wasn't fast, before settling back on the plain ViT.
  • SAM3's backbone lineage shows the cost of this approach: an 800-million-parameter model described as not usable in many low-power deployment cases, which is why Roboflow built the RF100VL benchmark and reports about a 40x speedup for the same accuracy versus fine-tuning SAM3 directly.
01Why the plain vision transformer wins despite no inductive bias

Convolutional networks have built-in inductive bias -- a filter activates the same way regardless of where an object appears in the image -- at O(n-squared) cost. Vision transformers have no such bias and cost O(n-to-the-fourth) as resolution scales, yet the speaker argues the plain ViT wins because of massive ViT-specific pretraining combined with infrastructure speedups borrowed from the LLM world.

“it is because of massive VIT-specific pretraining, and then we get to borrow a lot of speedups and infrastructure from the fact that LLMs are blowing up.”

02The architecture detour: Swin, then ConvNeXt

The field first tried windowed attention (Swin), which restricts attention to local windows and shifts them between layers, bringing compute back down to O(n-squared) and adding a locality inductive bias similar to convolution. It then tried going back to a pure convolutional network, ConvNeXt, built using the same recipe learned from ViTs, which beat both ViT and Swin on the standard ImageNet benchmark -- but wasn't fast.

“this actually gets us down to n-squared if your window size is independent of your resolution, and it adds a locality inductive bias following the convolutional net.”

“Turns out that beats VIT and Swin when you apply it on the uh standard ImageNet reference. That's great. Finally, we have something that makes a little bit of sense. Um turns out that's not super fast.”

▶ watch at 06:08
03Pretraining, not architecture, supplies the missing bias

Masked autoencoder (MAE) pretraining, where patches are dropped from an image and the model reconstructs them from context, is ViT-specific because you can't drop patches out of a convolution the same way. Taken further, DINOv2/DINOv3 self-supervised pretraining produces feature maps rich enough that a PCA decomposition traces individual cat paws correctly and decomposes satellite imagery in a semantically meaningful way, with self-supervised features probed by a simple linear layer catching up to the best fully supervised results.

“you can't actually apply MAE to a convolutional network. How do you drop out a patch when you're doing this convolution that's invariant across patches?”

“decomposition of the feature maps produced by a DINOv3 pretrained VIT, and we see that the paws of the cat have different colors, and that it's tracing the paws correctly for each of the different cats.”

04The cost of winning: SAM3 is powerful but not deployable

The SAM segmentation model series (SAM, mobile SAM, SAM2, SAM3) tracks the same pattern of a ViT backbone trained with MAE-style pretraining. The result is powerful but expensive: SAM3 is 800 million parameters, and the speaker says it's not actually usable in a lot of cases because vision has historically needed low-power, resource-constrained edge deployment.

“SAM 3 is this very very powerful thing, but is also 800 million parameters.”

▶ watch at 11:50

“It's not actually usable in a lot of cases, uh especially because vision historically has been focused on these very low-power edge devices, these uh resource constrained deployment scenarios.”

05Roboflow's fix: benchmark transfer, then compress for deployment

Roboflow introduced the RF100VL dataset to measure how well foundation models transfer to diverse downstream object-detection tasks. Using this benchmark, they report about a 40x speedup for the same accuracy compared to fine-tuning SAM3 directly, and a meaningful accuracy improvement even at a smaller 15x speedup.
