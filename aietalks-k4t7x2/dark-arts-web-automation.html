The core idea: a CDP browser is indistinguishable from a human's

  • Gallon's premise is that an agent driving a browser through the Chrome DevTools Protocol (CDP) sends clicks and keystrokes down the exact same internal path as a human using the mouse and keyboard, as far as Chrome, Cloudflare, or any anti-bot system can tell.
  • The talk's method rests on three pieces: a CLI (not an MCP server) to drive it, CDP as the interaction layer, and a sense-act-verify loop climbed rung by rung only as far as a page resists.

02CLI beats MCP on reuse, speed, and cost
Slide at 02:10 · click any slide to enlarge · 8 more from this section below

CLI beats MCP on reuse, speed, and cost

  • Citing a study from Arise AI, Gallon says CLI and MCP achieve the same task roughly equally often (about 83%), but CLI wins on every other dimension: a CLI sequence can be scripted once and replayed without a model in the loop, while MCP invokes the model on every turn.
  • In the cited study, the same task took MCP 71 round trips and 8 minutes versus 7 turns and under 1 minute for the CLI, and Anthropic reported CLI can be up to 75x cheaper in token cost.

03The meatbag ladder: escalate click fidelity only as far as needed
Slide at 11:30 · click any slide to enlarge · 7 more from this section below

The meatbag ladder: escalate click fidelity only as far as needed

  • Within a sense-act-verify loop (perceive the page via DOM/accessibility tree/screenshot, take one action, confirm it landed through a different channel than the action), agents climb a three-rung ladder when a page resists: rung one uses free synthetic JavaScript clicks, rung two uses CDP's real input domain so Chrome stamps the click 'trusted,' and rung three adds human-like mouse paths with jitter and dwell time for pages actively hunting bots.
  • Pages check whether an event is Chrome-stamped trusted or untrusted and silently drop untrusted (synthetic) input.

“Chrome stamps every single event with just that answer, whether it's trusted or untrusted”

said at 11:26
04Beating Turnstile, MTCaptcha, and reCAPTCHA v2 live
Slide at 13:00 · click any slide to enlarge · 8 more from this section below

Beating Turnstile, MTCaptcha, and reCAPTCHA v2 live

  • Cloudflare Turnstile hides its checkbox behind a closed shadow root nested in a cross-origin iframe with a second shadow root, defeated by computing the iframe's on-screen position and firing a trusted click at that coordinate.
  • MTCaptcha is solved by having the agent's vision read the distorted text and type it back with real trusted keystrokes.
  • For reCAPTCHA v2, deterministic code handles the click and iframe navigation while the agent (the 'operator') is used only for the one step that needs vision: identifying objects in the image grid each round, because the challenge times out if a model is round-tripped on every click.
