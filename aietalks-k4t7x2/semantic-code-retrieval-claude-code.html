Gives measured numbers, not vibes, for whether adding semantic (vector) code search on top of Claude Code's default grep-based search actually helps: Turbopuffer's Context Bench test shows file-read precision jumping from 65% to 87% with...

If you only read one thing

  • Cursor reports semantic code search drives a 24% relative improvement in answer accuracy for its composer model (12-13% across all models), plus a 2.6% code-retention gain and 2.2% fewer dissatisfied requests in an online A/B test (c1, c2).
  • Claude Code doesn't use semantic search by default; early versions tried a local vector DB but agentic grep-based search worked better and simpler (c3).
  • On Turbopuffer's own Context Bench test, adding windowed grep plus semantic search took Claude Code's file-read precision from 65% to 87%, cutting wasted file reads from 1-in-3 to 1-in-8, though grep still wins on import-tracing tasks (c5, c6, c7).

Claude Code's default is grep, not vector search

  • Claude Code does not use semantic code search by default; an early version experimented with a local vector database, but Anthropic found plain agentic grepping through the file system worked better and simpler, so it stuck with that.
  • Turbopuffer built an open-source CLI tool, Turbo Grep, that parses and chunks a codebase with a tree-splitter library, embeds it with Voyage's code model, and uploads it to Turbopuffer for Claude Code to query.

03Context Bench results: precision improves a lot, recall doesn't
Slide at 06:40 · click any slide to enlarge · 8 more from this section below

Context Bench results: precision improves a lot, recall doesn't

  • Using Cursor's public Context Bench methodology (which scores whether an agent looked at the right files/lines/symbols while solving a task, not just whether it solved it), Claude Code's baseline hit 65% file precision, 33% line precision, and 43% symbol precision.
  • Adding windowed grep plus semantic search raised file precision to 87%, cutting wasted file reads from about 1-in-3 files to 1-in-8.
  • Recall told a different story: default Claude Code actually wins on file recall because it explores aggressively, though a lot of that exploration lands on files without the needed lines.

04When semantic search helps versus when grep wins
Slide at 12:20 · click any slide to enlarge

When semantic search helps versus when grep wins

  • Breaking results down by task showed semantic search won on tasks needing behaviorally related files that didn't share keywords (e.g. code implementing the same behavior across different libraries), while plain grep won on tasks that were mostly import-tracing, where the right keyword shows up in the first tool call.
  • The speaker also notes semantic search performs best on code with a lot of inline documentation/comments, since that gives the embedding model more explicit semantic meaning to match against.

“I think it works best when there's a lot of like comments on code uh because it kind of finds that semantic meaning”

said at 12:20
05Turbopuffer's broader positioning
Slide at 11:50 · click any slide to enlarge · 8 more from this section below

Turbopuffer's broader positioning

  • The speaker attributes Claude Code's smaller gains (relative to Cursor's reported 24%) to semantic search being bolted on as an optional extra tool rather than a tool the model has been trained to know when and how to invoke, unlike Cursor's composer.
  • Turbopuffer describes itself as the vector database underlying companies including Cursor, Anthropic, and Notion.

“we are the we are the vector database that powers companies like Cursor, Anthropic, Notion”

said at 11:49

Commentary (ours)

The precision/recall split (semantic search helps precision a lot, recall barely, and only wins on specific task types) argues against a blanket 'add vector search' recommendation and toward routing by task type, which is a more actionable takeaway than Cursor's single headline accuracy number (ours).
