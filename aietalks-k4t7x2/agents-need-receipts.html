Agents Need Receipts, Not More Tool Calls

SpeakerArmanas Povilionis · Alithea Bio Watchyoutu.be/Fu45geO3zX8
MCP & protocolsAgentic engineeringVertical AI

If you only read one thing

  • Argues that agentic automation in science is bottlenecked not by more tools but by the lack of a verifiable, cross-organization receipt system for trusting and repeating results.
  • Predicts organizations will give agents budgets, not just tool access, so agents can autonomously discover, negotiate, and pay for services across organizational boundaries.
  • Introduces Froglet, an open-source protocol where every transaction is cryptographically signed into a tamper-evident chain, with setup costing 'a few thousand tokens' versus bespoke closed-source integrations that 'take years and cost millions.'
01Science needs verifiable receipts, not just more tools

Povilionis argues that adding more tools to agents improves local efficiency, using a cooks-in-a-kitchen metaphor, but that life-sciences work is inherently collaborative across organizations, more like running a Michelin-star restaurant that depends on suppliers. He says the real bottleneck is aligning the whole supply chain to be repeatable and consistent, not local tool access, and that this requires a verifiable chain of receipts.

“in order to enable agents to collaborate, we need a way to have a verifiable chain of receipts.”

02His prediction: agents will manage budgets, not just tools

He predicts that as agentic workflow automation matures, organizations will give agents budgets to discover services, request data, negotiate terms, and pay for work across organizational boundaries, rather than just granting tool access.

“organizations will give to the agents not only tools, they will give them budgets.”

03Froglet: an open protocol for agents to discover, pay, and prove work

Froglet is described as an open-source protocol letting agents discover, transact with, and receive verifiable receipts from external data and service providers, integrating with existing payment rails, agent harnesses, and MCP rather than replacing them. He says setup for a shared resource on Froglet costs a few thousand tokens and takes minutes.

“An open-source protocol for agents to discover, transact with, and receive verifiable receipt from external data uh data and service providers.”

“That setup costs few thousand tokens and takes minutes.”

04Closed-source integration is slow; Froglet is cryptographically signed

He contrasts this with closed-source collaboration, which he says typically becomes a bespoke, multi-year, multi-million-dollar enterprise project before any reusable workflow exists. Every Froglet node generates an identity keypair, and every artifact in an interaction is signed into a chain that is only valid if no data point has been tampered with.

“closed source and the collaboration often turns into a bespoke project, enterprise project that can take years and cost millions before any reusable workflow exists.”

▶ watch at 05:14

“everything is being signed in a chain, and the chain is only valid if all data points are not tampered with.”

▶ watch at 07:52
05Live demo: an agent used Froglet via MCP to call a remote service

In a live demo, he ran a Froglet node locally on Docker and had Claude, using a Froglet MCP integration, publish a service artifact and invoke a remote add-two-numbers service, which correctly returned 12 for the inputs 7 and 5.

“And here we have an answer. It's 12.”
