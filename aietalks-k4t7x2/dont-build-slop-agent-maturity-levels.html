01Four levels of building agents

Four levels of building agents

  • The speaker breaks agent-building into four escalating levels: use an existing framework to validate an idea quickly, hand-build your own agent as a state machine once you're serious, adopt a Kanban-based workflow for the UX of managing multiple agents, and finally ship execution to the cloud to scale across many users.

“I want to break down this problem of building agents into like four different parts”

02Less instruction, not more, for frontier models

Less instruction, not more, for frontier models

  • The speaker's second rule for hand-built agents is that every addition to an agent risks making it worse; large system prompts and lots of edge-case logic tend to overwhelm frontier models rather than help them.
  • As evidence, the Codex repo's system prompt for GPT-5.3 is a third the size of its GPT-5 prompt, and the speaker's own team rewrote Cline's codebase from scratch multiple times to strip out junk accumulated from older versions.

03Frontier API lock-in through reasoning traces

Frontier API lock-in through reasoning traces

  • The speaker's fifth rule warns that frontier labs' newer models (Opus 4.6, Gemini, GPT-5.3) expect reasoning traces to be sent back in a precise format as part of caching and the test-time compute loop; if a developer doesn't format them correctly, the API still returns a response but with degraded performance and no visible error.

“you want to send the reasoning traces in the exact precise format that is expected. If you don't, the response would still work, except that the performance would be degraded, and you would have no way of knowing.”

said at 10:22
04Kanban as the UX for inference-bound parallel agents

Kanban as the UX for inference-bound parallel agents

  • Because agents are inference-bound (an agent might run for 8-10 minutes before finishing a step), the speaker argues developers naturally end up running two or three agents in parallel, which makes a Kanban board -- giving an engineering-manager-style overview of each agent's state -- the right form factor for tracking them, a claim Claude Code's own Kanban-style feature later validated.

“you have at least like two or three agents running in parallel at all times because you're inference bound”

said at 11:52
05Cloud agents scale beyond a single session

Cloud agents scale beyond a single session

  • Cloud agents can run autonomously for extended periods, manually clicking through UI, testing settings changes, and iterating on failures without supervision; the speaker describes sending tasks that ran 50-60 minutes from his phone, letting him return to a finished, tested change.

“the cloud agents are so good that they will actually manually do all the clicks of the Q&A testing that I just described on their own”

said at 14:27

Commentary (ours)
