Your Attention Is the Bottleneck, Not Your Agents

SpeakerZack Proser · WorkOS Watchyoutu.be/so9l_MwS2yg · 25 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Argues that once agents can loop and self-verify, the human developer's attention -- not agent capability -- becomes the hard constraint on how much work can actually ship, which matters for anyone deciding how many parallel agent sessio...

If you only read one thing

  • Agents can loop infinitely against verification criteria and now scale via cloud API, but human attention still degrades under load and is the real bottleneck, echoing Simon Willison being wiped out by 11am after four parallel agents.
  • Practical balance tactics: give agents MCP access to Slack/Linear as a signal-filtering layer, use voice-first coding (184 wpm vs. ~90 wpm typing) to run more parallel sessions, and use remote-control (e.g. Claude Code's remote flag) to direct agents from a phone while away from the desk.
  • Recommends a weekly pass where an agent reviews its own saved conversation logs (Claude Code's local JSONL files) to find friction patterns and missing skills, and cautions against using AI to do tasks you don't already know how to do yourself, to keep building real skill.

The bottleneck has shifted from agents to attention

  • The speaker's core claim is that agents are no longer the constraint on throughput -- they can scale and loop against verification criteria -- but human attention is fixed capacity that degrades under load.
  • He cites Simon Willison firing up four parallel agents and being exhausted by 11am as evidence this is a widespread, individual problem developers now have to manage themselves.

“the agents are not the bottleneck now and I think that's going to increasingly be the case, but we are”

Voice-first coding for parallel workflows

  • He describes shifting to voice-first coding roughly 18 months ago, hitting about 184 words per minute versus his prior ~90 wpm typing speed, which enables prompting multiple agent windows (Cursor, Codex, Claude) near-simultaneously rather than serially.

“I regularly hit like 184 words per minute on a on a given day”

03Remote control lets you direct agents away from the desk
Slide at 08:00 · click any slide to enlarge

Remote control lets you direct agents away from the desk

  • Using a remote-control flag/config in Claude Code, a session keeps running on the dev machine while the developer checks in and sends messages from a phone on a different network, which he ties to the 'shower principle' -- diffuse-mode insights no longer require stopping work to capture.

“I pass the remote control flag, or I run remote control, or I have in my config enable remote control, then I can start at my desk”

said at 09:44
04Verification gates make it safe to step away
Slide at 08:00 · click any slide to enlarge

Verification gates make it safe to step away

  • He lays out escalating verification gates: automated lint/build/unit tests via hooks, browser-level checks (e.g. confirming login isn't broken), and a constitutional-AI-style step where a second agent verifies the first agent's work against defined criteria.

“speed requires safety, and so there's levels of doing this and having verification”

said at 11:15
05Mining session history and setting personal limits
Slide at 16:10 · click any slide to enlarge · 1 more from this section below

Mining session history and setting personal limits

  • Because Claude Code saves all conversations locally as JSONL files, he recommends a scheduled (weekly or daily) agent pass over that history to surface where significant back-and-forth or thinking-token spend occurred, then convert that into new skills or MCP connections.
  • He also warns that scaling agentic work without deliberate pacing leads to faster, easier burnout than before.

“all of Claude Code's conversations are saved locally in JSON L files”

said at 13:51

“the default path is going to be burnout, but now burnout turbo, like super fast and easier than ever, enabled by LLMs”

said at 16:27
06Don't outsource skills you haven't built yet
Slide at 18:40 · click any slide to enlarge · 8 more from this section below

Don't outsource skills you haven't built yet

  • In Q&A, responding to a question about skill development early in a career, he advises against using AI to do things you don't already know how to do, since hard-won experience is what lets you catch a hallucination or bad suggestion immediately.

“don't use AI to do something that you don't know how to do already”

said at 18:29

Commentary (ours)

The framing implicitly assumes verification infrastructure (hooks, browser checks, a second reviewing agent) is already in place -- for teams without that scaffolding, unattended looping is more likely to produce the 'burnout turbo' failure mode he warns about than the attention-preserving one he demos (ours).
