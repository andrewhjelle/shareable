The agent-ready web: Simplify user actions with WebMCP

SpeakerTara Agyemang · Google Watchyoutu.be/ghJmWQCIHRM
Web automationMCP & protocolsProduct & UX

If you only read one thing

  • Without WebMCP, agents burn heavy tokens parsing DOM, accessibility trees, and screenshots just to click one button, and layout shifts (e.g. an ad loading) can break the click entirely.
  • WebMCP exposes a site's capabilities as structured tools (declarative HTML attributes or an imperative registerTool API) so agents call a tool instead of guessing UI, which Google reports significantly improves performance and reliability.
  • It's a client-side complement to server-side MCP, not a replacement, and is still an early-preview, experimental Chrome feature (v146+, behind a flag) that changed during the weeks before this talk.
01Why agents struggle on today's websites

The speaker demoed a concert-ticket site where an agent had to read the full HTML DOM, inspect the accessibility tree, take a screenshot, and calculate click coordinates just to buy tickets -- a process she called long, brittle, and token-heavy, that can still fail if the page layout shifts.

“this process is quite long. It can be brittle, and I don't even want to guess at how many tokens you probably just used trying to do this”

02Fix web foundations before adding WebMCP

Improving semantic HTML, accessibility, page performance, and UX flows already makes a site more agent-ready by default, and only once those are in place does WebMCP add further value.

“making your site accessible for everyone makes it accessible to AI agents by default”

▶ watch at 03:06
03What WebMCP is

WebMCP is a proposed web standard that lets a site define its capabilities as structured tools for AI agents to call directly, rather than the agent inferring actions from the page. Google reports it significantly improves the performance and reliability of agents navigating a site, and it comes with two implementation paths: a declarative API (HTML attributes on standard forms, auto-generating a JSON schema) and an imperative API (a registerTool function for custom, multi-step flows).

“the Web Model Context Protocol is a a proposed web standard, and that gives you the ability to define your site's capabilities as structured tools for your AI agents to use”

04WebMCP vs. MCP

Server-side MCP lets agents connect to applications via a service the developer sets up, accessible anywhere, anytime; WebMCP is inspired by MCP but implements just the tools piece for client-side, in-browser agents, meaning the user's browser window must be open for it to work.

“Web MCP is the implementation of the tools part of the MCP. And so, Web MCP allows engineers to provide tools to in-browser AI agents”

▶ watch at 10:26
05Current status: early and experimental

WebMCP is enabled starting in Chrome 146, requires a testing flag (Canary recommended), and is explicitly early-preview and experimental -- the speaker noted the API had changed multiple times in recent weeks and invited developer feedback via a Chrome extension (Model Context Tool Inspector) and a GitHub repo of demos.

“We're still in early preview stage. This API is very experimental. It will change”

▶ watch at 17:44

“Web MCP is enabled in Chrome version 146 upwards”

Commentary (ours)

The declarative/imperative split mirrors how HTML forms vs. JS event handlers evolved -- expect the imperative API to dominate real usage the way custom JS did over plain forms, since most production UI flows are multi-step (ours).
