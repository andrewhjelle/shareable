We Gave an Agent Production Code Access and Then Tried to Sleep at Night

SpeakerMoritz Johner · Form3 Watchyoutu.be/LqLoYksJ6do
SecurityAgentic engineeringCoding agents

If you only read one thing

  • Thesis: a useful coding agent with production access is a supply chain actor whether you plan for it or not, and needs the same guardrails you'd apply to an engineer (c1).
  • Patch Pilot splits work into a deterministic Go controller (holds GitHub write and CI-trigger credentials) and an agentic layer that only edits files on disk, explicitly withholding push/PR/CI-trigger credentials from the agent to limit blast radius (c2, c4).
  • Giving the agent a Docker socket for self-verification defeats standard agent sandboxes ("game over"), so Form3 moved to a Firecracker microVM with its own kernel around the Docker socket instead (c5, c6).
01The core thesis

Existing dependency-patching tools like Dependabot and Renovate can't see vulnerabilities buried in base-image OS packages or binaries pulled during a Docker build, and patches aren't isolated (bumping one dependency can force related bumps and break linting). Form3 built Patch Pilot to reason about the full surface of a CVE. When Infosec asked whether this was automation or a supply-chain incident waiting to happen, the speaker's answer became the talk's thesis: a useful coding agent with production access is a supply chain actor.

“A useful coding agent is a supply chain actor, whether you plan for that or not”

▶ watch at 03:08
02Two-layer architecture and credential split

Patch Pilot has a deterministic Go application that does orchestration (discovering vulnerable OCI images, linking them to repos, committing, pushing, opening PRs, watching CI) and an agentic layer invoked for reasoning tasks (the CVE-remediation agent, and a PR-remediation agent for CI failures). The agent only modifies files on the filesystem; it does not commit, push, create PRs, or trigger CI. Dangerous credentials, GitHub write access and CI-trigger rights, are deliberately withheld from the agent and kept in the deterministic layer.

“patch pilot has two layers. One, it's a simple go application that is deterministic”

03Blast radius from prompt injection

Because the agent processes untrusted content (vendor directories, CI logs), a bumped dependency PR could touch as much as 70,000 lines of changed code, a wide attack surface if injected content steered the agent. Mitigations included prompt steering to mark specific directories/files as untrusted and an end-to-end eval with a crafted repository containing deprecated functions designed to try to recruit the agent into malicious behavior.

“there was like 70,000 lines of code that were changed in that small PR”

▶ watch at 12:26
04Why Docker sockets defeat sandboxes

Standard agent sandboxes (including those built into Codex and Claude) look secure until the agent needs a Docker socket to build and verify its own Dockerfile changes; at that point the agent can spawn a privileged container, escape it, read other processes' environment variables and memory, and plant SSH keys. Existing Linux sandboxing primitives (landlock, bubblewrap, seccomp, gVisor-style unprivileged builds) don't compose well with containers and can't contain a Docker socket.

“At that point, it's more or less game over for you, um, because the agent can then simply just spawn a privileged container, escape out of it”

▶ watch at 14:30
05The Firecracker microVM design and takeaway

Form3's current design puts the agent and the Docker socket inside a Firecracker microVM with its own kernel, containing the Docker daemon escape risk, with network policy enforced separately for the deterministic and agentic layers via a DNS/TCP forwarder over a vsock to a host process. The agent runs an end-of-invocation retrospective (what went well, what went wrong, what's missing) to improve future runs. The closing takeaway: the blast radius of an agent is an architecture decision, determined by what capability you push into the deterministic layer versus the agentic one.

“we put the agent in, we put the Docker socket in, and then the Docker socket is powered by its own kernel in this case”

Commentary (ours)

(ours) The credential-split pattern here (deterministic layer holds the dangerous capabilities, agent only ever touches the filesystem) is a cleaner mental model than most 'sandbox the agent' advice, because it removes the credential from the agent's reach entirely rather than trying to detect misuse after the fact.
