01Codex is a full software-engineering agent, sped up by WebSockets and a native Windows sandbox

Codex is described as more than a code-writing tool: it can run commands, run tests, and explore codebases, doing what a software engineer would do. It runs on OpenAI's model line, with GPT-5.4 named as the current state-of-the-art version. A WebSockets-based connection between the user's device and the API gives roughly 1.75x faster token delivery, and Codex has native sandbox support on Windows, which the speaker says no competing harness offers.

“It can run commands. It can run tests. It can explore code bases. It can really do everything that a software engineer would do.”

03Automations run scheduled background tasks

Automations let a user set up a recurring background process for Codex to run on a schedule, comparable to a cron job, rather than requiring interactive use of the app each time.

“you can set up automations that run in the background, so like a cron job”

04Code review reasons about the whole repo, and sub-agents parallelize review work

Codex code review spins up a separate review process that contextualizes a change against the entire repository, not just the diff, which the speaker says often surfaces second-order effects in modules the pull request never touched. Sub-agents let a task be decomposed into parallel, independent pieces; in one demo, Codex found 45 curated persona files in a repo and created 20 reviewer sub-agents to divide up reviewing them.

“Codex code review will like find find out changes which would have second order effects um which is not limited to just the, you know, diff or whatever changes you've made”

05New safety controls: guardian approvals and hooks

Guardian approvals, an experimental feature, address the risk of what the speaker calls 'YOLO mode' -- giving a coding agent unfettered access to do anything -- by spinning up a sub-agent to verify whether a privileged action actually needs human sign-off before running it. Separately, Codex currently supports three hooks -- after each tool use, at session start, and at session stop -- that let a user programmatically trigger an action based on those events.

“all of us, including myself, at some point were um guilty of using YOLO mode all the time, which means that you by default give unfettered um access to your coding agent to do literally whatever the hell it wants”
