Large monorepos break standard coding-agent context handling

  • The talk frames the problem as: coding agents work well on small repos, but on monorepos with large context, performance degrades as context grows, and this problem worsens further as repo size increases.
  • Existing mitigations mentioned are grep-style file search, semantic/local search, context compression/summarization, and dedicated memory solutions.

RLM's core idea: externalize context into a programmable environment

  • The RLM thesis is to move context management out of the model's own context window and into a separate, dedicated programmable execution environment (a REPL), where the whole repository is treated as data the model can operate on.
  • The model writes code to inspect, slice, and compute relevant chunks, then feeds only those results back into its main context, functioning as another context-management technique or memory layer.

“Core thesis of the RLM is you need to externalize the context management into programmable execution environment.”

said at 02:05

“rather than putting everything into the model's context create a separate dedicated environment give them a coding agent or ripple and then model write the code to curate the context that can be used into the main”

said at 02:37
03RLM code: an open-source reference harness

RLM code: an open-source reference harness

  • Superagentic AI built RLM code as an independent, open-source reference implementation of the RLM pattern -- not adding anything beyond the paper's ideas -- so it can be run against local or cloud models, plugged into any observability framework, and integrated into other agent frameworks.
  • A live demo showed the loop executing in a Docker sandbox, producing a ripple (REPL) trace, an LLM query call, and a final synthesized answer, with full run traces exportable in JSONL.

“We have implemented something called RLM mode. We are using RLM as it is. We are not adding anything on top of RLM's ideas and RLM's paper.”

said at 07:50

Practical use cases and where RLM shows up already

  • The speaker recommends RLM-style harnesses for tasks like root-cause analysis and onboarding onto unfamiliar large repositories.
  • He also reports observing RLM-like recursive context curation already in use inside proprietary systems: the Codex harness writing Python in a REPL to curate context, and Anthropic Claude Code engineers acknowledging on X that they use RLM concepts, alongside broader speculation about managed agents and multi-agent "software factory" workflows using similar ideas.

Commentary (ours)

If Codex and Claude Code are independently converging on RLM-style recursive context curation without a shared standard, that suggests the pattern is becoming a default architectural choice for large-codebase agents rather than a niche research technique -- worth watching whether a common interface for it emerges (ours).
