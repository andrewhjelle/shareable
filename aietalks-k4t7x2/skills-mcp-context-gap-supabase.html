Combine Skills and MCP to Close the Context Gap

SpeakerPedro Rodrigues · Supabase Watchyoutu.be/JT3OzDKrucU · 18 min SourceRecording of this talk at AI Engineer (2026), published on YouTube by the conference. Quotes are verbatim from the talk transcript with the time they were said.
patternAgentic engineeringMCP & protocolsContext engineering

Reports an eval-backed comparison showing MCP-only agents miss product-specific safety behavior (Postgres RLS bypass) that a written skill file catches, across four models from two vendors

If you only read one thing

  • Supabase found agents with MCP-only access created a Postgres view that silently bypassed row-level security, while agents with MCP plus a written skill set security_invoker correctly.
  • Braintrust evals across four models (Opus 4.6, Sonnet 4.6, GPT 5.4, GPT 5.4 mini) and three conditions (baseline, MCP only, MCP plus skill) showed skill plus MCP outperformed on every model tested.
  • Agents are lazy about loading more than one reference file, so anything the agent must not miss belongs directly in skill.md, not in a linked reference file.

02Where MCP alone falls short

Where MCP alone falls short

  • Supabase observed agents given only MCP tool access would miss product-specific security pitfalls, such as row-level security setup, defaulting instead to stale training data and rarely admitting they lacked current information.
  • A live demo showed that creating a Postgres view over an RLS-enabled table without explicitly setting security_invoker = true silently bypasses RLS; the MCP-plus-skill agent set the flag correctly, the MCP-only agent did not.

“they would usually either miss some some security pitfalls that we have like row level security instructions that they have to set”

said at 02:04

“if you don't explicitly pass that that flag over there the security invoker equals true, it will bypass the RLS”

03Three authoring principles

Three authoring principles

  • Supabase converged on three rules for writing a product skill: point to a single source of truth rather than duplicating documentation (they also expose docs over SSH so agents can navigate them like a filesystem); assume anything skippable will be skipped, so must-not-miss information (like a security checklist) goes directly in skill.md rather than a reference file the agent may not load; and be opinionated about the workflow you consider correct for your product, such as running direct DDL changes on staging before creating a migration file.

“We're we basically exposing our documentation through SSH. The main reason behind it is that the agents can now look for the documentation like it was a file system”

“We've noticed that even if when the the agent loaded the skill, it will even if it had reference files there, it will be very lazy to load them”

Evals confirm the skill helps
