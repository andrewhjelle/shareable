Teaching Coding Agents to do Spreadsheets

SpeakerNuno Campos · Witan Labs Watchyoutu.be/HEFSExa0xl0
Coding agentsAgentic engineeringEvals & benchmarks

If you only read one thing

  • Replacing 15 separate tools with one stateful Node.js REPL was the single biggest driver of accuracy, taking the benchmark from 50% to 74%.
  • A high-fidelity formula/render engine that lets the agent verify its own output against ground truth is essential; an incomplete engine makes results worse, not better.
  • Deterministic evaluation (golden spreadsheets with known input/output pairs) proved more trustworthy than LLM-as-judge, which couldn't distinguish agent changes from evaluator drift.
01Why spreadsheets are hard for LLMs

Unlike a human opening Excel and instantly seeing structure (a revenue table, assumptions, a chart), an LLM has no visual sense of a spreadsheet and must disambiguate which 'revenue' is meant, whether a cell is an input or a formula. Early architectures split the work into three agents with a five-step edit process, but this proved too rigid because discovery ran once up front and context didn't flow between agents.

“We started at uh, around 50% accuracy on a financial analysis benchmark and got to 92%”

▶ watch at 00:30

“this architecture in the end was too rigid because, you know, discovery ran once up front, uh, and then you couldn't revisit it and uh, the context wouldn't flow between the different agents”

▶ watch at 01:34
02Representation dead ends before the REPL breakthrough

The team tried representing spreadsheets to the LLM as SQL, as raw XML (how Excel stores files on disk), and other formats; none worked standalone, though CSV/TSV views and an HTML-based rendered image became useful components. The eventual breakthrough was replacing roughly 15 accumulated tools with a single Node.js REPL tool, letting the agent combine many operations in one call instead of making 10-15 sequential tool calls that often timed out.

“we uh hit on uh what was probably ended up being the biggest uh breakthrough, which was to replace the, you know, the many tools that we accumulated over time. I think at that time we had around 15 tools”

▶ watch at 04:00

“before it would be you'd have, you know, 10 or 15 tool calls usually for an agent to to explore a spreadsheet and get to an answer”

▶ watch at 05:13
03REPL vs. code mode: persistent state matters

The REPL differs from plain 'code mode' (bundling multiple tool calls into one script) by keeping state persistent across calls, so the agent defines variables once and reuses them later. This led agents to write shorter scripts with more interleaved reasoning between steps, which often reached better answers faster than one long script.

“just pure code mode without the REPL semantics, uh, agents would very often write quite long scripts, like 50 lines of JavaScript would be pretty common”

▶ watch at 06:47
04Verification loop needs a high-fidelity engine

A formula engine (to calculate results) and a render engine (to produce an image of a range with formatting) act as the source of truth the agent checks its work against. If the engine only implements a fraction of Excel's formulas, results get worse because the agent writes formulas it believes are correct that then fail or error in the incomplete engine.

“if you use an incomplete engine that implements, say, 50% of the formulas in Excel, then what you end up with is actually worse results”

▶ watch at 10:26
05Evaluation: deterministic beats LLM-as-judge where possible

The team started with LLM-as-judge only, but couldn't tell whether a score change reflected an actual agent change or evaluator drift. They shifted to deterministic comparisons where possible, such as feeding known inputs into a golden spreadsheet and the model-produced spreadsheet and checking whether outputs matched.

“the annoying part is sometimes you can't really tell if when a score changes is it because the, you know, the agent changed something or the evaluator changed what it outputs”

▶ watch at 14:05

“take a golden spreadsheet that had a set of inputs and a set of outputs and then use that as kind of a black black box to test a spreadsheet that the model produced”

▶ watch at 14:37

Commentary (ours)

The REPL-over-many-tools pattern generalizes past spreadsheets: any domain where an agent is chaining 10+ sequential or parallel tool calls is a sign you've built an ad hoc scripting language and should just give it a real one (ours).
