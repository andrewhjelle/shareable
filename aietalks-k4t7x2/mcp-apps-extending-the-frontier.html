From MCP-UI to an official standard

  • MCP-UI, created by Salomon in May of the prior year, is an open protocol for transmitting interactive UI over MCP and for that UI to communicate back to the host.
  • A few months before this talk, the speakers partnered with Anthropic and OpenAI to formalize MCP Apps as the official MCP extension built on MCP-UI, launching with support in Claude and VS Code before OpenAI and others adopted it.

“just a few months ago, we partnered with Anthropic and OpenAI to create the official extension to MCP, which we call MCP apps based on MCPUI, MCP SDK, and other solutions in the field”

Adoption so far

How the protocol keeps the host in control

  • When a user interacts with an app's rendered UI -- for example, clicking a favorite button in a Spotify widget -- the app doesn't call Spotify's backend directly; it sends a message to the host, which decides what to do, including whether to call a tool.
  • The spec formalizes this into three levels of control, from the app simply notifying the host that something happened up to the app asking the host to run a prompt and handing off responsibility entirely.

“instead of the app sending a message to to the backend, to Spotify's backend, it's actually sending a message to the host saying, "Hey, user clicked a button. Do something with it. I recommend you to call a tool in Spotify's MCP server."”

said at 06:09

“MCP apps actually standardizes it by defining this three level of control over the user journey. So, an app can notify the chat that something happened or an app can actually ask the chat to run a prompt”

said at 12:26

The pitch: an agentic web replacing browser tabs

  • The speakers frame MCP Apps as infrastructure for consuming services through a personal assistant instead of opening many browser tabs, with each service contributing a UI "atom" the assistant composes.
  • They cite a claim that ChatGPT reached 800 million weekly users -- about 10% of world population -- far faster than the web reached comparable scale, and argue this represents roughly 170 times the addressable market the Apple App Store had at its launch.

What's next on the roadmap

  • Near-term spec work includes reusable views so heavy apps (their example: Autodesk's 3D renderer) don't have to re-render from scratch on every update, and "app tools" (also called view tools), which let the host or chat act on an app's UI -- for example, filling out a form on the user's behalf -- rather than only the app messaging the host.

“there's a bunch of stuff coming up. Uh, the first thing uh, that we get a lot of uh, uh, of asked for is kind of reusable views”

said at 14:28

“MCP apps actually standardizes this this flow which we call view tools. That's actually that's in the spec right now.”

said at 14:59

Commentary (ours)

The speakers are the protocol's creators presenting adoption numbers and growth comparisons without independent sourcing, so the 800-million-user and 170x-TAM figures are best read as the promotional framing of people with a direct stake in MCP Apps' success rather than neutral market data.
