User Signal Dies at the Retrieval Boundary

SpeakerSonam Pankaj · StarlightSearch Watchyoutu.be/Jx4ZFEAq6bY
MemoryContext engineeringEvals & benchmarks

If you only read one thing

  • 73% of retrieval pipeline failures come from retrieval being static, not from generation or context stuffing, per the speaker's cited figure.
  • Existing memory systems (LangChain, Mem0) retrieve by embedding similarity and don't learn from whether a memory actually helped or hurt the outcome; Reflect introduces a utility score that weights similarity by historical usefulness.
  • On TAU-bench, memory alone moved pass rate from 66% to 76%, and baking reasoning into 'skills' after enough memories accumulate raised it further to 80%.
01Retrieval, not generation, is the reported failure point

The speaker cites a figure that 73% of agent pipeline failures stem from static retrieval rather than generation or context stuffing, and separately cites an 85% AI project failure rate reported by Gartner. She frames current memory systems as storing user preferences and conversation history for chat personalization rather than functioning as self-improving learning systems for production agents.

02The missing layer between evals and agent action

She argues observability captures every tool call and completion, and eval suites judge pass/fail on final output, but neither signal is fed back into the agent's context or retrieval, so an agent has no access to why yesterday's runs passed or failed. Fixing this currently requires an engineer manually rewriting prompts or redeploying after reviewing evals and traces.

“the agent doesn't have any access to why yesterday's runs, uh, runs passed or failed. The eval signal dies in the dashboard”

▶ watch at 02:53
03Utility score: weighting retrieval by outcome

Reflect (Agent RX) introduces a utility score that weights semantic similarity by whether a given memory has historically helped or hurt task execution, making outcome a first-class signal in retrieval re-ranking rather than just embedding distance. The system treats memory as reasoning about a task rather than as stored facts, and after enough memories accumulate (around 10) it bakes the pattern into an updatable 'skill.'

“you do retrieve by semantic similarity to the current task weighted by whether those memories have historically helped or hurt the execution or the outcome”

▶ watch at 05:14

“it treat memory as reasoning, not as facts, statistics, fact with no context and no history, but reasoning”

▶ watch at 05:47
04Benchmark results and limitations

On TAU-bench, which measures whether agents follow policy correctly, performance moved from a 66% baseline to 76% with memory alone and to 80% with skills baked in. On an agentic benchmark resembling Humanity's Last Exam, the baseline was 35.7%, a comparable memory system reached 58.2%, and Reflect reached 61.3%; the speaker names cold start (pure semantic search until enough reviews accumulate) as a limitation that can't be fully solved.

“we have seen the performance improve from 66 to 76% without baking in uh skills and with skills reflect performance at 80”

Commentary (ours)

The demo (searching for a 'gaming mouse' that returns nothing until a later run surfaces a wireless mouse via accumulated feedback) is a small, single-example illustration, not a controlled test, so the benchmark numbers carry more evidentiary weight than the live demo (ours).
