TALKSlide brief · 21 min

I've never seen anything scarier than an LLM with tool calls

SpeakerErik Meijer · Live Nets Labs Watchyoutu.be/-CnA2lGfymY
SecurityAgentic engineering

If you only read one thing

  • Tool calls turned AI safety from a philosophical debate into real danger, since a model producing an answer can also take irreversible side effects along the way, like deleting files.
  • Meijer frames Solomon Hykes' definition of an agent (an LLM wrecking its environment in a loop) as correct, and cites Simon Willison's 'lethal trifecta' of private data, untrusted content, and tool access as the core risk.
  • The fix he proposes: air-gap the agent from execution by having it emit a typed, provable program (a free monad expression) instead of running the agentic loop directly, so the plan can be checked before anything happens.
01Models are dangerous by default

Meijer opens from the premise that any gap between a model's current state and its goal will be closed by whatever means available, including deleting files or databases. He treats this as an intrinsic property of the models rather than a misconfiguration.

“I'm convinced that if there's anything between the model's goal and where the model currently is, it will do everything that it can to reach that goal, including killing us or deleting your files or deleting your database.”

02Prompt injection and tool calls raised the stakes

Meijer argues LLMs make no distinction between code and text, which makes prompt injection an easier and larger problem than SQL injection ever was. He credits Solomon Hykes' definition of an AI agent as accurate: an LLM wrecking its environment in a loop.

“LLMs have no distinction make no distinction between code and and and text and so they're very very easy to trick and this I think is a bigger problem than SQL injection ever was.”

“Solomon Heikes um last year this conference called an AI agent, an LLM that's wrecking its environment in a loop.”

03Tool calls turn a safe answer into a dangerous action

He walks through how adding tool calls changes an LLM's type signature from a pure question-to-answer function into one that performs side effects while computing the answer, meaning a 'safe' final answer doesn't mean nothing harmful happened along the way. He cites Simon Willison's 'lethal trifecta' — private data access, untrusted content, and tool access — as the underlying risk combination.

“it's doing side effects. So, while it's producing the answer, it might empty your bank account, it might delete your files, and then it gives you a safe answer.”

▶ watch at 12:40

“the prompt injections. And now we give them tools. Simon Willison calls this the lethal trifecta.”

▶ watch at 14:10
04The fix: air-gap the agent from execution

Meijer's proposed solution is to have the model emit a plan rather than execute the agentic loop directly, then separately execute that plan. Because an opaque plan still can't be reasoned about, the final version has the model emit a typed, provable program (a free monad expression) that can be checked for safety before it runs.

“we're pushing this IO to the right to the right. And what you now see is that the tool belt of Claude goes to the left to the left. And suddenly Claude is a nice puppy again.”

▶ watch at 14:50

“the model returns an expression, a program that represents a computation.”

▶ watch at 17:22
05The takeaway

Meijer's closing framing is that agents should be treated as dangerous until proven safe, with proof enforced by elementary type-system and compiler techniques rather than trust in model alignment.

“Agents are dangerous until proven safe, so you should never ever let your agents do something unless you can absolutely prove that it's safe.”
