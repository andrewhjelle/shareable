Beyond Code Coverage: Functionality Testing with Playwright MCP

Informs whether to trust AI-generated unit test coverage or adopt functional/behavioral TDD with Playwright as a check on it, since the talk argues AI-written unit tests can be self-affirming (green suite, unvalidated behavior)

If you only read one thing

  • GitHub says commits are on pace for about 14 billion by end of 2026, versus roughly 1 billion in 2025, based on COO Kyle Daigle's tweet citing about 275 million commits per week.
  • A cited Stanford study of 120,000 developers found clean code bases amplify AI's productivity gains while unchecked AI amplifies entropy; a case study team saw more PRs but worse code quality and only about a 1% effective output increase.
  • Recommends red-green-refactor TDD with AI: write failing Playwright functional tests first, let the agent make them pass fast, then spend the most time refactoring -- because AI-generated unit tests can be self-affirming, passing coverage while never validating actual system behavior.

04AI-written tests can be self-affirming, so test for functionality instead
Slide at 07:30 · click any slide to enlarge · 3 more from this section below

AI-written tests can be self-affirming, so test for functionality instead

  • The speaker warns that AI sometimes generates self-affirming tests: the unit test suite goes green and code coverage looks fine, but system behavior was never actually validated.
  • Her proposed fix is functional/behavioral testing with Playwright, and she argues pairing AI with this TDD cycle speeds up the red and green phases so developers can spend the most time in the refactor phase improving code the agent generated.

“AI sometimes generates self-affirming tests. So, while the code coverage tests might pass and you your unit test suite is all green”

05Practical workflow: Playwright agents and commit discipline
Slide at 10:40 · click any slide to enlarge · 8 more from this section below

Practical workflow: Playwright agents and commit discipline

  • Running the Playwright agents installer sets up three agent.md files -- a planner, a generator, and a healer -- that respectively plan which tests to run, generate the tests, and fix failing ones.
  • Recommended practices include committing code before letting an agent attempt to fix a failing test (since without a commit the agent may lose track of prior state), writing one test per feature, and attaching Playwright's automatic screenshots to PRs.

“it's going to install for you three agent.md files. So, the first one is going to be a planner, second is a generator, and the third is a healer”

Commentary (ours)

The self-affirming-test warning is the sharper claim here: it implies AI-generated coverage metrics can look healthy while silently validating nothing, which argues for functional/behavioral tests as a check on agent-written unit tests rather than a replacement for them (ours).
