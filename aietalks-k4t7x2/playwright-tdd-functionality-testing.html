03TDD's history and the over-focus-on-unit-tests critique

The speaker traces test-driven development's red-green-refactor cycle and notes it was 'pronounced dead' in a widely discussed 2014 critique, with a recurring complaint that TDD over-indexes on unit test coverage rather than testing actual system behavior -- for example, a test tied to an internal method name breaks on a harmless rename even if functionality is unchanged.

“like many things in this industry, TDD was pronounced dead in 2014. Um and one of the most common complaints”

▶ watch at 06:12
04AI-written tests can be self-affirming, so test for functionality instead

The speaker warns that AI sometimes generates self-affirming tests: the unit test suite goes green and code coverage looks fine, but system behavior was never actually validated. Her proposed fix is functional/behavioral testing with Playwright, and she argues pairing AI with this TDD cycle speeds up the red and green phases so developers can spend the most time in the refactor phase improving code the agent generated.

“AI sometimes generates self-affirming tests. So, while the code coverage tests might pass and you your unit test suite is all green”

▶ watch at 07:44

“when we're using Playwright with AI, it actually should speed up the full process of TDD for us”

▶ watch at 09:18
05Practical workflow: Playwright agents and commit discipline

Running the Playwright agents installer sets up three agent.md files -- a planner, a generator, and a healer -- that respectively plan which tests to run, generate the tests, and fix failing ones. Recommended practices include committing code before letting an agent attempt to fix a failing test (since without a commit the agent may lose track of prior state), writing one test per feature, and attaching Playwright's automatic screenshots to PRs.

“it's going to install for you three agent.md files. So, the first one is going to be a planner, second is a generator, and the third is a healer”

Commentary (ours)

The self-affirming-test warning is the sharper claim here: it implies AI-generated coverage metrics can look healthy while silently validating nothing, which argues for functional/behavioral tests as a check on agent-written unit tests rather than a replacement for them (ours).
