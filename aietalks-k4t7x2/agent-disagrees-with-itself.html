Why Your Agent Disagrees With Itself (And What To Do About It)

SpeakerDiane Lin · Datadog Watchyoutu.be/wEc9aG7cRQc
MemoryContinual learningEvals & benchmarks

If you only read one thing

  • Running the same model on the same input repeatedly can produce semantically different verdicts, in both sentiment analysis and security-alert triage, and the flip-flopping concentrates near the decision boundary, not randomly (c1, c3).
  • LLM self-reported confidence/uncertainty scores are unreliable signals for finding these cases; disagreement across multiple runs or models is the more reliable signal (c4).
  • Rather than fine-tuning, augmenting the agent with semantic memory (domain policy) and episodic memory (past similar labeled cases) is proposed as a lighter-weight fix, tested on 93 real alerts where a quarter flip-flopped and the intervention got 15% to consistent automatically, leaving 10% still inconsistent for human review (c5, c6, c7).
01Same model, same input, different verdict

The talk opens with the observation that running an LLM repeatedly on an identical input can produce semantically different outputs, illustrated with a hotel-review sentiment task and a security-alert triage task where the same alert is sometimes labeled consistently benign, sometimes consistently suspicious, and sometimes flip-flops between runs.

“Same model, same input. But different output.”

▶ watch at 02:37
02Why it matters beyond inconvenience

In a customer-facing product, flip-flopping verdicts create a trust problem: a customer comparing a vendor with consistent output against one with inconsistent output will favor the consistent vendor, even if average accuracy is similar.

“the inconsistency is causing a trust issue in your product”

▶ watch at 05:15
03Inconsistency clusters at the decision boundary

Across both example domains, the cases that flip-flop are concentrated near the decision boundary, the ambiguous 'gray zone' where even human experts disagree and where the correct label often depends on company-specific policy rather than an objective right answer.

“the data points tend to flip-flop actually concentrate around the decision boundary, the so-called gray zone”

▶ watch at 06:25
04Finding the ambiguous cases: disagreement over confidence

Borrowing from active learning, the talk recommends using query-by-committee style disagreement, sampling the same model multiple times or different models, to surface which cases the system is actually unsure about, rather than trusting the model's own uncertainty/confidence score, which the speaker says is not a reliable signal.

“the uncertainty score from LM is not very reliable. It's kind of a LM model doesn't know what it doesn't know”

▶ watch at 14:48
05Fix with memory, not fine-tuning

Instead of retraining or fine-tuning, the proposal is to add semantic memory (explicit domain/policy knowledge, such as a company's rule for a specific scenario) and episodic memory (referencing past similar labeled cases) so the agent can resolve recurring ambiguous cases automatically, escalating only genuinely novel cases to a human.

“fine-tuning model is expensive. Here, we are proposing a more lighter weight solution, easier to iterate. It's about augment your agent with semantic and episodic memory”

▶ watch at 15:47
06Measured results on real alerts

On a test set of 93 real cybersecurity alerts run three times each, about a quarter flip-flopped without the intervention. After applying the memory-based solution, roughly 15% became consistent automatically via episodic memory, while about 10% remained inconsistent and were routed to human review.

“here we collect uh 93 alerts, cybersecurity alerts, and then we run them three times”

▶ watch at 22:45

“about 15% of them become consistent. However, there's still 10% of them remaining inconsistent”

▶ watch at 23:15

Commentary (ours)

(ours) The framing that 'it's not your AI agent's fault, your AI agent simply points out the ambiguity that already exists' is a useful reframe, but it also shifts responsibility away from evaluating whether the underlying policy/label scheme itself is well specified, which the talk doesn't dig into.
