Your agent is blindfolded

01Feedback loop, not codebase type, explains agent success

Lajili rejects the common explanation that agents succeed on greenfield projects and fail on legacy brownfield code, citing his own success using agents on legacy code. He argues the real variable is whether the agent has a feedback loop: on greenfield the agent's intuition tends to be correct, while on brownfield there are unexpected dead ends and unfamiliar code the agent hasn't verified against.

“On brownfield, however, there be dragons. You're going to have things that the agent is not expecting.”

02Building Spoolside: a CLI so the agent can test itself

Because Poolside's product is a VS Code extension rather than a web page, Lajili built an internal CLI tool called Spoolside that lets the agent take screenshots, extract logs, restart services, navigate menus, and send/receive messages the way a human tester would. He says this lets the agent reproduce a bug before attempting a fix, which is a first step toward trusting it to run unsupervised.

“At Poolside, I've created a little CLI tool called Spoolside. Yeah, I might be good at programming. I'm not good at naming things.”

03The engineer's role is shifting to making AI self-verifying

Lajili argues engineers are becoming 'AIX engineers' who spend less time on product features directly and more time making it easy for the AI to verify its own work -- via CLIs, skills, MCPs, or better knowledge bases. He frames this as an investment: it can slow you down short-term but pays off once you're running multiple agents in parallel or overnight.

“we are going to have to focus less on the product and more on trying to make the AI work on the product”

▶ watch at 05:48

“you want to focus more on making sure that that velocity is not a trap, that you're not going to multiply errors or compound errors”

Commentary (ours)

Lajili's oxygen-mask framing (secure the AI's own verification before building features) is a sharper version of what several other AI Engineer talks gesture at -- worth treating agent-facing test/observability tooling as a first-class product surface rather than internal-only infrastructure (ours).
