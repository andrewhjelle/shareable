Agent Optimization with Pydantic AI: GEPA, Evals, Feedback Loops

If you only read one thing

  • GEPA is a genetic/Pareto optimization library that evolves a prompt (or JSON) string by breeding from the best-performing candidates; Pydantic AI's managed variables let any Pydantic-model-typed value, not just text, be swapped in production via feature-flag-style targeting (built on the OpenFeature standard) without redeploying.

01What GEPA and managed variables are

GEPA is described as a genetic algorithm that optimizes a string (a text prompt or JSON object) by taking the best candidates from a Pareto frontier and recombining them, similar to breeding the fastest racehorses rather than mixing in slow ones. Pydantic AI's managed variables extend simple prompt management to any Pydantic-model-typed object, and support targeting -- rolling out a new value to a percentage of calls, similar to A/B testing, built on the OpenFeature standard.

02Baseline evals favor deterministic checks over LLM-as-judge

Using a live demo (extracting political ancestry relations from Wikipedia pages for UK MPs, checked against a hand-built golden data set), a one-line prompt scored 87% accuracy while a more detailed hand-written prompt scored 92%. The speaker recommends defining custom deterministic evaluators over LLM-as-judge where possible, arguing LLM-as-judge evaluation can itself introduce unreliable judgment.

03Running GEPA improved the score but showed signs of overfitting

After running the GEPA optimization loop (a Pydantic AI agent proposing new prompt candidates, evaluated and iterated toward a better Pareto frontier), the resulting prompt scored 96.7% -- at the cost of becoming notably more verbose. In audience Q&A, an attendee running the same optimization found the optimized prompt explicitly excluded aunts and uncles despite them appearing in the golden relations, which the speaker attributes to the optimizer's training subset not containing enough aunt/uncle cases -- a likely instance of overfitting.

04Optimization pays off most with large private data volumes

The speaker cites an (unverified) statistic that 98% of data is private, arguing that optimization matters more when a system must encode large amounts of proprietary domain context (e.g. an internal bank spec) into a prompt, versus tasks a frontier model can already answer from public knowledge. He also notes that big model labs generally advise against fine-tuning because a next-generation model release often supersedes the gains, except in cases like finance with very high query volumes where fine-tuning still pays off. A cited Shopify example used GEPA to optimize a Qwen-based agent for site classification, cutting the yearly cost from GPT-5-on-raw-HTML pricing to a fraction of it.

05Limits: broad, high-variance tasks like coding agents skip formal evals

The speaker suggests optimization techniques like GEPA work less well for open-ended, high-breadth tasks, citing coding agents as an example where the trajectory space is too wide to usefully optimize against a fixed eval set without overfitting. He states that Claude Code's own team reportedly does not run extensive formal evals, tuning behavior mostly by feel instead.

Commentary (ours)

The aunt/uncle overfitting anecdote is the most transferable finding here: it's a concrete, reproducible failure mode (optimizer narrows behavior to fit an under-sampled training subset) rather than a hypothetical caveat, and argues for holding out a genuinely separate, full-coverage evaluation set before trusting an optimized prompt (ours).
