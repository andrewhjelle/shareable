Why this talk is a blueprint, not a take (ours)

Scope: Amplifon's Amplify platform for governing MCP and A2A agent development across teams: the AI gateway, the MCP and A2A registries, the use-case/lineage layer, and the developer blueprints and CI/CD that keep them in sync.

A central AI gateway with authentication and per-use-case budgets, a private MCP registry built as an enterprise extension of the public community registry, and an A2A registry where agents self-publish their agent card on deploy via CI/CD. A use-case registry ties these together into a lineage view for impact analysis when something in the chain breaks.

Prerequisites the talk implies:

  • An identity provider (Amplifon uses Entra ID) that the AI gateway can require for authentication
  • Willingness to extend the public community MCP registry rather than build a bespoke tool catalog from scratch
  • Standardized template repositories (blueprints) for MCP and A2A servers so metadata publishing is consistent across teams
  • A CI/CD pipeline that can publish both a deployable artifact and registry metadata (agent card or server.json) on tag
  • A central governing body, like Amplifon's control tower and committee, to set guidelines and prioritize use cases

What the talk does not say:

  • Team size or engineering effort required to build and maintain the gateway and registries
  • Cost figures for running the platform itself, separate from the per-use-case model budgets
  • How many teams or agents are actually onboarded today versus the demo data shown in the walkthrough
  • Failure modes: what happens when the lineage view is wrong or a proxy lookup fails to resolve a backend
  • Adoption or compliance metrics showing how much AI development across Amplifon actually goes through this platform versus around it

If you were to replicate one thing first: Start with the AI gateway (authentication plus per-use-case budgeting) before building the registries, since every other component in this architecture sits behind it.

03MCP registry built on the public catalog

MCP registry built on the public catalog

  • The MCP registry is the central catalog of all tools and Amplifon system integrations exposed to LLMs.
  • Rather than building from scratch, Amplifon built its own private MCP registry as an enterprise extension on top of the official community MCP registry, enriching each registered server with metadata like ownership, environment, authentication model, cost attribution, and use-case linkage.

A2A registry: self-documenting agent discovery
