Agents on the Canvas in tldraw

If you only read one thing

  • tldraw is a whiteboard SDK that other companies' AI canvas products (Replit's agent canvas, Luma AI's canvas) are built on, and it exposes the canvas as hackable React components.
  • tldraw's own agent went from one-shot generation (like 2023's Make Real) to a Cursor-style review/iterate loop to 'fairies' -- multiple agents on the same canvas where one is elected leader, scouts the canvas, and delegates a to-do list to the others.
  • To let agents fully control the desktop, tldraw built an Electron app with an HTTP endpoint that executes anything posted to it as JavaScript, calling this 'a terrible idea' that's only acceptable because the app is offline and file-based.

02From one-shot generation to an agentic review loop

From one-shot generation to an agentic review loop

  • The talk traces tldraw's AI features back to Make Real, a 2023 project that sent a canvas sketch to a model and returned a working HTML prototype -- framed as an early precursor to vibe coding, before that term existed.
  • A later canvas-drawing feature used structured text outputs rather than image-diffusion models so the AI could manipulate the same shape primitives a human user has.
  • The speaker says this one-shot approach 'didn't go really far enough,' motivating a move to an agentic loop modeled on coding agents of the time (2025), where the agent produces output, reviews it, and iterates.

03Vision models conflict on basic spatial conventions

Vision models conflict on basic spatial conventions

  • Getting a model to draw structured diagrams reliably ran into a specific training-data problem: conventions for axes and orientation conflict across the model's training data.
  • The speaker gives the example that a Cartesian graph's Y axis increases upward, while on the web, coordinate systems increase downward from the top-left corner -- a conflict the model has to be prompted around to behave predictably.

“on the web, the Y axis goes up in this direction, right? The top left corner is zero, your top left corner here, but as you go down, the Y goes up”

said at 06:46
04Fairies: multiple agents on one canvas with leader/follower delegation

Fairies: multiple agents on one canvas with leader/follower delegation

  • tldraw's 'fairies' feature (fairies.tldraw.com) puts multiple visible agents directly on the canvas rather than in a sidebar, each shown acting relative to the others' work.
  • When several fairies are given a task together, one is elected leader: it scouts the canvas, builds a to-do list, and delegates that list to the other agents, who can see and build on each other's output.
  • The speaker says this leader/follower and shared-state design was worked out around the same time (roughly October-December of the prior year) that agent orchestration patterns were being figured out more broadly.

“it's going to go scout kind of what's going on on the canvas, and then it's going to create a to-do list, and it's going to delegate that to-do list to the other agents”

said at 11:32
05Full desktop access via a deliberately unsafe local endpoint

Full desktop access via a deliberately unsafe local endpoint

  • Extending agent access beyond the canvas ran into safety questions about what's actually safe to expose through tldraw's hackable runtime API, since a sandboxed approach couldn't provide the DOM access needed for screenshots and browser-level interaction.
  • The team's workaround was an Electron desktop app wrapping tldraw with an HTTP endpoint that treats anything posted to it as JavaScript to execute -- a design the speaker calls a terrible idea in general, justified only because the app is offline and file-based.
  • He gives an example of a team member asking the agent to remove podcasts from the Spotify desktop app, which it does by editing the app's minified bundle directly, described as having 'no qualms at all' about modifying software on the user's computer.

“we started to kind of run into the barriers of of safety. Like, what is actually safe to to do with our hackable thing for for users?”

Commentary (ours)

The leader-election/shared-to-do-list pattern for multi-agent canvas work reads as a lightweight, visible alternative to more formal agent-orchestration frameworks -- worth watching whether the visible-state-on-a-shared-surface idea generalizes to non-canvas multi-agent coding setups (ours).
