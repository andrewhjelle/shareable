If you only read one thing

  • A software factory is defined as incrementally moving the human out of the loop in the SDLC, not just running many parallel coding agents at once.
  • Runtime, orchestration, and triggers for background agents are effectively solved (VMs beat containers for isolation because containers aren't a bulletproof security boundary and suffer noisy-neighbor compute contention); coordination between agents is the missing piece.
  • GitHub is not a coordination layer for agents -- PRs, merge conflicts, and CI fixes get too noisy for a human to know when to intervene -- and agents don't respect coarse five-step SDLC diagrams because each step hides many micro-steps.

03Harness engineering: encoding process into the repo
Slide at 05:20 · click any slide to enlarge · 2 more from this section below

Harness engineering: encoding process into the repo

  • Referencing OpenAI/Ryan's harness engineering blog, the speaker frames harness engineering as an extension of context engineering: everything in a repository -- skills, agents.md, unit tests, and any other feedback source -- that helps an agent complete SDLC steps.
  • In practice this means running the agent, observing where it gets lost, and encoding that knowledge back into the repo or context.

“really another extension on context engineering whereby everything in your repository from skills to agents.md to unit tests, everything that you could possibly use to give feedback to your agent is for me harness engineering”

said at 05:12
04VMs, not containers, for agent isolation
Slide at 07:00 · click any slide to enlarge · 6 more from this section below

VMs, not containers, for agent isolation

  • Ona runs coding agents inside full virtual machines rather than containers, because containers are not a bulletproof security isolation boundary and suffer noisy-neighbor compute contention when run on Kubernetes/pods.
  • Runtimes, orchestration (scaling agents up/down), and triggers (webhooks, PR/ticket creation) are described as largely solved problems at the infrastructure level.

“a container is not bulletproof isolation boundary. So, if you have an agent running in there and you want to secure it, you this challenge is for a container”

said at 06:45
05What's actually missing: coordination
Slide at 11:00 · click any slide to enlarge · 8 more from this section below

What's actually missing: coordination

  • The speaker argues agents don't respect the coarse five-step SDLC diagram teams typically draw, because each step hides many micro-steps agents must be taught to follow deterministically; context window consumption degrades agent effectiveness, and agents tend to skip steps (e.g., skipping tests) out of sycophancy.
  • GitHub and tools like Linear are reused human-oriented tools that make poor coordination layers for agents, leaving coordination as the primitive still missing -- something the speaker believes may be solved via state machines, durable execution, and a CLI-based gateway construct.

“GitHub is not a coordination layer for agents. It gets incredibly overwhelming. You know, you can have your agents raise a pull request, you can review it, you can then solve the merge conflicts, you can fix the CI build, etc.”

said at 12:27

“the SDLC is not this. It you know, this is the conceptual SDLC that we present and talk about with each other. Very coarse-grained five steps of the SDLC. Agents don't respect this”

said at 10:53

“once the context window becomes consumed, the the agent starts to lose track of where it's going and things like that. It gets less effective. They also skip steps typically. You know, they want to please us”

said at 11:54

“I do believe we've effectively solved the runtime. There are many options for this now, sandboxes and and containers and other solutions. The orchestration is effectively solved. The triggers are solved, but the thing that's missing for me is coordination”

Commentary (ours)

The claim that runtime/orchestration/triggers are 'solved' reflects Ona's own product maturity in that area; the honest signal here is what's still unsolved (coordination), which is a more defensible read on where the field actually stands (ours).
