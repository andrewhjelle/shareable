Agents Building Agents

patternAgentic engineeringEvals & benchmarksCoding agents

Describes two production pipelines for using a coding agent (Claude Code) to autonomously improve another AI agent: an eval-driven 'AutoAgent' loop that iterates system prompts and tools against a golden dataset, and a live-data pipeline...

If you only read one thing

  • A naive hello-world agent evaluated against a golden dataset scored only 18% pass rate because most eval questions required tools or context the agent didn't have.
  • AutoAgent, a Claude Code-driven loop that creates a hypothesis, edits the target agent, reruns evals, and rolls back on regression, took that same naive agent from 18% to 83% pass rate in about 10 iterations, and improved an already-optimized production agent's evals by 10% and another from 67% to 86%.
  • A separate live-data pipeline clusters real user feedback (thumbs up/down plus comments, or SME trace annotation) into failure-mode reports that get triaged, fixed, and folded back into the golden dataset as regression tests.

01Golden datasets and evals as the baseline

Golden datasets and evals as the baseline

  • A golden dataset is built with subject matter experts to define inputs and expected outputs (which can be a value, tool call, or specific tool-call chain) for an agent, paired with a scorer that reports current accuracy against it.
  • A naive hello-world agent with no tools scored only an 18% pass rate on its golden dataset because most questions required external tools or context it lacked.

02AutoAgent: an eval-driven self-improvement loop
Slide at 09:30 · click any slide to enlarge · 1 more from this section below

AutoAgent: an eval-driven self-improvement loop

  • Modeled on Andrej Karpathy's 'AutoResearch' loop that tunes ML hyperparameters against a loss metric, AutoAgent uses a coding agent (Claude Code, though others can be used) to build the target agent, read its eval feedback and traces, generate a hypothesis, implement a change on a new branch, rerun evals, and roll back if the change regresses.
  • Humans set the initial agent structure and give the coding agent guardrails, including explicitly telling it not to edit the golden dataset or scorers just to make evals pass.

“we can see that the baseline has a specific accuracy. And while we go um while we go with the number of experiments, accuracy is improving”

said at 09:21

“updating the golden data sets or the scorers just to let the evals pass is not a good idea, so we want to enforce we want to tell the we want to tell the AI agent to not do that”

said at 12:38
03Reported eval improvements from AutoAgent
Slide at 10:00 · click any slide to enlarge · 8 more from this section below

Reported eval improvements from AutoAgent

  • On the naive hello-world agent, AutoAgent raised pass rate from an 18% baseline to 83% in about 10 iterations.
  • On an already-humanly-optimized production agent, it found a further 10% improvement on internal benchmarks, and on another real production agent it moved baseline accuracy from 67% to 86% over roughly 10 iterations by improving system prompts, tool descriptions, and fixing tool logic.

“we have the baseline accuracy, which was 18%, and we managed to reach up to 83% um in like something around 10 uh 10 iterations”

said at 10:23

“the baseline accuracy was 67% um but then in something around 10 iterations, we managed to reach 86% in our evals without actually cheating”

said at 18:16
04Improving from live user feedback
Slide at 23:00 · click any slide to enlarge · 8 more from this section below

Improving from live user feedback

  • Separately from eval-driven improvement, the team collects real-user traces with thumbs-up/thumbs-down feedback and comments, or subject-matter-expert trace annotations, and runs an agent workflow that clusters negative feedback into failure modes, does root-cause analysis using the target agent's code, and generates a markdown report proposing fixes.
  • In one run, 114 collected traces fed this clustering step; humans then triage, validate with SMEs, and either fix or discard each cluster, and validated failure modes get added to the golden dataset so regressions are caught automatically going forward.

“we have 114 traces, and we're using those traces to then do the cluster analysis”

said at 22:59

“all the failure modes that we are founding during this investigation step, they will become part of the golden dataset that we mentioned earlier and the eval suite is updated to spot those regressions”

said at 26:08

Commentary (ours)

The explicit rule against letting the improving agent edit its own evals or scorers is the key safeguard here; without it, an eval-driven optimization loop has an obvious failure mode of gaming its own scoring rather than improving the underlying agent (ours).
