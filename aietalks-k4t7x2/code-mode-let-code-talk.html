Code Mode: Let the Code do the Talking

SpeakerSunil Pai · Cloudflare Watchyoutu.be/8txf05vVVl4
Agentic engineeringMCP & protocolsSecurity

If you only read one thing

  • Tool calling breaks down once an agent has hundreds of tools filling context; Cloudflare instead has models generate JavaScript that runs directly against an environment in one execution.
  • Applying this to Cloudflare's own ~2,600-endpoint API surface (about 1.2 million tokens if every endpoint were a tool) with a two-tool search/execute pattern cut it down to about 1,000 tokens.
  • The recommended sandbox starts with zero capabilities (no fetches, no exposed APIs) and grants them explicitly, run in V8 isolates with full observability into what code executed.
01Why tool calling stops working at scale

Pai says tool calling is fine with a couple of tools and short runs, but once an agent has hundreds of tools spanning services like Google, Jira, and internal wikis, the context fills up and the back-and-forth with the model becomes slow and starts breaking. Cloudflare's response, which they call code mode, is to have the model generate code (usually JavaScript) that executes against an environment in a single run instead of many round trips.

“the moment you start stuffing in uh your Google services, your Jira, your wiki, etc., and you have like hundreds hundreds of tools filling up the context, it starts breaking”

“Instead of doing this JSON back and forth thing, we asked the model to generate code, usually JavaScript, that we could run against an environment.”

02Cloudflare's own API as the proof case

Cloudflare's API surface has about 2,600 endpoints; exposing each as an individual tool would cost about 1.2 million tokens on the first call, which Pai says is unworkable. A colleague's design exposes just two tool calls, search and execute, both taking code as input, with search using the full OpenAPI spec; this reduced the token cost to about 1,000 tokens.

“the Cloudflare API surface is about 2,600 API endpoints. If we exposed a tool for every single one of them, it's about 1.2 million tokens in your first call”

▶ watch at 03:03

“it reduced that 1.2, 1.5 million token thing down to 1,000 tokens”

03The sandbox model: zero capabilities by default

Pai describes the harness/sandbox architecture behind code mode: unlike a container, the sandbox starts with no capabilities at all -- it can only execute code, with no fetches and no exposed APIs -- and capabilities are granted explicitly as APIs. Cloudflare runs this in V8 isolates for fast startup and about a decade of security hardening, and argues the system needs full observability into why any given piece of generated code ran.

“you start with something that has no capabilities. The only thing it can do is execute code. It can't do fetches, there's no exposed APIs, no nothing.”

“We use V8 isolates because they start up really, really quickly and uh it's about 10 years of security hardening.”

04An emergent behavior: inhabiting state instead of generating a program

Pai relays an internal example where a colleague built a drawing canvas and asked a model to play tic-tac-toe against him using only the raw state (an array of strokes), with no tic-tac-toe code anywhere in the system. The model inferred the board from the stroke state and played directly against it, which the team now describes as the model 'inhabiting the state machine' rather than generating a separate program to interact with.

“the the phrase we've started using is it stopped generating a program and it instead inhabiting the state machine”

▶ watch at 11:20
05Design implication: treat agents as a developer-experience audience

Pai closes by arguing teams need to design developer experience for code-generating agents specifically -- markdown docs, actionable error messages, discoverability via search -- because agents, not only humans, are now a primary audience interacting with a system's code-level surface.

“you do need to be in a place where you understand that your next billion users are these little robots that are generating code for you”

▶ watch at 17:06

Commentary (ours)

The tic-tac-toe emergent-behavior anecdote is a single internal demo relayed secondhand (Pai wasn't the one who ran it), not a reproducible benchmark, so it's best read as a vivid illustration of the state-vs-program distinction rather than a general claim about model capability (ours).
