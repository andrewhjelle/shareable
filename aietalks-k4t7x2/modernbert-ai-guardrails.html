01RAG and MCP poisoning need only a few crafted chunks

RAG and MCP poisoning need only a few crafted chunks

  • The talk cites the Poison-RAG paper's finding that in a knowledge database of 8 million documents, poisoning only five chunks was sufficient to manipulate the retrieved answer.
  • For MCP, it describes an asymmetry: the human approving a tool call sees only a simplified one-line description, while the LLM reads the full tool description, which can contain hidden instructions the human never sees.

02A GitHub issue triggered an NPM supply-chain compromise

A GitHub issue triggered an NPM supply-chain compromise

  • In a February incident, an attacker published a malicious NPM package and opened a GitHub issue containing a prompt injection; a coding agent interpolated the issue title directly into its prompt, installed the package, and self-escalated.
  • The talk states nearly 4,000 to 5,000 developers were affected.

“after the agent installed the malicious NPM package, it started to self-escalate. And I think nearly four or 5,000 developers were affected by this exploit”

said at 14:06
03Minimum safety checkpoints for production LLM systems

Minimum safety checkpoints for production LLM systems

  • The speaker's stated minimum safety bar for a production LLM application is checking both user inputs and model responses, with additional checks recommended for RAG, MCP, context memory, and agentic plans as system complexity and autonomy increase.

“the minimum safety requirements here in production would be to check at least for the user inputs and the model responses”

said at 17:13
04ModernBERT's architecture cuts memory and adds latency headroom

ModernBERT's architecture cuts memory and adds latency headroom

  • The talk walks through ModernBERT's architectural choices -- alternating local/global attention, unpadding and sequence packing, rotary positional encoding, and flash attention -- and reports that combining alternating and flash attention reduces memory requirements for fine-tuning by about 70%.
  • A single classification pass on the fine-tuned model takes 35 milliseconds as a baseline, before optimizations like quantization.

“to perform such a classification task, so in our fine-tuned model, this only needs 35 milliseconds”

said at 18:49

“the use of alternating attention combined with flash attention as we will see later reduce the memory requirements for fine-tuning by about 70%”

said at 20:21
05Fine-tuning pipeline and measured results

Fine-tuning pipeline and measured results

  • The classifier is fine-tuned on InjectGuard, a dataset of 75,000 labeled examples from 20 sources, using the Hugging Face Datasets library and a classification head on the CLS token.
  • On held-out benchmark data the resulting model reaches almost 85% accuracy at 35 milliseconds per classification.

Commentary (ours)

(ours) The RAG-poisoning and MCP-description numbers -- five chunks out of 8 million documents; a full tool description hidden from the approving human -- are useful concrete anchors for arguing that guardrails need to cover RAG and MCP specifically, not just the prompt.
