ResearchBot Architecture How the stack works · layers, scheduled pipelines, skills, evals, and the harness laws behind them. Updated 2026-08-22 after AIE corpus round 3. Status column is honest: code = enforced by a script, paper = a rule in a skill/prompt that a model is asked to follow, gap = not done.

What it is. A local-first, single-reviewer research stack: scheduled pipelines fetch and render daily briefs, a YouTube digest, and a forecasting world model; Claude Code skills do the judgment-bearing stages; a thin harness (logs, graders, receipts, a kill switch, a weekly meta-check) keeps the whole thing inspectable by one person. The flow itself lives in ResearchBot/_kg/PIPELINE.md; this page is the map of the machinery around it.

Self-critique of the loop (ours, round 3).
  • It documented more than it measured. Rounds 1–2 reported "built" for the session log; in fact only the talk pipeline had one. Worse, the skeptic found the one scheduled pipeline (6am Landscape) had produced nothing for 72 days because the script could not parse under Windows PowerShell 5.1 · and round 3's own patch added more parse errors and was auto-synced four minutes later. Three rounds wrote laws about logs and receipts for a pipeline nobody had executed. Fix applied the same night: encoding repaired, manual run, first receipt (which logged FAIL · no artifact · correctly), law 10 above.
  • Nobody verified the proposer. 10 of 28 round-3 proposals described machinery this stack does not have (context compaction, semantic search, a 4pm brief, handoff chains, graph "nodes"); 8 of 12 adopt-now items were downgraded; 5 claim ids were hand-abbreviated and did not resolve. Fix: rubric F1 (verify the current-state description against the repo) is applied to miner output before ranking; a proposal naming a file or behavior that does not exist is discarded.
  • "Built" does not survive a round. Round 2's four builds were one-off, pending, never-run, or partial, and became round 3's unexamined premises. Fix: the change-log row for each round now links to the receipt that proves each "built" item; no receipt, no "built".
  • Lessons→law went stale. _lessons.md had no entry after June 9 while three rounds of laws accumulated elsewhere. Fix: round-3 laws are logged there with "enforced where" (see ledger entries 11+).
  • Miners recycle talk-speak. Several of the 28 proposals addressed machinery this system doesn't have (context compaction in scheduled runs, a 4pm brief). Next round feeds miners the real file tree and PIPELINE.md before the claims, and asks for the file each change would touch.
  • Skills are the unharnessed half. Every Claude-run stage still has no log, no receipt, no halt check. That is the single highest-value gap on this page.

8. The corpus engine, now multi-corpus (built overnight Aug 21–22)

The talk-brief pipeline (manifest → transcripts → claim extraction against a fixed theme vocabulary → mechanical grader → synthesis → site) now runs on three corpora with one engine and one grader. Each corpus is a directory with its own content-schema.md (theme vocabulary), corpus.json (manifest with upload dates), transcripts/, content/ (graded briefs), and runs/*.jsonl (session log). build_corpus_site.py renders all three into one site: a Today page (what changed since the previous build, computed from the previous build's receipt, not from memory), a Timeline per corpus (weekly volume, theme share by month, rising vs falling themes, stance mix, and a month-by-month narrative whose evidence refs are verified against the briefs before the file is accepted), and a sub-site per corpus.

Aug 22–23 layer: depth tiers, diagrams, and a measurable wave harness. After the owner rated a talk page "3 out of 10" (no slides, no elevation of dense talks), the engine grew four pieces. Depth tiers: an Opus triage tiered all 459 AIE briefs (34 blueprint / 317 pattern / 108 take, depth_triage.json); blueprint talks carry a slide-grounded architecture table, an agent-drawn system diagram, and a replicate-first evaluation. Diagrams for every talk: agents write a JSON spec (lanes / nodes / edges, time-linked), build_site.py draws it deterministically; 459/459 briefs now have one. Readable slides: crop_slides.py finds the slide rectangle (persistent-edge box, activity fallback) and camera_frames.py flags stage shots; decks re-extracted at 1080p and cropped at native resolution (375 decks, 4 failures). The harness became measurable: run_wave.py replaces agent fan-outs with scripted headless claude -p calls, one receipt per talk in runs/waves/*.jsonl; the diagram wave ran 455 talks at $0.36 / 3.9k output tokens / 42 s per talk, 100% grader pass, ~$163 total (wave_report.py prints the series). Honest note: the per-talk cost is flat across waves so far; the gains over the overnight run came from cheaper tooling and cleaner inputs, not from the loop learning. The cost series now exists so that claim can be tested instead of asserted.

Aug 24 layer: layout became an engine plus an eval. The hand-rolled diagram renderer drew spaghetti on dense specs, so layout moved to Graphviz (diagram_gv.py): agents still only name boxes and arrows, dot places them. The change is measured, not asserted: eval_crossings.py renders all 459 specs both ways and counts edge crossings; legacy mean 1.44 / max 36 / 238 zero-crossing pages became Graphviz mean 0.03 / max 4 / 450 zero-crossing, with one 0-to-1 regression. A viz layer (viz_render.py: steps / compare / split / loop / stat) gives blueprint briefs 7-8 small visuals each, wave-authored and grader-checked. Two new hub pages render from specs: skills-atlas.html (clean-room functional research on 19 vendor skills, 14 capability classes, a 12-item replication queue, zero copied code) and service-map.html (the engine's own flow and quality harness as functional diagrams, plus 14 talk-traced change proposals ranked adopt-now / experiment / watch).

What tonight taught the loop (ours). The Landscape run that had never executed now has a receipted artifact (debug run 02:38, 60,471 bytes; the 06:00 scheduled run is the real proof). The two things that cost the most time were not model work: a YouTube bot check that stalled dates, transcripts and decks for three hours, and a transcript converter nobody had eyeballed before fanning out 50 agents. Both are now laws: serialize external fetches to one polite worker and stop on the first burst of failures; read twenty lines of any converted artifact before spending agent-hours on it.
